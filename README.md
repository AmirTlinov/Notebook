# Notebook

`Notebook` превращает iPad в бумагу и раскрывает её в бесконечную доску. На
доске живут два равноправных предмета: тетрадь для Pencil и документ для
набранного текста, формул и интерактивных моделей. Открытый предмет занимает
весь экран. Щипок внутрь постепенно возвращает его на доску; движение пальцев
напрямую управляет размером и обложкой. Обратный щипок или двойное касание снова
открывает выбранный предмет.

```text
лист <-------- управляемый щипок --------> обложка <--------> бесконечная доска
```

Тетрадный лист не имеет собственного зума. Пока он открыт, его масштаб
закреплён, а
бледная клетка на полноразмерном iPad равна `0,5 см`. Лист и обе стороны обложки
имеют непрерывные углы радиусом `0,8 см`, согласованные с силуэтом iPad. Под
тетрадями лежит отдельный холодно-серый рабочий холст с редкими точками. Он
сохраняет ориентацию в бесконечном пространстве, но больше не выглядит ещё
одним листом тетради.

## Как пользоваться

| Действие | Результат |
|---|---|
| Apple Pencil с ручкой | Пишет на листе, обложке или доске; нажим меняет непрозрачность от выбранного минимума до полного цвета |
| Apple Pencil с ластиком | Стирает пройденную полосу; нажим расширяет контакт до выбранного максимума |
| Значок инструмента | Выбирает цвет, толщину и минимум непрозрачности ручки либо толщину ластика |
| Касание двумя пальцами | Отменяет последнее движение на открытом листе или текущей пространственной поверхности |
| Удержание двумя пальцами | Повторяет отмену каждые 95 мс, как удержание Backspace |
| Два пальца влево или вправо на открытой тетради или документе | Лист едет за пальцами; отпускание завершает либо возвращает то же движение. В тетради движение вперёд за последнюю страницу создаёт одну новую |
| Щипок внутрь на листе | Непрерывно закрывает тетрадь и выводит на доску |
| Щипок внутрь на документе | Непрерывно закрывает документ и выводит на доску |
| Двойное касание предмета на доске | Сразу раскрывает тетрадный лист или документ |
| Щипок наружу над предметом | Свободно приближает доску и раскрывает близкую обложку; рядом с полным экраном мягкий магнит завершает путь |
| Отпустить щипок | Оставляет камеру в выбранном месте; только почти раскрытый лист примагничивается до полного экрана |
| Одно касание предмета | Выделяет обложку и показывает рядом кнопку удаления |
| Одно касание свободной доски | Снимает выбор |
| Один палец с движением по свободной доске | Двигает камеру; два пальца меняют масштаб вокруг места касания |
| Короткое удержание предмета и перетаскивание | Сначала приподнимает обложку тенью, масштабом и откликом, затем раскладывает её; сброс на другой предмет создаёт стопку максимум из пяти предметов |
| `+` на доске | Предлагает создать тетрадь с первым листом либо чистый документ |
| Двойное касание пустого места приближённой обложки | Вставляет прозрачный текст и сразу открывает клавиатуру |
| Двойное касание готового текста | Снова открывает его для редактирования; одно касание оставляет текст спокойным |
| Один палец внутри документа | Управляет текстом и интерактивными элементами; сменой физических листов владеет общий жест двумя пальцами |
| Двойное касание Markdown или LaTeX в документе | Открывает исходник блока как обычный текст; уход с поля сохраняет правку |
| Интерактивный блок документа | Принимает касания и сохраняет своё JSON-состояние отдельно от текста документа |

Один палец на бумаге не открывает выделение или системное меню. Интерактивный
элемент, который явно добавил агент, остаётся нажимаемым. Цвет, толщина,
минимальная непрозрачность и размер ластика сохраняются между запусками.
Обложка является такой же поверхностью Pencil, как доска: название можно
написать рукой, нарисовать или оставить пустым. Печатное название остаётся
необязательной подписью.

## Кто чем владеет

```text
WorkspaceIndex
|-- тетради, документы, страницы и текущий предмет
|
BoardDocument
|-- положения предметов, стопки и элементы доски/обложек
|
SpatialInkJournal
|-- действия Pencil на доске и обложках
|
PageDocument
|-- drawingData   <- Pencil на одном листе
`-- elements[]    <- Markdown / SVG / CSS / JS агента

DocumentDocument
|-- paperSize            <- A4 либо Letter, выбранный при создании
|-- preamble + blocks[]  <- Markdown / LaTeX / interactive source
`-- contentStamp         <- одна версия исходника

DocumentStateJournal
`-- state[blockID]        <- состояние интерактива, независимо от исходника

SessionPresence   <- камера, режим, текущий фокус и лист открытого документа
```

У предмета внутри стопки нет второго скрытого положения. Порядок участников
хранит `BoardDocument`, а `WorkspaceItemStackPresentation` выводит из него центр
каждой обложки. Этот же центр получает камера открытого листа. Пока одна тетрадь
раскрыта, соседние участники остаются в стопке и не попадают в её полноэкранную
сцену. При приближении стопка раскрывается в ограниченный веер. Его общий размах
не растёт после добавления тетради, поэтому все пять обложек сохраняют видимую
полосу для выбора.

На iPad один оконный тракт Pencil решает, какой физической поверхности принадлежат
точки. Доска и каждая обложка несут собственный `InkCanvasView`: обложечный холст
находится внутри самой тетради и получает тот же перенос, масштаб и поворот.
Поэтому рисунок едет как часть обложки, а не догоняет её после пересчёта камеры.
При подъёме Pencil уже показанные точки закрепляются в том же холсте, а затем
попадают в `SpatialInkJournal`. Холст повторяет журнал напрямую: ручка добавляет
геометрию, ластик вычитает её в том же порядке. Линия сохраняет форму после
отпускания, а ластик обложки работает с теми же пикселями, где лежит линия.

Один стабильный распознаватель, прикреплённый к сцене, владеет всей парой
пальцев. Поэтому он продолжает щипок даже в тот момент, когда лист уже стал
обложкой. Короткое окно наблюдения сравнивает совместный перенос пальцев с их
движением друг от друга: шум расстояния во время горизонтального свайпа больше
не закрывает тетрадь вместо перелистывания. `PencilInputGate` отдаёт активное
касание Pencil одному владельцу до подъёма. Новая пара после подъёма получает
отмену, перелистывание или камеру после публикации готовой геометрии; пара,
пересёкшаяся с Pencil, остаётся частью движения руки. Тап требует тихой короткой
пары, а наблюдаемое радиальное движение сразу продолжает щипок.

Перелистывание имеет одного временного владельца — `PageMotionController`.
Распознаватель передаёт ему полный перенос и скорость пары, поэтому лист после
раннего выбора жеста сразу догоняет пальцы без второй анимации. Текущий лист и
два соседних образуют одну горизонтальную направляющую; соседние тетрадные листы
являются готовыми растрами, а писать принимает только один текущий Metal-холст.
При отпускании одна критически затухающая пружина продолжает текущую скорость.
Короткое движение возвращается, достаточно глубокое либо быстрое завершается,
а новый жест прерывает пружину ровно в показанном положении. На краю доступен
только короткий упругий ход. Выбор страницы сохраняется и отправляется на Mac
один раз после завершения, а не в каждом кадре движения.

Пока пальцы лежат на экране, щипок задаёт сырую траекторию камеры. Одна замкнутая
формула сохраняет мировую точку из начала жеста точно под текущим центром двух
пальцев. Поле над обложкой выбирает возможную тетрадь, а её магнит становится
единственной плавной поправкой к этой траектории. Небольшое движение и дальний
подход остаются свободным приближением доски.
Распознаватель один раз отличает настоящий щипок, а кандидат тетради продолжает
следовать за центром пальцев во время подхода. Направление пересчитывается по
живому движению, поэтому разворот пальцев сразу разворачивает камеру. Когда
обложка достигает `0,84` своего обычного закрытого размера, движение наружу
передаётся ей без второго скрытого порога. Сцена запоминает точный масштаб этого
кадра, поэтому раскрытие начинается с нуля без прыжка и раньше прежнего слишком
близкого положения. С этого кадра та же камера непрерывно управляет раскрытием.
Когда тетрадь становится хорошо видна, мягкое поле начинает вести камеру к её
центру и полноэкранному масштабу. Чем крупнее тетрадь, тем сильнее тяга; рядом с
листом она становится точной. Отпускание в самом ядре завершает короткий стык.
Ранее отпускание сохраняет достигнутый масштаб и положение, а обратный щипок
сразу продолжает путь к глубокому обзору доски.

## iPad, Mac и агент

```text
Apple Pencil -> Metal -> PageDocument -----------+
                                                   |
Markdown/LaTeX/JS -> WebKit -> DocumentDocument ---+-> Network.framework
                                                   |          |
                                                   `-> Mac -> files -> MCP
                                                              `-> Tectonic PDF
```

iPad находит Mac через Bonjour и передаёт изменения напрямую по локальному
каналу Network.framework. Каждая сетевая запись принадлежит Mac как устройству:
Bonjour может показать один Mac через Wi-Fi, USB и другие интерфейсы, но iPad
держит для него одну задачу соединения, а адреса перебирает как запасные пути.

Долгоживущая модель Mac следит за атомарными файлами в
`~/Library/Application Support/Notebook` и передаёт изменения на iPad. Этот
наблюдатель живёт вместе с процессом приложения, поэтому закрытие окна оставляет
доставку работающей. Перед обычным запуском MCP `MCP/run.sh` будит каноническое
приложение `~/Applications/Notebook.app`; запись, сделанная во время старта,
попадает либо в начальную загрузку, либо в следующий проход наблюдателя.

Mac показывает ту же сцену и создаёт два вида PNG: изображение каждого листа и
точное изображение текущей сцены. Для документа живой WebKit сначала отдаёт
Markdown, MathJax и интерактивные кадры в поток фиксированной высоты. Браузер
сам переносит этот поток по отдельным физическим листам A4 или Letter, поэтому
длинный документ остаётся набором страниц, а не бесконечной лентой. Затем WebKit
отдаёт снимок набранного документа; рендер сцены
использует именно этот снимок, а не пустую SwiftUI-заглушку. Квитанция текущей
сцены связывает версии камеры, доски, чернил, листа либо исходника, состояния и
выбранной физической страницы документа с SHA-256 картинки. Квитанция листа связывает его
ревизию с полным PNG, вариантом без сетки, картой занятых физических клеток и
увеличенными областями. MCP сверяет ревизии и каждый SHA-256 перед выдачей,
поэтому агент получает один законченный зрительный факт.

Карта листа строится из окончательно видимых пикселей PencilKit. Исходный путь
стёртого штриха может оставаться внутри `PKStroke`, поэтому границы штрихов не
участвуют в поиске рисунка. Соседние занятые клетки объединяются, а большая
связная схема делится на перекрывающиеся окна до двенадцати клеток. Агент сначала
получает лёгкую карту, затем просит до четырёх нужных увеличений вместо повторной
передачи всего листа. Последние восемь карт позволяют назвать области, которые
изменились с известной ревизии.

Каждое положение камеры несёт номер сессии, порядковый номер и фазу
`active` либо `settled`. Mac сразу показывает самый новый активный кадр, а на
диск сохраняет только завершённую сцену. Завершённый кадр нельзя вытеснить
началом следующего жеста. PNG для агента также строится только из завершённого
состояния и после короткой паузы изменений, поэтому движение камеры и письмо не
соревнуются с бесполезными промежуточными картинками.

Bonjour продолжает следить за списком Mac независимо от конкретного соединения.
Каждый найденный Mac получает одну задачу, исчезнувший Mac её завершает, а
listener и browser восстанавливаются после временной ошибки. Поэтому перезапуск
Mac не требует перезапуска приложения на iPad. При соединении сначала приходят
содержимое страниц и документов, их состояние и размещение, затем каталог как
граница публикации и текущий завершённый вид. Полные рисунки одного листа,
исходники одного документа и его состояние, ещё ожидающие отправки,
схлопываются до самой новой ревизии.

Новая тетрадь публикуется в порядке `лист -> размещение -> каталог`. Старый
читатель может безопасно увидеть заранее подготовленное размещение, а после
появления тетради в каталоге её лист и место уже существуют.
Новый документ проходит ту же границу как
`исходник -> состояние -> размещение -> каталог`. Снимок, который одновременно
добавляет и удаляет предметы, на миг использует объединённую доску: старый и
новый каталоги в любой момент имеют полное размещение.
Удаление идёт в обратную безопасную сторону: сначала меньший каталог, затем
доска без обложки, затем файлы листов, документов, состояний и предпросмотров.
Поздняя фоновая запись проверяет каталог под тем же файловым замком и поэтому не
может воскресить уже удалённое содержимое.

## Запуск

Нужны Xcode 27, XcodeGen 2.46 или новее и iPadOS/macOS 27. Для PDF-экспорта
документов нужен Tectonic.

```bash
cd /Users/amir/Documents/projects/Notebook/Applications
xcodegen generate
open Notebook.xcodeproj

brew install tectonic
```

В Xcode сначала запустите `NotebookMac` на Mac, затем `Notebook` на iPad. Обе схемы
используют команду разработки `VUNH73AYPY`; другой владелец меняет
`DEVELOPMENT_TEAM` в `Applications/project.yml`. При первом запуске iPad нужно
разрешить доступ к локальной сети. Постоянную сборку Mac положите по адресу
`~/Applications/Notebook.app`: MCP запускает именно этот экземпляр, а не
случайную сборку с тем же bundle identifier из DerivedData.

## MCP для агента

```bash
cd /Users/amir/Documents/projects/Notebook/MCP
npm ci --ignore-scripts
codex mcp add notebook -- /Users/amir/Documents/projects/Notebook/MCP/run.sh
```

После добавления нужен новый сеанс Codex. На этой машине сервер зарегистрирован
как `notebook`.

| Инструмент | Проверяемое действие |
|---|---|
| `notebook_context` | Читает текущий режим, камеру, выбранный предмет и его лист либо документ |
| `notebook_read_board` | Читает размещения тетрадей и документов, стопки, пространственные элементы, визуальные ссылки и версии |
| `notebook_read_notebook` | Читает одну тетрадь, её место, стопку, обложку и визуальную ссылку |
| `notebook_render_view` | Возвращает свежий PNG ровно того, что сейчас показывает Mac |
| `notebook_create_notebook` | Создаёт тетрадь, первый лист и размещение |
| `notebook_create_document` | Создаёт документ A4 либо Letter из упорядоченных Markdown, LaTeX и интерактивных блоков |
| `notebook_read_document` | Читает исходник документа и независимо слитое состояние интерактива |
| `notebook_patch_document` | Целиком заменяет preamble и порядок блоков под ожидаемой ревизией исходника |
| `notebook_export_document` | Собирает полный `.tex` и PDF локальным Tectonic и возвращает SHA-256 |
| `notebook_rename_item` | Меняет или очищает необязательную подпись тетради либо документа |
| `notebook_move_nodes` | Перемещает предметы и стопки в точных мировых координатах |
| `notebook_stack_nodes` | Кладёт предмет на другой предмет или в существующую стопку |
| `notebook_put_spatial_markdown` | Добавляет прозрачный Markdown на доску или обложку |
| `notebook_put_spatial_web` | Добавляет прозрачный интерактивный HTML/SVG/CSS/JS на доску или обложку |
| `notebook_remove_spatial_elements` | Удаляет выбранные пространственные элементы, сохраняя Pencil |
| `notebook_read_page` | Читает данные и агентские элементы листа |
| `notebook_render_page` | Возвращает свежий PNG листа с клеткой и рукописью |
| `notebook_page_map` | Находит физические клетки и области с видимыми пикселями Pencil; умеет показать дельту от недавней ревизии |
| `notebook_render_region` | Возвращает одно точное увеличение области с сеткой либо без неё |
| `notebook_render_regions` | Возвращает до четырёх увеличений одним вызовом в порядке карты |
| `notebook_put_markdown` | Добавляет прозрачный Markdown на лист |
| `notebook_put_web` | Добавляет прозрачный интерактивный HTML/SVG/CSS/JS на лист |
| `notebook_remove_elements` | Удаляет выбранные элементы листа, сохраняя Pencil |

Сначала агент читает контекст или доску. Если открыт документ, агент получает
`contentRevision`, меняет его через `notebook_patch_document` и сохраняет
стабильные `blockID`: тогда кнопка или модель не теряет состояние при правке
текста вокруг неё. При создании он явно выбирает `paper_size: a4 | letter`;
выбор принадлежит документу, управляет живыми страницами и тем же форматом PDF.
Markdown и математический LaTeX набираются внутри приложения.
Сырой LaTeX-блок и общий `preamble` без преобразования попадают в Tectonic, так
что печатный PDF принадлежит настоящему TeX. Интерактивный блок живёт в отдельном
`sandbox`-кадре без сети; в статическом PDF он становится честной пометкой о
живом элементе.

Для рукописи агент читает
`notebook_page_map`, а затем только нужные области через
`notebook_render_region` или `notebook_render_regions`; полный лист остаётся
обзором. Полученная `drawingRevision` связывает карту с увеличениями. Для
изменения агент передаёт ревизию владельца. Устаревшая запись получает конфликт
и должна перечитать владельца. Интерактивный слой читает
`window.notebook.state` и сохраняет новое состояние через
`window.notebook.commit(nextState)`. WebKit не имеет сетевого доступа.
Если печатной подписи нет, агент сопоставляет `screenFrame` с обложкой в
`notebook_render_view`. В инструментах он использует точный `itemID`, а в
разговоре может продолжать человеческое имя вроде «тетрадь с орлом»;
`shortID` различает похожие обложки.

Маршрут проверяет Swift-домен, физическую клетку, слияние независимых потоков,
геометрию камеры и поверхностей, нажим, один финальный расчёт ластика листа,
прямой Metal-порядок ручки и ластика обложки, свежие размеры одного значка Mac/iPad,
MCP-контракты, карты видимых клеток, свежесть PNG, сборки macOS/iPadOS и живой Simulator.
Отдельные UI-суды открывают документ, требуют одновременно набранный Markdown,
отрисованный MathJax и работающий интерактивный элемент, а затем двойным
касанием превращают текст в редактор, который принимает экранную клавиатуру.
UI-проверки пишут и стирают плотный лист, сразу выходят и возвращаются к уже
стёртому листу, стирают подготовленную линию обложки, проводят последовательные
линии по обложке и доске, снимают выбор касанием свободной доски, удаляют и
переносят тетрадь после визуального подъёма,
проверяют отзывчивость панели, возвращают лист из
поворота `портрет -> альбом -> портрет` без усадки, приближают далёкую тетрадь
несколькими щипками без раннего открытия, затем открывают её продолжением того
же пути, проверяют свободно оставленный промежуточный масштаб, магнит полного
листа, стопки, открытие тетради двойным касанием и отдельный путь, который
создаёт, закрывает и повторно открывает текст на обложке.
Подробные системные контракты находятся в
[`docs/research.md`](docs/research.md).

## Граница локального прототипа

Канал остаётся внутри ближайшей сети, но текущий TCP ещё не шифруется и не
проверяет личность второго устройства. Поэтому приложение рассчитано на личную
доверенную сеть. Использование в общей сети требует явного спаривания устройств
и TLS с ключом этой пары.
