# Семь живых научных примеров

Это собственные учебные реализации на JavaScript: SVG для схем и графиков,
WebGL для объёмного механизма. Они следуют выбранным Амиром визуальным
референсам, а не копии статей, исходного кода или авторских иллюстраций.
Каждая сцена раскрывает один механизм. В частности, `gears` показывает
вращаемую трёхмерную передачу с разборкой, но не целые механические часы; `gaussian` — один вариант GP-регрессии,
не весь материал Distill. Ссылки и авторы находятся в
[examples.json](../assets/science/examples.json) и в раскрываемом разделе каждой сцены.

| Example | Model | Main relation |
|---|---|---|
| `sound` | Longitudinal wave | Displacement / compression / propagation |
| `gears` | Gear train | Tooth count / angle / direction |
| `linear` | Linear transformation | Matrix / basis / oriented area |
| `gaussian` | RBF Gaussian process | Observations / covariance / uncertainty |
| `astar` | A* search | Obstacles / frontier / shortest path |
| `tensor` | Matrix contraction | Indices / components / sum |
| `probability` | Bernoulli trials | Probability / outcomes / frequency |

## Сначала проживи пример

Запусти локальную галерею в папке своей задачи:

```sh
node ~/.codex/skills/notebook/scripts/science-preview.mjs /absolute/task/preview
# Пока процесс работает, открой /absolute/task/preview/index.html в браузере.
```

Повторный запуск обновляет галерею в выбранной папке. Не направляй генератор
в папку с авторскими HTML. Встроенные примеры используют `animationPreview`,
пакетные `gears`, `signal` и `wave` — существующий `program-preview` с теми же
проверенными ассетами и браузерным мостом. Процесс обслуживает пакеты только на
`127.0.0.1`; оставь его работающим во время просмотра, затем останови Ctrl+C.
Внешняя сеть и соединение с Notebook не нужны; параметры живут до перезагрузки.
Внешние ссылки открываются только при выборе человеком.

В `sound` проследи за одной частицей и сравни её с движением сжатия. В `gears`
поверни модель, подними опорную пластину и сравни движение помеченных колёс.
В `linear` выбери проекцию, проведи ползунок до конца и посмотри на исчезнувшую
площадь. Перетаскивание базисного вектора меняет столбец матрицы.
В `gaussian` добавь точку, затем измени длину связи и сравни матрицу с полосой.
В `astar` перекрой проход и проверь не только удачный маршрут, но и отсутствие
пути. В `tensor` выбери компонент результата, пройди по k и измени входное число.
В `probability` сравни короткую и длинную серии; p = 0 и p = 1 показывают границы.


Модель занимает главное поле. На первом экране остаётся только необходимое
управление; матрица ковариаций, дополнительные параметры и границы модели
раскрываются через «Как это устроено». Пояснения не уменьшаются до мелкого
служебного текста. Нейтральная поверхность сохраняет цвет за данными; тёмное
координатное пространство `linear` — отдельный язык этого примера, а не тема
для всех иллюстраций.

В `gears` геометрия действительно имеет три координаты: объёмные венцы,
отверстия, спицы, оси и опоры рисуются через WebGL с попиксельным буфером глубины.
SVG-сортировка граней по средней дистанции не сохраняет перекрытия при повороте
и здесь не используется. Остальные примеры остаются SVG.
Поворот камеры и разборка не меняют передаточные отношения и не останавливают
воспроизведение. Клавиатурный фокус виден; клик по сцене не создаёт рамку. Это небольшой
рендерер одной сцены, не универсальная CAD-система и не физический решатель.

## Поместить в Notebook

Имена примеров — параметр существующего рецепта `animation`, а не новый SDK:

```json
{
  "example": "gaussian",
  "target": {"kind": "page", "id": "PAGE_ID"},
  "offset": {"x": 40, "y": 80},
  "width": 960,
  "height": 960,
  "initialState": {"length": 0.8, "noise": 0.12}
}
```

```sh
node ~/.codex/skills/notebook/scripts/prepare.mjs animation input.json request.json
node ~/.codex/skills/notebook/scripts/animation-preview.mjs request.json scene.html
# Только когда намерение включает запись на выбранную поверхность:
node ~/.codex/skills/notebook/scripts/submit.mjs request.json
```

Доска требует `anchor`; документ использует `target.kind: "document"` и при
необходимости `afterID`. При узкой колонке сцена складывается вертикально:
подбери высоту под фактический рендер, а не уменьши всю композицию до мелкого текста.
Подготовленный запрос содержит HTML, CSS и JS целиком; исходные файлы и интернет
после вставки не нужны. Действия человека сохраняют состояние, кадры — нет.
Новое состояние Notebook останавливает воспроизведение и показывает именно его.

## Перенести способ объяснения

Исходники находятся в [assets/science](../assets/science/): отдельные `.html` и
`.js` каждой сцены, общие `models.js`, `runtime.js`, `common.css`.
`models.js` владеет вычислениями; файлы сцен связывают модель с её рендером; `runtime.js`
владеет только состоянием, управлением и локальным временем. Он не заменяет
Notebook runtime. Модели проверяются в `MCP/test/science-examples.test.ts` проекта.

Для нового сюжета возьми близкий пример и поменяй модель, подписи и композицию
в своей рабочей копии. Затем передай обычные `htmlPath`, `cssPath`,
`javaScriptPath` рецепту `animation` вместо `example`. JavaScript должен содержать
нужные модели, общий runtime и сцену в таком порядке; CSS — нужные общие стили.
Или возьми только один полезный приём — эти сцены не обязательные шаблоны.

Все примеры начинают работу без автозапуска. Количественные условности и границы
модели названы в самой сцене. Сохраняй их при адаптации: особенно нормированные
величины в `sound`, линейную интерполяцию матриц в `linear` и
поточечный, а не одновременный интервал в `gaussian`.
