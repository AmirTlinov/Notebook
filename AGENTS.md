# Notebook: карта проекта

```text
Notebook/
|-- README.md                 # Пользовательский путь, запуск и доказательства.
|-- Package.swift             # Общий домен без UI и сети.
|-- Sources/NotebookCore/       # Каталог, доска, страницы, пространственные чернила, диск и wire.
|-- Tests/NotebookCoreTests/    # Камера, владение, слияние и публикация файлов.
|-- Applications/
|   |-- project.yml           # Нативные iPad и Mac targets.
|   |-- Shared/               # Единая сцена, лист, обложки, WebKit и модель.
|   |-- iPad/                 # Pencil, один Metal-тракт и стабильные жесты сцены.
|   `-- Mac/                  # Зеркало, file watch, PNG листов и текущего вида.
|-- MCP/                      # Локальный stdio-сервер над файлами Mac-приложения.
|-- docs/research.md          # Системные API, владельцы и измеренные следствия.
`-- verify.sh                 # Полный локальный проверочный маршрут.
```

Общий ход принадлежит `NotebookCore.CollaborationStore`: типизированный пакет
проходит проверку, причинное согласование полей и восстанавливаемую публикацию
вместе с квитанцией. `NotebookBridge` исполняет этот контракт для MCP;
TypeScript готовит содержание и транспорт. Сеть переносит каталог, дерево и
изменившихся тяжёлых владельцев одним `CollaborationEnvelope`; приёмник публикует
содержание и историю в одной транзакции. Отмена проверяет значения и причинные
версии, сохраняя человеческую доработку. `DocumentStateRecord.fieldVersion`
владеет тем же правилом для интерактивного состояния.

`SharedContext` сохраняет указания и ответы по устойчивым ID; отдельный выбор
человека не меняет адрес начатого хода. `CollaborationAction.contextID` связывает
результат с рассмотренным контекстом, а самостоятельный ход создаёт свой контекст
в той же транзакции. `NotebookSearch` ищет названия и текст для приложения и MCP
в одном завершённом снимке. Физический
владелец, локальная область или ID блока и хеш исходника дают точную ссылку.
`NotebookAttentionProjection` переводит её через существующую геометрию сцены;
`DocumentRenderRegistry` получает области блоков от живого WebKit.
`NotebookPointerView` завершает один контакт и возвращает прежний инструмент.
Одна область может содержать ссылки на несколько физических владельцев.
`ReferenceVision` сравнивает окончательные региональные пиксели общего Metal-
рендерера и содержание пересекающихся элементов; пока снимок готовится, статус
остаётся `checking`. Исходный отпечаток переживает вытеснение PNG из кеша.
`NotebookNavigationView` использует Core-поиск и владельцев выбора страницы;
«Показать» сохраняет место, а возврат адаптирует его через прежнюю геометрию камеры.
Миниатюры монтируют не более шести тех же поверхностей с отключённым вводом.
`PenControlsView` выбирает инструмент без раскрытия; отдельная кнопка открывает
настройки. `ElementEditingSession` владеет рамочными жестами переноса и размера.
`NotebookCollaborationView` показывает ход и отдаёт «Показать» существующим
владельцам камеры и перелистывания после окончания касания. iPad подтверждает
показ точной ревизии только после готового кадра и проверки видимой области.

`TargetRenderRequest` заказывает поверхность независимо от камеры человека.
`MacPreviewPublisher` получает бумагу, окончательные чернила и агентские слои
через тот же составной рендер. `SpatialInkGeometry` и общий Metal-шейдер исполняют
сырые пространственные операции обеих платформ. Целевая квитанция связывает
PNG, область, диагностику и карту чернил; расчёт размещения передаёт хеш всех
рассмотренных слоёв в проверку следующего хода. Миграция формата сотрудничества
создаёт точную резервную копию и один маркер завершённой публикации.

Путь тетрадного листа: намерение человека -> `PageDocument` -> атомарный файл ->
Network.framework -> такой же лист на втором устройстве. Pencil и
`appendInkStroke` агента меняют общие чернила в `drawingData`; Markdown, SVG и
интерактивные элементы меняют `elements`. `PageInkDrawing` хранит UUID, порядок и
неактивные записи отменённых контактов; слияние сохраняет независимые штрихи,
а старый сетевой пакет не возвращает отменённую линию. `PencilUndoHistory` помнит
только UUID собственного контакта. На доске и обложке тот же агентский штрих
попадает в `SpatialInkJournal`. `CollaborationExpectation.inkRevision` проверяет
версию рассмотренных чернил при записи и точность показанного результата;
`CollaborationResults` возвращает физическую область штриха без выдуманного ID
элемента. Импортированная основа PencilKit сохраняет отдельную границу смены
целого растра; нативные штрихи поверх одной основы сходятся по своим UUID.

Путь документа: выбранный при создании A4/Letter + Markdown/LaTeX/interactive
source -> `DocumentDocument` -> WebKit на обоих устройствах. WebKit переносит
единый поток содержания по конечным физическим листам, а Tectonic получает тот
же размер бумаги. Состояние кнопок и моделей принадлежит отдельному
`DocumentStateJournal` и сходится по устойчивому `blockID`; изменение исходника
его не перезаписывает. MCP собирает печатную форму из того же исходника через
Tectonic. Интерактивный блок остаётся живым в приложении и явно обозначается в
статическом PDF.

Пространственный путь разделён по смыслу: `WorkspaceIndex` владеет составом и
выбором тетрадей, документов и порталов. `BoardHierarchy` владеет строгим
деревом бесконечных досок как плоским списком: постоянный корень и каждый портал
имеют UUID своего `BoardDocument`, поэтому дочерняя доска получает ровно одного
родителя без рекурсивного JSON. Узлы сходятся независимо. Перед публикацией
пришедшего каталога модель объединяет его дерево с текущими узлами, сохраняя
независимые изменения других досок и камер порталов. Перемещение, стопка и выход
из портала сохраняются через `saveMergedBoard` под файловым замком. Проверка требует
единственного достижимого владельца для каждого предмета. `BoardDocument`
владеет размещением, стопками и элементами одной доски, `SpatialInkJournal` —
действиями Pencil с UUID доски либо обложки, а `SessionPresence` — активной
доской, камерой, режимом и фокусом. На iPad одна сцена и один
распознаватель владеют полным щипком от листа до доски. На Mac
`CurrentViewReceipt` называет одну типизированную завершённую поверхность и
связывает текущий PNG с точными версиями этих владельцев. Для листа и документа
он также хранит SHA-256 составного растра, из которого построен текущий вид.
`PageVisionReceipt` связывает один завершённый `drawingStamp` с полным PNG,
вариантом без сетки, видимыми клетками и увеличенными областями. Области выводятся
из альфа-пикселей окончательного `InkRasterRenderer`. Формат квитанции 2
различает физический вид `faithful` и контрастный вид чтения `ink`.
Положение участника стопки выводит только `WorkspaceItemStackPresentation` из порядка
в `BoardDocument`: доска и камера открытой тетради получают у него один центр.
В сфокусированном состоянии сцена монтирует одного выбранного участника, а
остальные остаются членами стопки. `SessionPresence` хранит UUID тетради и не
дублирует вычисляемый UUID стопки. Каждый `BoardNode` хранит каноническую
`portalCamera` отдельно от содержимого своего `BoardDocument`. Портал рисует
дочернюю доску этой камерой, а `BoardPortalProjection` переводит её в текущий
viewport так, чтобы последний кадр портала и первый кадр активной дочерней доски
совпадали, включая нецентральный щипок. Портал не участвует в раскрытии бумаги
и `NotebookDockingField`: вход передаёт координаты, когда его окно перекрывает
экран, а выход проходит входной масштаб доски. В момент передачи
`CameraGestureTrajectory` один раз выражает показанную камеру и ту же пару пальцев
в новом владельце. Отпускание сохраняет кадр без автоматического приближения.
Выход нормализует граничную камеру обратно в портал и продолжает остаток щипка
на родителе даже с минимального масштаба; явная кнопка возврата сохраняет текущий
вид и использует `SceneCameraSettlement`. `portalStamp` и `BoardDocument.stamp`
сходятся независимо. При смене поверхности во время контакта модель сразу
передаёт существующий `NotebookInputActivity` новому физическому владельцу.
`BoardPortalCamera` хранит положительное отношение масштаба, а `SpatialCamera`
ограничивает экранный масштаб. `BoardPortalProjection` рендерит портал через
допустимую экранную камеру на расширенном холсте и уменьшает его в каноническую
рамку. Выход с минимального масштаба и повторный вход сохраняют проекцию в обоих
положениях экрана. `BoardHierarchy.revision` называет всё дерево через UUID
каждого узла, `board.stamp` и `portalStamp`; квитанция текущего вида формата 6
и `MacPreviewPublisher` используют эту идентичность. MCP возвращает и проверяет
ревизию конкретного `BoardDocument` для записи.
Портал использует `WorkspaceItemCoverView` и `SpatialElementContent` как активная
доска. `PortalBoardInkView` передаёт сырые операции тому же `InkCanvasView`;
координатор сохраняет готовую геометрию до изменения чернил этой поверхности;
движение камеры меняет только её проекцию.
`AgentElementSnapshotCache` хранит точный растр исходника и состояния на обеих
платформах. При смене владельца `SpatialElementContent` показывает этот растр,
а создание нового WebKit активной доски ждёт разрешения фоновой подготовки.
Пассивный портал освобождает WebKit после получения точного растра и не запускает
его снова при отпускании пальцев; новая версия исходника или состояния получает
свой растр. Уже смонтированный интерактивный элемент активной доски остаётся
живым при следующем щипке. `WorkspaceSceneProjection.mountsContent` ограничивает
монтирование физических предметов рабочим кадром с запасом для подготовки и
полной рамкой тени. Сфокусированный предмет, выбранный или поднятый предмет и
кандидат жеста удерживают своих владельцев; полный каталог и геометрия остаются
доступны для адресации и камеры. Снимки обходят то же конечное дерево.
`SpatialInkMeshCache` передаёт готовую геометрию тому же физическому владельцу
между порталом и активной доской. Кеш удерживает не больше 16 поверхностей и
64 МиБ учётного объёма геометрии и исходных замеров. Точное сравнение журнала
замечает независимые изменения даже при прежнем максимальном stamp.
Неподготовленная новая поверхность сначала убирает чернила прежнего владельца;
завершение отменённой подготовки не заменяет текущий кадр.
`SpatialBoardGrid` получает итоговый экранный масштаб через всё дерево порталов:
при передаче доски шаг и радиус точек не выбираются заново по локальному холсту.
`WorkspaceSceneProjection.snapshotLayers` перечисляет веб-слои и поверхности чернил того же конечного
дерева отображения. Mac-публикатор заранее получает их через обычный
`AgentWebCoordinator` во временном окне; `afterScreenUpdates` завершает растр
даже для скрытого окна. Публикатор слабо ссылается на модель, отменяет задачи
при завершении и связывает каждое окончание с поколением своей публикации. В стопке помещается от
двух до пяти тетрадей;
её полностью раскрытый веер занимает один и тот же ограниченный размах, поэтому
добавление участника сужает доступную полосу каждой обложки, а не выталкивает
крайние обложки за экран.
Во время активного щипка `SpatialCamera.pinched` владеет сырой траекторией
камеры. На доске поле обложки выбирает кандидата, а `NotebookDockingField` служит
единственной поправкой: после видимого приближения оно всё сильнее ведёт камеру
к центру и масштабу этого кандидата. Одна `NotebookDockingCorrection` выводит из
этой силы два ответа. Во время подхода центр приходит раньше, а масштаб сохраняет
осторожную квадратичную кривую. В точном кадре передачи обложке сцена замораживает
уже видимую поправку; после него раскрытие обложки становится единственной
координатой, а центр и логарифмический масштаб вместе ускоряются к
полноэкранному листу по кривой степени `1,35`. `CameraGestureTrajectory` каждый
кадр считает только от начала пары пальцев: уже показанная магнитная поправка и
смена направления никогда не становятся новой базой. Поле применяется одинаково
в обе стороны и вычитает силу, уже видимую в начале нового жеста, поэтому обратный
путь совпадает с прямым, а повторный щипок не притягивает предмет второй раз. Пока
текущий кандидат остаётся в удерживающем ореоле, соседняя обложка не может
перехватить камеру из-за одного шумного измерения.
`TwoFingerIntentArbiter` один раз подтверждает радиальное движение и ставит
честную базу пары пальцев. Сцена затем выводит направление из каждого нового
измерения: разворот щипка сразу разворачивает камеру. `NotebookOpeningIntent`
передаёт тетради подтверждённый щипок на `0,84` обычного размера закрытой
обложки. Точный масштаб передачи становится началом раскрытия, поэтому далёкий
подход остаётся масштабом доски, а близкая тетрадь открывается раньше и без
скачка. С первого видимого изгиба один `openProgress` одновременно раскрывает
обложку и усиливает `NotebookDockingField`: в начале тяга почти невесома, а у
листа камера уверенно догоняет полноэкранное положение. Второго состояния
захвата и позднего порога нет. Один мягкий отклик отмечает первый видимый изгиб.
Если пальцы подняты после движения наружу, фактическая скорость переходит тому
же короткому пружинному стыку и он завершает раскрытие; точный нулевой прогресс
остаётся камерой доски. Явный обратный щипок сохраняет владельца у пальцев и
продолжает ту же камеру через закрытую обложку до
`SpatialCamera.minimumScale`. Новый жест с частично раскрытой обложки вычитает
уже показанный магнитный ответ.

`PageTurnSurface` является единственным временным владельцем перелистывания
тетради и документа. Оба вида содержимого только предоставляют страницу по
индексу и принимают завершённый индекс. На iPad системный
`UIPageViewController.pageCurl` владеет движением руки, возвратом и посадкой.
Соседние страницы заранее смонтированы за текущей: Metal и WebKit сообщают о
первом готовом кадре, после чего UIKit получает тот же живой экземпляр листа.
Как только жест раскрывает направление, `PageTurnPrewarmWindow` монтирует ещё
один лист за точкой посадки. У тетради посадка на последний чистый лист сразу
открывает следующий чистый лист локальному владельцу, не ожидая нового прохода
SwiftUI.
Переданный UIKit экземпляр до смены владельца остаётся в его пуле и больше не
монтируется в prewarm-контейнер: UIKit может завершить или повторно использовать
его уже после delegate callback.
На Mac этот контракт исполняет один `MacPageTurnView`: он владеет трекпадом,
presentation transform, скоростью, пружиной и commit. Сценовый распознаватель
уступает горизонтальное движение странице и сохраняет за собой щипок камеры и
двухпальцевую отмену. `DocumentWebView` показывает только один
фиксированный индекс и не содержит scroll-snap или собственной физики.
Живой `NSHostingView` присоединяется во время обновления SwiftUI, а его вложенный
WebKit размечается следующим обычным проходом AppKit; синхронный вложенный
layout во время `_setWindow` нарушает контракт геометрии `WKWebView`.
Интерактивен только текущий лист; соседние листы являются теми же живыми
поверхностями с выключенным вводом. Фактической позицией листа владеет
JavaScript-renderer: изменение геометрии сразу восстанавливает его фиксированный
индекс, а Swift считает WebKit готовым только после квитанции с теми же
`documentID`, `renderToken` и `pageIndex`.
`DocumentWebCoordinator` сравнивает канонический JSON с отсортированными ключами;
JavaScript последовательно применяет содержание и объединяет ожидающие пакеты
до последнего. Завершение набора сохраняет текущий индекс, а квитанция читает
его после двух кадров. Конфигурация геометрии сохраняет известное число листов
до завершения новой пагинации. MathJax получает SVG-шрифт, дополнительные
символы и assistive MathML из bundle; нативный диктор читает MathML.
Интерактивный исходник монтируется script-элементом внутри sandbox iframe.

Устойчивый выбор публикуется один раз после посадки: тетрадь абсолютной
`WorkspaceIndex.selectPage` меняет выбранный лист, а документ —
`SessionPresence.documentPageIndex`. `PageTurnSelectionTracker` оставляет
последнюю визуальную посадку главной, пока одна или несколько публикаций
догоняют её, поэтому старое подтверждение не возвращает лист назад. Файловая
запись выбора идёт после изменения памяти вне главного актора; следующий жест
её не ждёт. Дальний внешний переход получает короткое растворение. Снимок
документа связывает страницу с `contentStamp + stateStamp + documentPageIndex`.

На iPad `PhysicalWebViewport` удерживает канонический размер WebKit из
`WorkspaceItemGeometry.document` либо рамки агентского элемента. Меняющаяся рамка
сцены меняет только внешнюю проекцию; SwiftUI не округляет внутренний холст,
а WebKit элемента не вычитает безопасные поля окна. `SpatialWorkspaceView`
сначала задаёт физический размер содержания доски, затем масштабирует весь слой
камерой. Ручки редактирования остаются экранного размера; только завершённое
изменение размера элемента меняет физический холст. Размер шрифта и
прямоугольники строк сохраняются при дробном округлении камеры и повороте экрана.
`document-shell.html` задаёт печатную шкалу Georgia: основной текст 12/14,5
пункта, заголовки 17,28/22, 14,4/18 и 12/14,5 пункта. Первый заголовок
совпадает с верхним полем владельца бумаги. `DocumentGeometryTests` измеряет
эти значения относительно физического листа для A4 и Letter, затем проверяет
устойчивость строк при смене экранной рамки. `MCP/latex.ts` сохраняет ту же
гарнитуру и стандартную шкалу 12-пунктовой статьи; уровни Markdown переходят
в section, subsection и subsubsection.


`CoverOpeningSurface` является единственным временным владельцем раскрытия
обложки и одинаково обслуживает тетрадь и документ. Камера передаёт ему один
обратимый `openProgress`; Core Image выводит из него изгиб, обратную сторону и
освещение сгиба. Внешняя тень закрытого предмета плавно передаёт лист этому
освещению в самом начале изгиба. Каждый Metal-кадр сначала очищается до
прозрачности, поэтому следующая форма обложки всегда заменяет предыдущую целиком.
Выбранная, сфокусированная или найденная текущим щипком обложка в устойчивом
конце заранее замораживает точный уже показанный вид и выводит один практически
невидимый кадр в своём настоящем `CAMetalLayer`. Поэтому первый видимый изгиб не
владеет снимком SwiftUI, созданием drawable или компиляцией Core Image. Один
общий `CoverCurlGPU` исполняет фильтр тетрадей и документов. Снимок живёт только
на время физического перехода, потому что внутри обложки могут жить Metal и
WebKit. Текущий лист
остаётся живым под этим изгибом, а в конечных положениях управление снова
принадлежит живой обложке либо живой странице. Снимок не становится состоянием
предмета и не создаёт второго владельца его текста, элементов или чернил.
Изменение обложки, пришедшее посреди жеста, становится видимым на ближайшем
конечном положении и не заменяет лист, который уже находится в руке.
Камера, касания и сохранённая геометрия по-прежнему видят ровно прямоугольник
тетради. Только Metal-холст изгиба шире: со стороны открытия он резервирует
целую ширину обложки и поле для тени. Core Image получает прозрачную цель лишь
в исходных границах листа, а готовый изгиб выводит на расширенный холст, поэтому
обложка физически выходит наружу, не превращая запасное поле в невидимый предмет.
На iPad видимость живой обложки принадлежит контейнеру вокруг hosting-вида,
поэтому источник снимка остаётся непрозрачным. Контроллер откладывает захват
до следующего прохода главной очереди в присоединённом окне: первый снимок
содержит уже смонтированное содержание даже при запуске с открытым листом.
`InkCanvasView.isStableFramePresented` подтверждает готовность чернил;
ожидание уступает главный поток между кадрами и сохраняет живую обложку.
Устойчивый выбор предмета меняется в памяти при посадке камеры, сразу уходит в
сеть и записывается атомарно вне главного актора; путь касания не ждёт диск.

`WorkspaceItemGeometry` владеет единым прямоугольником предмета. Тетрадь имеет
размер `834 × 1194` и радиус `0,8 см`; документ выводит размер из неизменяемого
`DocumentDocument.paperSize` через `132 / 72` пространственных points на
PostScript point и имеет радиус `0,12 см`. Эту геометрию получают обложка,
страница, изгиб, камера, Pencil, элементы и снимки портала. `contentShape`
accessibility получает тот же физический контур; видимая толщина листов
остаётся оформлением и сохраняет прежнюю рамку жестов. WebKit вписывает
бумагу в этот же прямоугольник, сохраняя внутренние печатные поля. MCP возвращает
`coverSize` и проверяет размещение элементов по реальному размеру владельца.
`WorkspaceCoverMaterial` выводит устойчивую светлую палитру из UUID тетради;
`WorkspaceCoverRaster` кеширует готовый материал по палитре и геометрии,
а прозрачную тень — по геометрии и подъёму. Камера масштабирует эти постоянные
пиксели; тень лежит отдельным слоем под живыми Pencil, текстом и WebKit.
Тот же материал входит в растр изгиба. Блок листов
остаётся под движущейся обложкой, а один свет задаёт контактную и мягкую тени.

`WorkspaceItemGeometry` переводит физический предмет между размерами окна.
Примагниченный `page` имеет канонический масштаб, а свободные `cover` и `board`
хранят масштаб относительно вписывания тетради; поворот экрана и обратный поворот
обязаны быть обратимы. По сети активный `SessionPresence` обновляет живое зеркало,
но файл и MCP-PNG принадлежат только `settled`-состоянию.
`CurrentViewPreviewWriter` в этом состоянии строит `SettledSceneSnapshot` доски,
обложки, листа либо документа. Внутри `ImageRenderer` не монтируются жесты,
`PageTurnSurface`, `CoverOpeningSurface`, Metal drawable, живой WebKit, соседние
страницы и вложенные hosting-графы. Лист сначала получает один составной растр
из бумаги, общего растра чернил и готовых снимков агентских элементов.

На iPad выбранный лист остаётся смонтированным в единственном `InkCanvasView`
под обложкой. При подходе к другой тетради этот владелец заранее переносится под
её ещё непрозрачную обложку. Щипок меняет доступность ввода, сохраняя один и тот
же Metal-тракт на всём переходе. Лист, лицевая и обратная стороны обложки имеют
одну непрерывную форму с физическим радиусом углов `0,8 см`.
`PageDocument.drawingData` хранит `PageInkDrawing` с измеренными точками и
упорядоченными действиями ручки и ластика. `SpatialInkGeometry` и общие шейдеры
дают живую линию, устойчивую текстуру масштаба 2 и снимок агента. `IncrementalInkMesh`
кеширует готовые сегменты и перестраивает изменённый хвост с соседними стыками.
`PageInkRasterCache` связывает Mac-растр с UUID, ревизией и размером листа.
`PageInkMigration` однократно импортирует прежний `PKDrawing` по окончательному
PNG, сохраняя оригинал через файловый замок в `migrations/before-ink-v1/pages`.
Сохранённая основа включает прежние стирания; `PKStroke.path` принадлежит лишь
архиву PencilKit. Живые Metal-партии остаются до готовности точного растра той
же принятой ревизии; новое касание отменяет более старую сборку.

Пространственный Pencil имеет один оконный ввод, который через
`SpatialInkSurfaceRegistry` направляет точки физическому владельцу: доске либо
конкретной обложке. Доска и каждая смонтированная обложка несут собственный
`InkCanvasView`; обложка двигает и поворачивает его тем же SwiftUI-преобразованием,
что и своё тело. Завершённый жест закрепляет уже показанные сырые точки в этом
же холсте, затем кладёт их в `SpatialInkJournal`; устойчивый рендер повторяет
точки и операции ластика напрямую, без второй геометрии PencilKit. Следующее
касание очищает только новый активный жест. `NotebookInteractionTouchView` один
разбирает прямое касание обложки: системный `UITouch.tapCount` отличает выбор от
двойного касания, а удержание начинает перемещение. На доске двойное касание
открывает предмет; на сфокусированной обложке оно создаёт текст либо передаёт
готовый текст редактору. Верхний слой касаний пропускает ввод только сквозь
рамку активного текста и интерактивные элементы агента. Оконный `BoardPanView`
ведёт камеру одним пальцем с доски и с поверхности любой обложки. При начале
движения `NotebookInteractionTouchView.yieldToCameraPan` передаёт ожидающее
касание камере и завершает ожидание удержания; уже поднятая обложка сохраняет
палец до размещения предмета. Короткое касание свободной доски тем же оконным
владельцем снимает выбор. Редактор текста и интерактивные области сохраняют
свой ввод через существующие проходные рамки.

Созданный агентом элемент принадлежит тому же листу или `BoardDocument`, который
видит человек. На iPad один `ElementEditingSession` в `NotebookAppModel`
временно владеет типизированным выбором и смещением жеста. Все смонтированные
`EditableElementContainer` только показывают это состояние и передают ему
касание, перетаскивание и удаление. Завершённое действие меняет `frame` либо
удаляет элемент обычной ревизией `PageDocument.elements` или
`BoardDocument.elements`, которая сходится с MCP тем же путём; после выбора
ручки или ластика WebKit снова получает интерактивные касания.

Печатный `WorkspaceItem.title` может быть пустым: обложка с Pencil и агентскими
элементами является полноценной визуальной идентичностью. MCP связывает её PNG
и `screenFrame` с точным `itemID`, а `shortID` различает похожие безымянные
обложки. `NotebookInputGate` удерживает контакт Pencil до подъёма и завершает
пересёкшую его пару пальцев вместе с движением руки. Камера ждёт публикации
геометрии завершённого Pencil, а перелистывание может начаться сразу после
подъёма: отдельная задача координатора уже владеет сериализацией независимо от
жизни view. Все заранее смонтированные листы регистрируют свои finishers, но
gate ждёт только лист, который сейчас принимает Pencil. Тихая новая пара
владеет undo, а наблюдаемое радиальное движение сохраняет смысл щипка до
отпускания. При выходе с листа gate завершает текущее действие и ждёт его
сериализацию до начала камеры. Удаление дочерней доски проверяет предметы, элементы и активные штрихи пера,
сохраняющие возможность отмены ластика. `NotebookStore.deleteWorkspaceBundle`
повторно проверяет этих владельцев и состав каталога под файловым замком;
новое содержимое сохраняет доску и возвращает модели явную причину отказа.
Удаление
публикует `WorkspaceIndex`, затем `BoardDocument`, затем убирает листы,
исходники документов, их состояние и PNG. `saveMergedPage`,
`saveMergedDocument` и `saveMergedDocumentState` под тем же замком сверяют
принадлежность каталогу и не воскрешают удалённое содержимое. Сетевые страницы,
документы и состояние, пришедшие раньше создающего их каталога, живут только в
staging. Новый `WorkspaceIndex` публикуется после полного содержимого и точной
доски либо отбрасывает осиротевший хвост. Снимок, который одновременно добавляет
и удаляет предметы, проходит через временную объединённую доску, поэтому и
старый, и новый каталог имеют ровно одного владельца размещения.

`CollaborationAction` связывает описание, исходные ссылки, явных владельцев и
типизированный пакет операций. `notebook_apply` передаёт его локальному
`NotebookBridge`, а `NotebookCore/CollaborationStore.swift` исполняет проверку,
публикацию и бережную отмену под общим замком. `CollaborativeContent` хранит
причинные версии полей элементов, блоков и размещений: независимые правки
сходятся, пересекающаяся человеческая правка сохраняет значение. Подготовленная
транзакция завершается следующим владельцем записи после сбоя; повтор ID
возвращает квитанцию того же хода. [Контракт](docs/collaboration.md) ведёт к
проверкам. Долгоживущий `NotebookAppModel` Mac перечитывает опубликованных
владельцев и отправляет новые версии на iPad. `DirectoryWatcher` принадлежит модели, а не окну; `MCP/run.sh` будит
канонический `~/Applications/Notebook.app`, поэтому закрытое окно не разрывает
цепочку. `MacPreviewPublisher` также принадлежит долгоживущей модели: он строит
`current-view` в размере завершённого iPad `SessionPresence.viewport` и обновляет
PNG листов даже без смонтированного окна. `notebook_observe` внутри одного
вызова ограниченно ждёт, пока PNG и его квитанция догонят владельцев, и только
после исчерпания этого окна возвращает `snapshot_pending`. MCP принимает текущий
формат presence 4 с `boardID` и `documentPageIndex`, а форматы 1–3 поднимает к нему при
чтении. Bonjour
группирует интерфейсные адреса по имени Mac и держит одну
задачу соединения на устройство, используя остальные адреса как запасные.

`Applications/AppIcon.svg` является единственным владельцем значка Mac и iPad.
`render-app-icon.sh` выводит из него все размеры без второго отступа; системная
маска Apple уже формирует внешний контур значка.

`DocumentDocument` является единственным устойчивым владельцем Markdown,
LaTeX и исходников интерактивных блоков. `DocumentWebView` исполняет один
фиксированный лист; `PageTurnSurface` заранее держит соседний живой WebKit в
окне и ждёт его готовый кадр, но только текущий лист принимает ввод и создаёт
снимок. Каждый interactive block работает в своём
`sandbox` iframe без сети. Двойное касание заменяет только Markdown/LaTeX-блок
текстовым редактором и при уходе сохраняет исходник. На Mac завершённый WebKit
кадр попадает в `DocumentSnapshotCache`; `CurrentViewPreviewWriter` публикует
квитанцию документа только с точным снимком его
`contentStamp + stateStamp + documentPageIndex` и SHA-256 этого снимка.
`DocumentDocument.paperSize` неизменяем после создания: прежний format 1
мигрирует в A4, а новая запись всегда имеет format 2.

`Applications/install.sh` владеет установкой проверенной пары Mac/iPad. Он
связывает проверку и обе сборки неизменным отпечатком исходников, сохраняет
прежний Mac bundle и тетради, затем проверяет установленную публикацию через
`MCP/test/installed-smoke.ts` и обычный `notebook_observe`.

MCP `readSpatialInk` поднимает прежнюю поверхность доски с отсутствующим
`ownerID` к постоянному корню, как Swift `SurfaceID`. Идентичности действий,
их версии и замеры остаются прежними. Установочный smoke ограниченно ждёт
первую свежую квитанцию после запуска новой программы; обычное наблюдение
сохраняет своё короткое окно ожидания публикации.


`CollaborationPlacementRequest` считает до 32 новых элементов одним пакетом по
одной готовой карте чернил. `CompositionScope` проверяет геометрические изменения
и в расчёте, и в транзакции `CollaborationStore`: источники контекста и явно
названные `additionalOwners` ограничивают перемещаемые предметы. Расчёт сначала
сохраняет текущую композицию; разрешённые перемещения появляются только при
нехватке места. Ответ содержит все рамки либо явную недоступность всей
композиции. ID предшествующего результата может стать опорой следующего.

`NotebookInputGate` удерживает и Pencil, и пассивно наблюдаемые контакты сцены.
`NotebookInputActivity` временно защищает физического владельца в Core; apply и
undo повторно проверяют версии после ожидания вне файлового замка. iPad объединяет
пересёкшиеся входящие пакеты до отпускания и только тогда подтверждает приём.
`InputFrameMonitor` хранит ограниченные времена обслуживания кадров без содержания;
эти времена не заменяют подтверждение GPU-показа.

`CollaborationReadSnapshot` готовит временную проекцию истории вне главного
актора: кодирует только нужных владельцев по одному разу и использует обычные
правила ссылок и доработок Core. `NotebookAppModel` инвалидирует её при изменении
входов, отменяет устаревшую подготовку и принимает лишь текущее поколение вне
ввода. Строки истории читают готовые данные за постоянное время; региональный
опрос читает квитанции по готовой ревизии без замка содержимого. Подготовленная
ссылка не подтверждает показ: его по-прежнему удостоверяет готовый кадр iPad.


Подготовка чернил и диска не принадлежит обработчику касания.
`PageDocument.prepareInkChange` готовит типизированный результат вне главного
актора; `publishInkChange` принимает его только для того же UUID и `drawingStamp`.
Повтор после изменения ревизии включает входящий вклад, а отмена хранит UUID
своих действий и не удаляет историю новых контактов. Камера ждёт только контакт;
барьер совместного изменения ждёт также публикацию. `NotebookDiskRefresh`
готовит целый согласованный срез через `NotebookStore`, а модель принимает его
только при прежней версии памяти и вне активной камеры. Записи одного владельца
последовательны и объединяют ожидающие состояния; неизменённые квитанции не
порождают файловое эхо. Завершение приложения ждёт уже принятые изменения.
`SpatialInkMesh` строит геометрию около точных мировых плиток, объединяя соседние
партии одного инструмента без изменения порядка стираний. `InkCanvasView` в
`Shared` хранит эти буферы на обеих платформах; камера меняет только uniform.
Живая очередь Metal отделена от фонового чтения растра, общий владелец GPU
кеширует неизменяемые программы. Первый кадр раскрывается по завершению команды
без ожидания GPU главным потоком и без неявного растворения слоя; готовность
для снимка подтверждает следующий кадр уже раскрытого слоя.
`SceneCameraSettlement` владеет дисплейными
отсчётами доводки: каждый отсчёт меняет действительную камеру, отмена сохраняет
последний отсчёт, а только посадка сохраняется на диск.
`SpatialInkRasterSnapshot` готовит неизменяемые растры конечного дерева для
экспорта. `ImageRenderer` читает готовые слои; карты чтения и PNG кодируются
