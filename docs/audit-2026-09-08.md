| W1–W3 | State/source refresh recreated runtimes or discarded editor drafts |
| W4–W6 | Pages ran off-page programs, hidden-window scheduling stalled Mac preparation, and stale/thumbnail layout could count as shown |
| Q1–Q2 | Full startup work occupied UI and green tests did not establish physical responsiveness |

The conclusion was multiple ownership/publication failures rather than one slow
animation. Evidence strength varied: actual Core/WebKit reproductions and measured
CPU/I/O paths were separated from source-only race scenarios and unmeasured GPU or
hardware behavior. Local checks were not promoted to installation/acceptance.

The repair sequence centered on one transactional store, authenticated bounded
delivery, one accepted input owner, accountable physical resources and exact
source-to-shown receipts. Historical archive migration was later canceled by Amir;
it is not an outstanding ordinary-release prerequisite.
