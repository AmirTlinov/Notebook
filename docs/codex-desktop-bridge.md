# Прямой разговор с Codex: граница подключения

## Требуемый владелец

Чат Notebook должен продолжать ту же задачу, которой владеет Codex на Mac.
Codex сохраняет историю, запускает модель и принимает решения об инструментах.
Notebook хранит человеческий ввод до доставки, ссылки на общее содержание и
ограниченное представление истории. Агент свободно работает во всём общем
пространстве через существующие инструменты Notebook; отдельного режима
«спросить / сделать» и классификации просьб быть не должно.

Замена нынешнего `NotebookAgentExecutor` допустима после доказательства
каталога, открытия существующей задачи, создания новой, отправки, потока ответа,
остановки и запросов разрешений **через существующего владельца Codex**.
Самостоятельный App Server, читающий ту же историю, не доказывает этот контракт.

Это отрицательный результат предварительной проверки, не успешная интеграция.
Из ответа на обнаружение владельца нельзя вывести наличие каталога, создания
задач, полноценного чата или доступа к сервису инструментов приложения.
Закрытие соединения само по себе не называет причину: проверка не превращает
его в выдуманный код ошибки авторизации. При отдельном исследовании установленного
клиента найден собственный контроль допустимости процесса у этого сервиса;
обход его проверки не является частью интеграции Notebook.

Результат относится к проверенным каналам и версии, а не доказывает, что никакая
будущая версия или разрешённый интерфейс Codex не сможет предоставить эти действия.
Внешний протокол подключения к каталогу и созданию задач пока не установлен.

## Воспроизводимая проверка

Проверяющий код —
[Tests/NotebookCodexBridgeHarness/probe.py](../Tests/NotebookCodexBridgeHarness/probe.py).
Он допускает только чтение, ограничивает кадры и время ожидания, не объявляет
себя владельцем чужого разговора и не сохраняет тексты задач. Программа читает
только метаданные версии приложения, не извлекает его код во время проверки.

```sh
python3 -B -m unittest discover \
  -s Tests/NotebookCodexBridgeHarness -p 'test_*.py' -v

# TASK_ID — UUID уже существующей локальной задачи, без её запуска или resume.
python3 -B Tests/NotebookCodexBridgeHarness/probe.py \
  --thread "$TASK_ID" \
  --app-bundle /Applications/ChatGPT.app \
  --report ".build/codex-desktop-preflight/$(date -u +%Y%m%dT%H%M%SZ).json"
```

Код выхода `2` означает, что обнаружение владельца и чтение каталога вместе не
доказаны. Код `0` означает только успешную предварительную проверку чтения;
`featureReady` остаётся `false`, а `notTested` перечисляет оставшиеся условия.
Предыдущая квитанция не перезаписывается и не используется вместо нового запуска.

Необязательный `--app-tools-socket` принимает адрес для одной диагностической
попытки обычного внешнего клиента. Это аргумент лабораторной проверки, не
пользовательская настройка подключения. Проверка не ищет случайные сокеты,
не получает токены, не меняет настройки Codex и после отказа не ищет способ
выдать себя за разрешённый процесс.

Все 16 проверок самого клиента прошли. Они проверяют дробление кадров и UTF-8,
ошибочные длины и JSON, идентичность ответа, ограничение чужих уведомлений и
времени, права Unix-канала, запрет изменяющих запросов и честный отрицательный
результат. Они **не** являются проверками работы модели или физического iPad.

## Что не заменено и условие продолжения

Панель, доставка переписки и замена исполнителя не реализованы: первый
обязательный этап полного плана не пройден. Прежний исполнитель не удалён,
поскольку рабочего заменяющего пути ещё нет. Установленная пара, рабочие данные,
сопряжение, авторизация Codex и глобальная конфигурация не изменялись.

Для продолжения нужен разрешённый внешний вход к владельцу desktop, который
предоставляет каталог и создание/открытие задач, а затем проходит остальные
перечисленные проверки. После этого реализуется один адаптер в Mac-sidecar,
без копии агента, переписки или аккаунта. Не использовать вместо недостающего
входа автоматизацию интерфейса, чтение rollout-файлов, подмену клиентского
процесса, модификацию Codex или отдельного «агента Notebook».
