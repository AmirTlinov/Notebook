# Technical Design Document: Pencil → фигуры, текст и математика через MyScript

Дата решения: 17 сентября 2026. Задача и фактические статусы:
[GUI-205](https://linear.app/main-cluster/issue/GUI-205).
Просмотренная основа runtime: Notebook `b08da31`.

Это единственный целевой **Technical Design Document** распознавания Pencil.
Он заменяет прежний дизайн «QuickShape для фигур + PencilKit для подписей»
в этом же файле, а не добавляет к нему третий путь. Документальное изменение
**не устанавливает SDK, не включает распознавание и не удаляет рабочий код**.
На просмотренном срезе работают собственные QuickShape и нативная графика;
MyScript и `PKStrokeRecognizer` в приложении не подключены. Обязательное
удаление заменённого runtime входит в ту же поставку, что и его замена (§17).

## Навигация

- §§1–3: объём, владельцы, зависимость от SDK и офлайн-контракт.
- §§4–6: жесты, выбор источников и подготовка видимого письма.
- §§7–9: результат распознавания, авторское дерево, математическое ядро
  и точные границы типов.
- §§10–12: общий writer, проекция, Undo/Redo и доставка.
- §§13–15: исполнение, ресурсы, координаты и показ.
- §§16–18: отказы, замена старого пути и наблюдаемые результаты.

**Принцип UX:** пользователь один раз выражает намерение. Очереди,
финализация измерений, проверка свежести и сохранение — обязанности программы,
не дополнительное удержание, диалог или требование повторить успешный жест.

## 1. Результат и предел задачи

На листе и доске пользователь рисует Pencil обычные чернила. Удержание в конце
наброска превращает его в редактируемую фигуру. Отдельное удержание точки рядом
с написанным превращает письмо в подпись фигуры либо свободный блок текста
и математики. Формулы вычисляются локально, не заменяя авторскую запись.
Нужен один и тот же путь на обеих поверхностях, а не две реализации.

Целевой набор этого среза:

- круг, эллипс, квадрат, прямоугольник, треугольник, ромб;
- линия, ломаная, прямая, ломаная и изогнутая стрелка;
- одно- и многоштриховые наброски этих объектов;
- многострочный рукописный текст, прежде всего русский и английский;
- подпись внутри фигуры и самостоятельная надпись на свободном месте;
- смешанный текст и формулы: дроби, степени, корни, суммы, интегралы,
  системы, матрицы и индексная/тензорная запись;
- структурное редактирование формул и локальные результаты в объёме §8.4;
- обычное нативное редактирование, связи стрелок, сохранение и причинная отмена.

Это продуктовый набор, а не заявление о уже установленной поддержке всех
нативных типов. На базе `b08da31` модель содержит ellipse/rectangle/plus/connector:
недостающая нативная геометрия, структурное содержание и математическое ядро
входят в реализацию этого TDD, а не считаются уже существующими.
Распознать треугольник и сохранить его картинкой не считается поддержкой.

**Не входят:** обещание решить любую математическую задачу, доказательство
теорем, произвольная дифференциальная геометрия, исполнение программ из формул,
LLM-коррекция, распознавание фотографий, полный редактор MyScript Diagram
и автоматическая перестройка всего листа. Распознать/показать выражение
и получить для него численный или символический ответ — разные возможности.
Неизвестная операция остаётся редактируемой записью, а не выдуманным результатом.
Не добавляются жестовый язык вычёркиваний/объединений и поисковая база рукописи
только потому, что они доступны у поставщика.

Прежние пожелания GUI-205 о плюсе, волне, каркасном кубе, группах и полном
импорте tldraw не объявляются выполненными этим срезом. Существующие нативные
объекты, включая plus, продолжают открываться и редактироваться. Для новых
распознаваемых классов не сохраняется старый классификатор «на всякий случай»:
отсутствующая возможность остаётся открытой в GUI-205, а набросок — чернилами.

Численные пороги ниже — начальная политика, не результаты измерений точности
или задержки. Качество SDK на реальном почерке Амира ещё не подтверждено.

## 2. Один прямой путь и владельцы

```text
Pencil: существующий владелец контакта листа / доски
    ↓
NotebookPencilIntentSession — удержание и адресная группа источников
    ↓
NotebookAppModel — принятые намерения, история и одна FIFO
    ↓
NotebookInkRecognizer — один нативный MyScript Raw Content Recognizer
    ↓
ограниченный JIIX → нативная геометрия / текст / авторское дерево формулы
    ↓
существующий CollaborationAction / writer
    ↓
NotebookGraphic + одна проекция и обычный нативный painter
```

| Обязанность | Единственный владелец |
| --- | --- |
| Измерения, принятый контакт и текущая физическая поверхность | Существующий ink/input owner |
| Смысл удержания и продолжение управления Pencil | `NotebookPencilIntentSession` |
| Очередь намерений, их отмена и публикация рабочих объектов | `NotebookAppModel` |
| Вызовы SDK и перевод его ответа | `NotebookInkRecognizer` с закрытым адаптером JIIX |
| Авторское содержание, версии, source claims и запись | `NotebookCore` и общий writer |
| Математический разбор, типы, зависимости и вычисление | Один `NotebookMath`, один закреплённый CortexJS Compute Engine |
| Раскладка формул, курсор и выбор узлов | Общий native content layout/painter, не SDK и не WebView |
| Геометрия, bindings, hit test, resize | Существующий нативный граф/геометрия, расширенные для новых типов |
| Видимость чернил и графики, временный → канонический показ | Существующие presentation/scene owners |

SDK — вычислительная зависимость приложения, не второй документ. Его временные
stroke indices, IDs, buffers и JIIX не становятся адресами или форматом Notebook.
Нет пакета `.iink` на страницу, второго графа bindings, SDK UndoManager,
дополнительной камеры, canvas-view или web-редактора.

Не вводятся `RecognitionProvider`, реестр backends, роутер между Apple/MyScript,
флаги выбора движка, shadow recognition или каскад fallback. Приложение имеет
один конкретный сервис MyScript и закрытый адаптер к своим value-типам.
Тестовый double на границе SDK допустим только в тестовой сборке.

Сохранять pure-геометрию для редактирования — **не** сохранять классификатор.
Resize, положение наконечника, hit test и следование связи за узлом нужны уже
после распознавания и не должны повторно обращаться к модели.

После записи математического содержания `NotebookMath` получает его адресный
снимок, вычисляет производный результат и публикует его через существующий
presentation owner. Этот путь не распознаёт ink, не пишет авторский AST и не
создаёт вторую модель документа. Математическое ядро — не запасной recognizer.

## 3. SDK, ресурсы, языки и офлайн

### 3.1. Выбранная интеграция

Используется **native MyScript iink, Raw Content Recognizer**, без `Editor`,
`OffscreenEditor` и UI reference implementation. В отличие от Shape-only API,
который пытается найти фигуру в любом переданном содержимом, Raw Content
даёт классификацию смешанного ввода. Документальная основа — SDK 4.5;
в поставке фиксируются точные бинарник, конфигурации, ресурсы и их hashes.
[Распознаватели](https://developer.myscript.com/doc/interactive-ink/4.5/overview/recognizers/).

На iPad используется одна связка Engine/Recognizer, доступная только сервису.
Core, Mac-помощник, MCP, SQL и рендерер не импортируют SDK. Mac получает обычные
объекты Notebook и не распознаёт доставленное содержание повторно. Наличие
нативного macOS SDK этим решением не предполагается.

Текущий проект остаётся iPadOS/macOS 27+. Таблица квалификации iink 4.5 заканчивается
на iOS 26.5; поддержка Objective-C/Swift и arm64 указана, но совместимость именно
с нашей iPadOS 27 ещё не доказана. Эта граница относится к допуску интеграции,
не является поводом добавлять второй production backend.
[Платформы](https://developer.myscript.com/doc/interactive-ink/4.5/overview/platforms/).

### 3.2. Минимальная конфигурация

Профиль классифицирует `text`, `math`, `shape`, `drawing`; распознаёт
`text`, `math`, `shape`. `drawing` оставляет неподдержанное содержимое рисунком.
Не включаются SDK solver, gestures и глобальное beautification, меняющее соседние
объекты. Вычисление принадлежит только `NotebookMath`, не двум калькуляторам.
Настройки профиля задаются явно, включая отключение нежелательной автоматической
правки геометрии; на default-настройки демонстрационного приложения не полагаемся.

В приложение входят ресурсы layout analysis `raw-content2`, `shape`, `math2`
и выбранных языков, необходимые для этого профиля, а не весь каталог SDK. Не создаётся
собственный загрузчик моделей: нужные пакеты поставляются с приложением.
Отсутствующий обязательный пакет — ошибка комплектации, не повод тихо перейти
на Apple OCR или сеть.

Используются настройки семейства `recognizer.raw-content.*`, не настройки
`raw-content.*` для Editor. В JIIX нужны ranges, bounds и нативная семантика
геометрии, текста и математических spans; копия всех исходных strokes и glyph images не экспортируется.
Точные имена Objective-C/Swift методов берутся из закреплённых headers: пример
Android не копируется в Swift как будто это проверенный iOS API.
[Устройство и ресурсы Recognizer](https://developer.myscript.com/doc/interactive-ink/4.5/android/advanced/recognizers/).

Профиль языка фиксируется в намерении. По умолчанию используется русский
ресурс; английский профиль доступен в настройке письма, без выбора перед каждым
удержанием. Конкретные идентификаторы соответствуют установленным ресурсам.
`recognizer.lang` не трактуется как Apple-массив preferredLanguages; поддержка
нескольких латинских языков не доказывает автоматическое смешение кириллицы
и латиницы. Не выполняются два распознавания с последующим внешним выбором
«лучшего» текста. Необходимый русский пакет включается в поставку.

### 3.3. Офлайн-контракт и активация

После успешной активации runtime текст и фигуры распознаются на устройстве.
Рисование, редактирование, Undo и локальное сохранение не зависят от сети
вообще. У распознавания нет облачного endpoint, API quota на каждый штрих
или обращения к серверу Notebook.

Сетевая активация лицензии — отдельная граница первого запуска/новой установки,
не распознавание. Приложение не обещает работу SDK до неё и не маскирует
временный trial как постоянную автономность. При недоступной активации лист
открывается и принимает чернила; настройка показывает один понятный статус,
а не модальное окно на каждое удержание. Подключение сети не запускает задним
числом неисполненные конверсии.

Сервис различает `notConfigured`, `activationRequired`, `ready`, `unavailable`.
Статус берётся из фактического результата SDK, не сохраняемого нами флага
«однажды всё работало». Не сбрасываем активацию при обычном очищении временных
данных recognizer. Удаление/переустановка приложения не объявляются способом
получить бесплатную новую квоту.

Developer account и сертификат приложения подготавливаются разработчиком.
Не запрашиваем логин MyScript у пользователя при рисовании. Account credentials
не попадают в репозиторий; сертификат встраивается предусмотренным SDK способом
для нужного bundle. В документацию не вставляются его байты.

Условия дают 25 runtime-лицензий для внутреннего использования, оценки и
демонстрации, а не свободного распространения приложения. Активация описана
отдельно в §5.2. Покупка, создание аккаунта и принятие лицензии не выполняются
этим документальным изменением.
[Условия MyScript, §§3–5](https://developer.myscript.com/legal-docs/License-terms-of-use-and-sale.pdf).

## 4. Взаимодействие без ритуала

### 4.1. Общие правила

Pencil пишет, палец редактирует, два пальца управляют камерой. Существующий
владелец контакта не конкурирует с новым UIGestureRecognizer SDK.
Нет обязательного переключателя «текст/фигура/формула». Намерение определяется жестом
и контекстом, а не режимом всей доски.

500 мс удержания и 6 screen pt допустимого движения имеют одного владельца.
Короткая точка остаётся пунктуацией. Рисование не ждёт распознаватель.
Неоднозначный или неподдержанный ответ оставляет исходные чернила.

### 4.2. Фигура

1. Пользователь рисует один или несколько штрихов и задерживается в конце
   последнего. Порог регистрирует намерение и ограниченный снимок; короткая
   индикация сообщает, что команда принята.
2. До ответа остаются чернила. Если Pencil поднят без дальнейшего рисования,
   запрос продолжает выполняться: ждать ответ под прижатым Pencil не нужно.
3. Допустимая геометрия становится **одним** `NotebookWorkingGraphic` с заранее
   выбранным ID. Этот же ID получает запись. Не появляется отдельная фигура
   SDK, которую затем удаляют ради «настоящего» объекта.
4. Если Pencil ещё на поверхности, его последующее движение изменяет уже
   распознанную геометрию. Распознаватель повторно не вызывается. Lift завершает
   манипуляцию и передаёт последнюю геометрию writer, не подтверждает отдельное
   предложение и не возвращает на экран чернила.
5. Если ответ пришёл после lift, та же конверсия сохраняется сразу. Нет второго
   удержания, минимальной выдержки preview или диалога принятия.

При принятии working geometry ink owner фиксирует окончательно измеренный
префикс наброска, использованный снимком. Именно этот префикс сохраняется как
source-action; движения управления размером не добавляются в его samples.
Иначе source digest относился бы к одним точкам, а Undo возвращал бы другие.

До установки распознанной геометрии движение более 6 pt относительно удержания
означает продолжение наброска: прежний snapshot generation становится негодным.
Поздний результат не заменяет новые точки. После следующей естественной паузы
новая версия того же ещё рисуемого контакта может быть распознана; старые
версии не копятся в FIFO и не создают несколько Undo. Это не отмена уже
переданного writer действия и не правило для отдельной точки-команды текста.

После появления геометрии сохраняется поведение текущего resize: удержание
выбирает изменяемые стороны, обе оси доступны, противоположные стороны
не двигаются; смещение вычисляется от первоначальной геометрии, без накопления
ошибки. У стрелки меняется ближайший к удержанию конец, направление и второй
конец сохраняются. Общий binding resolver связывает концы с узлами Notebook.

Отклонённая ладонь, последующий контакт и поздний callback прежней view
не уничтожают принятую геометрию. Системный cancel после принятия рабочего
объекта завершает управление его последним корректным состоянием. Undo —
явная отмена; ошибка источников или записи — реальный отказ с сохранением ink.

### 4.3. Текст и математика

Пользователь пишет, поднимает Pencil и удерживает **отдельную точку** возле
письма. На пороге одно намерение уходит AppModel. Сам командный контакт
не входит в источники, не сохраняется точкой и не занимает отдельный Undo.
После порога lift, дрожание и движение не отзывают команду. Можно сразу
продолжать работу, не дожидаясь распознавания.

Однозначная пустая фигура получает подпись. На свободном месте получается
самостоятельный нативный content-объект. Text и Math spans сохраняются вместе;
для формулы не нужен другой жест. Уже существующая непустая подпись
не переписывается автоматически: открывается обычный редактор.

После преобразования завершённая формула получает результат рядом, без
диалога «вычислить?». Результат не вписывается в авторскую формулу и не занимает
новый Undo. Палец выбирает дробь, индекс или ячейку матрицы; обычный редактор
изменяет выбранный узел. Новый рукописный ввод в открытом math-редакторе идёт
через тот же recognizer и заменяет выбранный узел одной общей командой.
Никакого повторного распознавания всей страницы или отдельного режима доски.

До порога движение за пределы 6 pt оставляет контакт обычным рисованием.
При отсутствии подходящего письма или неоднозначном адресате контакт
не перехватывается. После принятой команды отказ не превращает управляющую
точку задним числом в неожиданную пунктуацию.

## 5. Адресная выборка, а не второй документ

### 5.1. Фигура

Из текущего contact owner берутся измеренные точки и ограниченная группа
предшествующих штрихов того же наброска. Начальные пределы: 16 pen-action,
8192 точек с учётом влияющих eraser, последовательные контакты одной поверхности
и инструмента с промежутком не более 3 секунд. Старые заметки из всей страницы
не добавляются ради получения удобного ответа. Явно выбранная группа чернил,
если она предоставлена существующим инструментом, может использовать тот же
сервис без ограничения возраста, но с теми же ресурсными пределами.

SDK возвращает ranges; преобразуется одна поддержанная фигура, которая
включает текущий контакт. Её участники берутся из ranges, не из всего окна.
Неиспользованные предыдущие штрихи остаются видимыми. Если один source-action
разделён между выбранной фигурой и посторонним содержимым, частичного скрытия
целого action быть не может: автоматическая конверсия такого ответа отклоняется.

Круг среди букв не выбирается только потому, что Shape-only fit оказался
возможен. Классификация text/math/drawing и неоднозначность учитываются до принятия.
Приложение не запускает собственный классификатор поверх ответа SDK.

### 5.2. Подпись и свободное содержание

Для подписи выбирается внутренняя область видимой замкнутой фигуры, не её
контурный hit test и не только AABB. При вложенности — единственная самая
внутренняя фигура. При неоднозначном перекрытии подходит явно выделенная цель;
без неё автоматическая команда не назначает адресата случайно. Чужой материал,
web-редактор или другая физическая поверхность не становятся полем подписи.

Пустая цель означает `.text("")` без происхождения. Очищенный `.content` с `source`
уже владеет источниками и не является пустым местом для нового преобразования.
У линии и стрелки нет внутренней области: их подписи открываются в обычном
редакторе. Существующий текстовый объект тоже редактируется, а не конвертируется
повторно поверх собственных источников.

Внутри цели рассматриваются все подходящие видимые pen, включая давно
сохранённое письмо. Возраст, смена view и очистка кеша не лишают надпись права
на преобразование. Включается целый action, чей оставшийся видимый след
помещается в область с допуском 12 screen pt. Контур, уже присвоенные источники,
predicted samples и пересекающие чужую поверхность actions исключаются.

На свободном месте точка выбирает локальный seed: ближайший видимый
неприсвоенный pen в радиусе 32 screen pt. Из адресного индекса собирается
связная группа соседних bounds, расширенных на 12 screen pt, до пределов
запроса содержания. Начало отсчёта screen → surface фиксируется при команде.
SDK сегментирует эту локальную группу; принимается один Text или Math block,
включая его типизированные spans, однозначно связанный с seed. Полный read-set включает всё окно классификации,
а source claim — только целые исходники этого блока. Соседний рисунок не
подавляется. При неоднозначном блоке ничего не угадывается и не склеивается.

Порог запроса текста/математики: 256 pen-action, 65 536 точек pen + влияющих eraser.
Превышение не обрезает письмо до префикса. Выборка по области фиксируется при
намерении; writer повторяет тот же предикат, чтобы обнаружить новую букву
или ластик. Независимое содержание за пределами read-set не отменяет работу.

`WritingSession`/кеш группы хранит ссылки, bounds и версии, не копию страницы.
После сброса выборка восстанавливается из индекса и принятого локального хвоста.
Подготовка может идти во время удержания; её задержка не требует нового жеста.

## 6. Снимок видимых штрихов и адаптер

### 6.1. Источник истины

В SDK передаются измеренные штрихи Notebook, а не screenshot/PNG/PDF,
не `PKDrawing` и не результат другого OCR. Изменение provider не меняет формат
канонического ink. Каждая команда несёт неизменяемый снимок либо адресный
handle к зафиксированному срезу, request ID и generation.

Существующий finisher уточняет estimated samples. Последовательность SDK
связывается с конкретными измерениями: позднее уточнение выбранной части
не скрывается под прежним digest. Ожидание окончательных измерений не равно
ожиданию всех пальцев или отпускания командной точки.

### 6.2. Видимость и ластик

Активность pen недостаточна: более поздний eraser может удалить часть письма.
Глобального eraser-frontier нет. По bounds и paint order берутся только eraser,
действительно пересекающие выбранные следы; простого пересечения AABB недостаточно.
Неактивный eraser не действует, поздний pen поверх прежнего eraser сохраняется.

Чистая геометрия действующих следов и видимых фрагментов имеет одного владельца
в ink-геометрии Notebook, общего для сцены и снимка. Она выделяется из нынешнего
пути при необходимости, а не копируется в MyScript-адаптер. Адаптер получает
упорядоченные **видимые pen-фрагменты** с ссылкой на исходный action и диапазон
измерений; eraser не подаётся в Recognizer как новый буквенный pen.

Частичное стирание разрывает траекторию: нельзя соединять оставшиеся куски
через удалённый участок. Позиции, время и доступные параметры пера сохраняются
или интерполируются на точных границах фрагмента. Полностью невидимый pen
не передаётся. Сложная маска, которую выбранное представление не может
передать без возвращения стёртого следа, даёт `ink_adapter_unsupported`,
а не молча распознаёт первоначальную букву. Обычное поддержанное стирание
входит в общий путь; требование переписать надпись после любого ластика запрещено.

Выход clipping ограничивается 4096 временными фрагментами и 65 536 точками
для SDK; превышение возвращает предел, не выделяет неограниченный массив.
Исходный предел геометрического/текстового запроса проверяется до clipping.

Фрагменты временные. После ответа SDK каждый range разрешается обратно в
исходные actions. Если все видимые фрагменты action не принадлежат принятому
результату, нельзя подавить action целиком. Для v1 такое разделённое
происхождение отклоняется, а не вводит второй журнал частичных source claims.

Изменение read-set во время распознавания отзывает право на старый ответ.
Undo конверсии показывает актуально стёртые чернила, не снимок до ластика.
`PKDrawing.erasePath` и отдельный PencilKit-слой масок из прежнего TDD удалены
из целевого пути; переносить их ради подключения другого recognizer нельзя.

### 6.3. Координаты и события SDK

```text
screen pt — жесты и допуски
surface pt — сохранённые измерения и нативная геометрия
SDK model mm — только внутри MyScript-адаптера / JIIX
```

Один обратимый transform сохраняется в запросе. Для доски сначала берётся
разность WorldPoint от локального origin; огромные tile-координаты не приводятся
к одному мировому Float. Zoom камеры не масштабирует почерк для модели.
Невырожденная установленная матрица обязательна; нет fallback на identity.

Политика адаптера: 1 surface pt = 25.4/72 model mm; поле 12 surface pt.
Это выбранная логическая единица, не физический DPI панели. Настройка входных
единиц SDK обязана учитывать коэффициент ровно один раз. Bounds, линии и дуги
JIIX переводятся обратно тем же transform; углы — radians. Native point/pixel
DPI не берётся из текущего zoom или screenScale устройства.

Сохраняются порядок контактов, подъёмы Pencil, относительное время и pressure
в диапазоне SDK. Не нормализуем запись в квадрат, не сводим её к 32/96 точкам,
не пропускаем через QuickShape resampling. Недоступный optional sensor получает
документированное постоянное значение, не выдуманный случайный сигнал.

Каждый временный входной stroke имеет индекс и запись в source map:
`SDK index → action UUID + fragment range`. JIIX ranges разрешаются только
через эту карту. Ни SDK block ID, ни текстовая близость не заменяют происхождение.
[JIIX: единицы и ranges](https://developer.myscript.com/doc/interactive-ink/4.5/reference/jiix/).

## 7. Приём ответа SDK

JIIX — недоверенный ограниченный обменный формат, не часть базы Notebook.
Парсер принимает закреплённую версию и профиль Raw Content **Recognizer**;
схема Raw Content Editor не подставляется вместо неё. Размер до 4 MiB,
глубина до 32, до 1024 блоков, finite coordinates, ranges только внутри
поданного снимка, без противоречивого происхождения. Повторение ranges у
родителя и его spans допустимо: claim строится как объединение источников,
не как повторное присвоение. Пересечение с непринятым содержимым по-прежнему
запрещает скрыть общий source-action.

У одного запроса один конечный ответ. Промежуточные incremental callbacks
не создают объектов и Undo. Они могут обновлять служебный статус, но каноническое
содержание принимает только завершённый результат этого request/generation.

- `.shape`: поддержанный вид и полная представимая геометрия, со всеми
  принадлежащими ему источниками. SDK `rejected`, text/math/drawing вместо фигуры
  или неоднозначный выбор не превращаются в собственный геометрический guess.
- `.content`: выбранный Text или Math block, порядок строк и типизированных
  spans, источники. Text span становится текстом; Math span проходит единый
  математический разбор (§8.3). Для подписи нужны все выбранные строки.
- В Raw Content Recognizer математическое содержание приходит как LaTeX,
  в том числе внутри Math spans; это не обещание готового семантического AST.
  [Схема результата Recognizer](https://developer.myscript.com/doc/interactive-ink/4.5/reference/jiix/).
  Используются spans/ranges, не удаление `$` регулярным выражением из общей
  строки. Разбор не вычисляет и не упрощает авторское выражение.
- Decoration/неизвестный вид и остаток drawing не становятся готовым текстом.
  Неразбираемая или непредставимая часть не отбрасывается: вся выбранная
  конверсия остаётся ink. Известная запись с неизвестным значением, напротив,
  допустима: символическое `x` не является ошибкой распознавания.

Нормализация text runs ограничена NFC и CRLF/CR → LF; внешние пробелы
убираются только на внешней границе всего содержания, не между text/math spans.
Внутренние переносы, пробелы, регистр и символы сохраняются. Пустое содержание,
control-символы кроме LF и текстовая часть длиннее 4096 UTF-16 не принимаются;
текст не обрезается. Чистая формула без text runs допустима. LaTeX/AST имеют
собственные пределы (§14), не проходят через правила нормализации prose. Альтернативы SDK не объединяются в придуманную строку.
Исправление — обычный редактор или Undo, не LLM и не второй recognizer.

Нет фиктивного общего confidence «95%»: числовая уверенность используется
только если она определена конкретным API для этого результата. Наличие
подходящего kind само по себе не означает безошибочное понимание намерения.
Геометрические проверки адаптера проверяют корректность и представимость
ответа, но не повторно классифицируют исходные штрихи.

### 7.1. Отображение в нативную геометрию

| Результат | Содержание Notebook |
| --- | --- |
| circle / ellipse | Нативный эллипс с сохранённой геометрией и ориентацией |
| square / rectangle | Нативный прямоугольник, без потери поворота |
| triangle / rhombus | Нативный замкнутый контур с вершинами |
| line / polyline | Нативный соединитель с соответствующим маршрутом |
| arrow / polyline arrow / curved arrow | Тот же соединитель с маршрутом и наконечниками |
| Text / Math, включая смешанные spans | Одно структурное `graphic.label` существующей фигуры или нового content-элемента |

Расширяется **существующая** модель `NotebookGraphic` и её общий geometry module:
представление поворота, замкнутых контуров, ломаных и дуг должно одинаково
пониматься рендером, hit test, bounds, ручками, bindings, экспортом и Mac.
Не заводится параллельный `MyScriptShape` в сцене. Нельзя объявить произвольную
дугу поддержанной, сведя её к нынешнему одному bend с изменением формы.

Преобразование примитивов SDK в нативный маршрут детерминировано; вся его
геометрия становится редактируемой. Непредставимый маршрут возвращает
`unsupported_geometry` до скрытия ink. Для целевого набора таблицы это означает
незавершённую реализацию соответствующей нативной формы, не автоматическое
сокращение согласованного набора.

Bindings определяет `NotebookGraphicGraph` по реальным существующим узлам.
Диаграммные связи из документации Editor не считаются автоматически доступными
в результате Recognizer. Геометрия SDK не получает права двигать соседние
узлы или создавать скрытый layout-граф.

## 8. Нативное содержание и происхождение

### 8.1. Одна модель содержания

Текст и математика принадлежат `graphic.label`. Нет конкурирующих `ocrText`,
`formulaLatex`, SDK document и MathJSON рядом с авторским содержанием.

```swift
enum NotebookGraphicLabel: Equatable, Sendable {
    case text(String)
    case content(GraphicContent)
}

struct GraphicContent: Equatable, Sendable {
    var runs: [ContentRun]       // упорядоченные text / math / lineBreak
    let source: InkLabelSource? // только дополнительная подпись/правка ink
}

struct InkLabelSource: Equatable, Sendable {
    let conversionID: UUID
    let strokeIDs: [UUID]
}
```

`ContentRun` имеет стабильный node ID и ровно один payload: текст, корень
`MathNode` или перенос строки. Каждый MathNode также имеет стабильный ID.
`.text` остаётся существующей JSON-строкой для простого текста без происхождения;
`.content` кодируется `{kind: "content", runs, source?}`. Это один тип label,
не отдельный документ для каждого вида содержимого. Ранее предложенные, но
не реализованные `case ink(InkLabel)` и kind `ink` заменены, а не сохраняются
как третий decoder/compatibility-путь. Реальные прежние строки остаются валидны.

Весь label — один атомарный причинный регистр. Узлы, текст и provenance не
получают независимых LWW-версий. Существующие causal heads хранят целые
альтернативы; итоговый показ не смешивает формулу одной версии с источниками
другой. ID узла служит адресом редактирования, но не отменяет guard целого label.

`plainTextValue` — только производное чтение для поиска/accessibility/plain
clipboard. Редактор и renderer обходят runs/AST, а не эту строку. Обычная правка
или очистка сохраняет source; она не запускает recognition и не проявляет ink.

### 8.2. Три назначения, не три системы

- **Новая фигура:** `convertInkToElement`, native graphic, источники в
  `graphic.sourceInkIDs`; label первоначально `.text("")`.
- **Подпись существующей фигуры:** `convertInkToLabel`, `.content` с source
  в прежнем label; источники контура в `graphic.sourceInkIDs` не меняются.
- **Свободное содержание:** тот же `convertInkToElement`, native content graphic
  без контура. Label содержит текст/AST; исходники всего объекта находятся
  только в `graphic.sourceInkIDs`, не дублируются в `label.source`.

Нативный content использует прежние frame, стиль, выбор, причинные поля и Undo.
Source claims ссылаются на исходные actions, не SDK fragments. Измерения
не копируются в graphic и не удаляются. Для открытия готового результата
не требуются JIIX, SDK session или исходная LaTeX-строка.

### 8.3. Авторское дерево формулы

`MathNode` — версионируемое ограниченное дерево значений Notebook, не указатель
на живой объект CAS. Число хранится лексемой, не округлённым Double. Узлы:

| Семейство | Сохраняемая структура |
| --- | --- |
| Число / символ / оператор | Лексема или известный token; регистр и алфавит различаются |
| Последовательность / группа / функция | Упорядоченные дети, скобки, аргументы; без перестановки множителей |
| Дробь / корень | Числитель, знаменатель; подкоренное выражение и степень корня |
| Индексы / степень | Основание, упорядоченные верхние/нижние слоты и их синтаксическая роль |
| Сумма / произведение / интеграл | Тело, пределы, связанная переменная и дифференциал, если заданы |
| Матрица / система / cases | Размерность, прямоугольная сетка ячеек либо строки условий, разделители |
| Отношение / определение | Левая и правая стороны; `=` не тождественно `:=` |
| Пустой слот | Явный `hole` незаконченной правки, не число 0 |

Парсер LaTeX — один, внутри `NotebookMath`: выбранный CortexJS с закрытым
адаптером к этой грамматике. Для авторского входа используется raw/noncanonical
режим закреплённой версии, не упрощающий `2/4` в `1/2`. Он сам по себе не
гарантирует сохранение всей типографики: словарь/адаптер обязан сохранить
поддержанные группы, слоты и порядок; потеря представимой структуры — отказ
конверсии, не молчаливая нормализация. Нет второго regexp-парсера или попытки
выдать неизвестную TeX-команду за значение. Актуальная документация описывает
`form: 'raw'`; сигнатура закрепляется вместе с версией, а не копируется из
старых примеров `canonical: false`.
[Авторская и каноническая формы CortexJS](https://mathlive.io/compute-engine/guides/canonical-form/).

Авторское дерево и вычислительное представление имеют разные задачи:

```text
LaTeX Math span → один parse/adapt → MathNode → общий writer
                                         ↓
                         resolve/types → MathJSON → CAS → derived result
```

MathJSON, разрешённые ссылки и нормализованные выражения — производные,
пересоздаваемые данные. CAS не записывает свой канонический ответ поверх AST.
Для `2/4` автор видит именно `2/4`, рядом может появиться `1/2`.

Один ограниченный сериализатор AST даёт LaTeX и Presentation MathML для
clipboard/export. Они не становятся двумя редактируемыми источниками истины.
Вставка LaTeX использует тот же parser; импорт произвольного MathML не входит
в этот срез. Локальные TeX macros, файлы, URL, `\input` и выполнение команд
не разрешены. Распознавание матричных/индексных конструкций ещё не доказывает
верное понимание смысла каждого индекса.

### 8.4. Единственное вычислительное ядро и его область

**Выбран CortexJS Compute Engine**, закреплённый JS bundle с лицензиями
зависимостей. Он владеет символьной/численной арифметикой; не подключаются
SymPy, mathjs, Giac, облачный solver и LLM-калькулятор параллельно. У MyScript
solver выключен. Нативный `NotebookMath` отвечает за документные типы, область
имён, адаптацию и бюджеты, а не пишет второй общий CAS.
[CortexJS](https://mathlive.io/compute-engine/),
[лицензия](https://github.com/cortex-js/compute-engine/blob/main/LICENSE).

Для исполнения переиспользуется уже имеющаяся зависимость CQuickJS с доверенным
math-only bootstrap. Существующий одноразовый `NotebookQuickJSEngine` не
объявляется готовым многоразовым математическим worker: его lifecycle нужно
обобщить у текущего владельца либо использовать общий нижний CQuickJS bridge.
Не копируются интерпретатор и watchdog. На обеих платформах одна закреплённая
версия bundle; нет Node-процесса или браузера на каждую формулу. Совместимость
этого bundle с QuickJS и реальная стоимость на iPad ещё не подтверждены.
Отсутствие подтверждения — незавершённость реализации, не право добавить fallback.

Целевые операции первого математического среза:

- точные целые/рациональные числа, арифметика, степени, корни, известные функции;
- подстановка определений и упрощение в пределах поддержанных правил CAS;
- матрицы/векторы: сложение, скалярное и матричное умножение, транспонирование,
  определитель, обратная матрица и решение конечной линейной системы;
- конечные плотные тензоры: доступ к компонентам, перестановка осей,
  поэлементные операции, внешнее произведение и явно определённая свёртка;
- суммы/производные/интегралы: сохранение и редактирование обязательно;
  вычисление — только для операций, реально поддержанных закреплённым ядром.
  Невычисленный интеграл остаётся интегралом, не нулём и не ошибкой конверсии.

Документация CortexJS описывает матрицы и многомерные массивы; это не обещание
готового исчисления произвольных индексных тензоров. Семантический lowering
объявленных индексов принадлежит `NotebookMath`: он превращает конечную свёртку
в ограниченное выражение сумм/произведений для того же CAS. Недостающая целевая
операция остаётся работой внутри этого пути, не переключением вычислителей.
[Линейная алгебра и массивы](https://mathlive.io/compute-engine/reference/linear-algebra/).

**Правила значений.** Целые и дроби вычисляются точно; десятичная авторская
лексема не проходит через binary Double. Приближённый ответ явно помечен `≈`,
с точностью 15 значащих цифр по начальной политике. Численные методы и округление
не выдаются за доказанную точность всех цифр. `=` означает отношение, не запись
в память; `x := …` — явное определение в математическом содержании. Неизвестный
символ остаётся символом. Деление на ноль, несовместимые размеры, неоднозначный
тип, незаполненный слот и неподдержанная операция не становятся `0`/NaN на доске.
Сохраняется авторская формула; короткая диагностика привязана к её узлу.

**Индексы.** По виду `A^i` нельзя всегда решить, степень это или индекс.
Тип массива выводится из его значения. Вектор без другой аннотации — столбец;
матрица — прямоугольная сетка строк, dense tensor — прямоугольные вложенные
массивы. `A v` — матричное произведение, не поэлементное умножение. Индексная
сигнатура задаётся определением `A^i_j := [[1,2],[3,4]]`, `v^j := [5,6]`:
различные символы слева обозначают слоты, их порядок совпадает с осями массива
справа, верх/низ сохраняются, диапазон каждого слота — 1…размер оси. Это
объявление целого тензора, не присваивание одной компоненте; подмножества
компонент меняются структурным редактором. Ранг/размеры проверяются при
разрешении определения. Для иного диапазона нужна явная конечная сумма;
отдельного модального мастера тензоров не добавляется. Неразрешённая
нотация хранится и показывается без выдуманного численного результата. Для
тензорной сигнатуры повтор одного верхнего и одного нижнего индекса в
произведении означает сумму по одному согласованному диапазону; свободные
индексы задают форму результата. Три появления одного индекса, конфликт
размерностей и недопустимое поднятие/опускание индекса — диагностика.
Метрика не предполагается молча. Явная конечная сумма доступна без соглашения
Эйнштейна. Порядок матричных/тензорных множителей не коммутируется как скаляры.

### 8.5. Контекст, результат и обновление

Область определений — текущая физическая страница либо доска; подпись фигуры
не создаёт скрытого отдельного пространства имён. Другой owner доступен только
через явную документную ссылку, не по близости объектов. Индекс определений
строится из авторского содержания тем же addressed путём; добавление или
удаление определения инвалидирует и прежние unresolved-ссылки. Две активные
дефиниции одного имени — конфликт, а не выбор последней по координате/времени.
Цикл зависимостей отмечается, а не запускает бесконечный пересчёт. Связанные
переменные суммы/интеграла локальны и не подменяются одноимённым глобальным именем.

Для каждой формулы снимок содержит её node ID, causal version label,
транзитивные версии определений, профиль вычисления (точность, радианы для тригонометрии) и hash bundle/семантики.
Этим же ключом ограничен кеш. Устаревший ответ не публикуется даже если прежняя
строка вернулась после `A → B → A`. Простое перемещение фигуры/камеры не
пересчитывает математику. Изменение одной дефиниции затрагивает только её
зависимых, не весь лист и не recognition.

Автовычисление срабатывает после авторской записи и коалесцирует быстрые правки.
Оно не задерживает сохранение/рисование. Результат — `exact`, `approximate`,
`symbolic`, `incomplete`, `unsupported`, `invalid` или `budgetExceeded` плюс
ограниченное дерево/диагностика. Во время пересчёта прежний ответ не выглядит
актуальным. Самопроизвольные вычисления не создают Undo, source claims или
replication actions. Для сохранения результата как самостоятельной авторской
записи есть обычное явное действие вставки, не автоматическая мутация.

Завершённое определённое арифметическое выражение получает ответ сразу после
вычисления; неизвестные переменные не требуют модального ввода значений.
`Solve`/`Simplify` по выбранному выражению — необязательные действия того же
ядра, а не другая трактовка каждого написанного знака `=`. Условный результат
сохраняет предпосылки: деление на символ или сокращение не скрывают исключения.

## 9. Точные границы намерения и снимка

```swift
enum InkConversionDestination: Sendable {
    case newShape(SurfaceToken, elementID: String)
    case newContent(SurfaceToken, elementID: String)
    case label(GraphicTargetToken)
    case mathNode(GraphicTargetToken, nodeID: UUID) // открытый редактор
}

struct InkConversionIntent: Sendable {
    let id: UUID
    let contactID: UUID
    let generation: UUID
    let destination: InkConversionDestination
    let selection: InkSelectionHandle
    let languageProfile: String
}

struct InkStrokeProof: Codable, Equatable, Sendable {
    let id: UUID
    let measurementDigest: String
    let stateStamp: VersionStamp
}

struct InkSourceToken: Codable, Equatable, Sendable {
    let surface: SurfaceID
    let strokes: [InkStrokeProof]
    let erasers: [InkStrokeProof]
}
```

Типы — контракт, а не уже существующие Swift declarations. Запросы/результаты
содержат только Sendable values. SDK objects никогда не пересекают границу
worker, не сериализуются в command и не получают `@unchecked Sendable` ради UI.

`SurfaceToken` фиксирует физического владельца и идентичность его создания.
ID нового элемента резервируется один раз при намерении; результат до/после
lift использует его же. Для геометрии сохраняется нынешняя связь стабильного
ID с принятым contact/action. Командная точка текста не становится source ID.

`GraphicTargetToken` фиксирует identity и точные версии exists/frame,
graphic.shape/style/label/representation/visible/sourceInkIDs, worldOrigin
и дополнительной геометрии расширенной модели. Core сам определяет обязательный
набор ключей; caller не может сократить guard. Изменение соседнего элемента
не входит в этот read-set. `A → B → A` не восстанавливает прежнюю версию.

`InkSelectionHandle` фиксирует surface, область/seed, read cursor, предикат
выбора, source proofs и принятый локальный хвост. В очереди он не содержит
полную копию points. `InkSourceToken` доказывает **всё окно, влиявшее на ответ**;
отдельный `claimedStrokeIDs` — только источники выбранного результата. Writer
проверяет оба набора и их соответствие, а не только удобные распознанные буквы.

### 9.1. Измерения и hash

Digest вычисляется один раз вне пути Pencil-сэмплов общим Core-кодеком, а writer
проверяет его по адресно прочитанным измерениям. Hash caller сам по себе
не доказательство. Состояние активности и paint order проверяются отдельно.

Канонический envelope v1: UInt8 версии; UInt8 tool (`pen=0`, `eraser=1`);
три RGB Double; UInt32 числа spans; каждый span — UInt8 surface kind
(`page=0`, `board=1`, `cover=2`), 16 UUID-байт, UInt32 числа samples;
каждый sample — point.x/y Double, UInt8 наличия worldPoint, при наличии
его tileX/tileY Int64 и offsetX/offsetY Double; затем timeOffset, width,
opacity, force, azimuth, altitude как Double. Числа little-endian, `-0 → +0`,
NaN/Infinity недопустимы. Страница — один span. UUID action связывается
отдельным proof.id. SHA-256 не включает publication cursor, SDK timestamps,
случайный ID сессии, `isActive` или stateStamp.

Paint order совпадает с текущим renderer/journal: page `(sequence, id)`,
spatial `(stamp, id)`. Его не заменяет лексикографическая сортировка чисел.
Для v1 spatial action с несколькими физическими spans не конвертируется
автоматически. Сшивать владельцев ради буквы или стрелки запрещено.

## 10. Общая транзакция и принятие

MyScript не пишет документ. Существующий `convertInkToElement` получает общий
узкий guard и новые поддержанные нативные виды. Для подписи добавляется
`convertInkToLabel`; оба используют одни source validators, action receipts,
индексы и авторство. Нового «быстрого writer для OCR» нет.

Вход label: target, element ID, назначение initialLabel/mathNode, runs/AST,
conversionID, новые claimedStrokeIDs и guard. Для mathNode передаётся только
заменяемое поддерево и ID; целое содержание/объединение sources формирует Core.
Вход нового объекта: те же guard/source данные и ограниченный нативный payload.
Для нового content payload не разрешает одновременно label.source и
sourceInkIDs на те же буквы. Авторство назначает доверенный native вход;
`nb.action` остаётся агентским, payload не содержит переключателя `human`.

### 10.1. Порядок writer

1. Найти receipt по `action.id`: тот же payload возвращает прежний результат,
   другой payload даёт `action_id_conflict`.
2. Применить общие scope/permission и idle-input правила.
3. Адресно прочитать цель/поверхность, выбранные actions, действующие eraser
   и полный ограниченный компонент source-конкурентов.
4. Сверить identity, обязательные causal versions, digest, paint order,
   видимость и первоначальный предикат выборки. Учесть появившиеся eraser/буквы.
5. Проверить нативный payload и полноту source claims, отсутствие уже
   присвоенных новых источников. Initial label требует `.text("")` у прежней
   видимой цели; mathNode replacement — тот же узел и целый label прежней
   версии. Старые claims сохраняются точно, новые принадлежат этой конверсии.
6. Создать один объект либо заменить один целый label. Не менять ink.isActive,
   не удалять исходники и не пересоздавать уже показанную working identity.
7. Через прежние restamp/recordFieldChanges/validate записать изменения,
   receipt, source/binding индексы и addressed delta в одной транзакции.
8. Вернуть receipt и durable cursor.

Несколько операций одного action резервируют sources транзакционно; один
штрих нельзя присвоить дважды до появления итоговых версий. При отказе
откатывается всё преобразование, а не остаётся «сначала спрятали, потом не записали».

Sources и eraser-зависимости должны быть сохранены раньше конверсии той же
очередью. Ошибка их сохранения запрещает зависимый commit. Распознавание,
внешний SDK и ожидание модели не выполняются внутри SQL-транзакции.

### 10.2. Ожидания и input gate

Общий `CollaborationExpectation` сохраняется. Native вход получает текущую
owner revision в той же транзакции, где впервые исполняет action с первоначальным
узким guard. Между чтением envelope revision и записью нет `await`.
Это не retry со свежей версией после CAS-отказа. После `revision_conflict`
старый guard не обновляется автоматически. Общий клиент отвечает за собственный
owner expectation как раньше.

Точка-команда после срабатывания больше не меняет ink и не удерживает ink gate.
Удерживаемая распознанная фигура допускает геометрическую манипуляцию до end;
её последняя версия передаётся writer после завершения этой манипуляции.
Независимый действительно рисующий контакт защищён обычным gate. Ладонь
и занятость распознавателя не считаются продолжающимся рисованием.

Read projection новой операции адресная, без `fullPageIDs` fallback. Пределы
чтения применяются ко всему action, не только к одному удобному элементу.

## 11. Source claims, видимость и причинная отмена

### 11.1. Одна проекция

`graphic_sources` остаётся производным индексом с видом заявки `object` либо
`label`: owner, address, elementID, claim kind, strokeID. Никакой второй базы
OCR нет. Строки обновляются в той же транзакции и восстанавливаются из содержания.
Индекс включает скрытые и проигравшие представления, чтобы не терять конкурентов.
Невыбранные causal heads label сохраняют ссылки через общий retention/delivery,
но не становятся вторыми активными заявками показа.

Прежний `NotebookGraphicPresentation` расширяется, не заменяется параллельным
resolver. Он разрешает сначала целые object claims (`sourceInkIDs`), затем
label claims у допущенных фигур. Объекты без источников, созданные обычным
редактором, тоже могут иметь подпись. Самостоятельный content участвует как объект,
а не одновременно в обеих стадиях.

Используется прежний устойчивый приоритет авторства/stamp/ID. Заявка выигрывает
целиком либо не выигрывает; частичный текст и половина стрелки не показываются.
Контур нельзя вытеснить его же подписью. Скрытый победитель удерживает источники,
чтобы удаление объекта не проявляло прежний набросок. При явном возвращении
объекта в ink действуют правила отмены и зависимостей, не произвольный patch.

Компонент читается по `(owner, strokeID)`, включая конкурентов вне viewport:
пакеты по 128 IDs, максимум 4096 адресов и 65 536 рёбер. Усечённый набор
не объявляется полным решением. Изменение label, source, версии или видимости
инвалидирует прежних и новых соседей индекса адресно.

### 11.2. Undo и Redo

Маркер Undo занимает место в истории при принятии намерения, не при случайном
возврате модели. Новое письмо остаётся более поздним действием. Отказ удаляет
пустой маркер, не создавая фиктивной содержательной квитанции.

До регистрации записи Undo отзывает право результата. После регистрации
он следует за receipt и выполняет общий причинный inverse; нельзя показать
«отменено», оставив неопределённый commit без разрешения исхода.

- Новая фигура/свободное содержание отменяются прежним переходом представления
  в ink, сохраняя устойчивую identity, порядок и исходные измерения.
- Конверсия подписи возвращает прежний целый label; сама фигура остаётся.
- Отмена не оживляет independently erased/tombstoned измерения.
- Поздняя правка label/frame/геометрии, движение и зависимая связь защищаются
  существующими causal ownership/restorations. `move → Undo move → Undo label`
  допустимо; совпавшие координаты после независимой правки не дают такого права.

Redo повторяет сохранённый нативный результат, **не SDK**. Новый action ID
ссылается на исходный receipt через `redoOf`; Core проверяет выполненную отмену,
identity, текущую принадлежность восстановленных полей и те же sources,
затем исполняет ту же операцию с новым read-set. Это явное новое действие,
не автоматическое исправление прежнего CAS. Payload результата берётся из receipt,
а не от произвольного caller.

При Undo распознанной правки math-узла возвращается прежнее поддерево и
прежний полный source set; проявляются только новые исходники этой правки,
если их не скрывают другие действующие правила. Старые source claims не теряются.

`PencilUndoHistory` получает это расширение один раз для конверсий. Не появляется
SDK UndoManager. Сессионные redo-slots ограничены 32 на owner; новый авторский
ввод очищает ветвь. После перезапуска восстановление UI redo-стека не обещается;
содержание, происхождение и причинный Undo долговечны.

### 11.3. Обычное редактирование

Общий `updateElement` заменяет runs/AST с guard целого label, сохраняя source.
Текстовая правка изменяет выбранный text run, математическая — выбранный node;
`replacingText` не сериализует и не затирает соседнюю формулу. Создать/расширить
source можно только конверсией. Для распознаваемой правки выбранного math-узла
тот же `convertInkToLabel` получает node ID и guard целого label, заменяет только
его поддерево и сохраняет объединение прежних и новых source claims. Источники
из `graphic.sourceInkIDs` повторно не включаются. Initial label conversion
по-прежнему требует пустую цель; node replacement разрешён только в явно
открытом редакторе с выбранным узлом. Никакого второго writer или слепого
перезаписывания непустой подписи. Очистка не восстанавливает старое письмо.

Новые узлы получают ID при принятии команды; неизменённые сохраняют ID.
Редактор передаёт структурную замену с точным guard, а не произвольный путь
в JSON. При конфликте draft остаётся доступным, чужая версия не затирается.
Изменение ячейки, числителя или индекса — одно обычное действие Undo.

Обычный UITextInput/клавиатура, включая системный Scribble **в уже открытом
редакторе**, не являются вторым recognizer наших чернил. Вне редактора Scribble
не отбирает Pencil у холста. Набор виртуальных текстовых полей поверх всех фигур
не создаётся. Локальный Undo незавершённого editor draft и Undo документа
не исполняют одну команду дважды.

## 12. Формат, доставка и существующие данные

SDK не входит в wire format. Передаются native geometry/runs/AST, версии
и source references. Получатель, включая Mac, не требует SDK, активации или
повторного распознавания. Обновление SDK/языкового пакета не переписывает
принятое пользователем содержание и геометрию.

`NotebookGraphicLabel` имеет один строгий decoder: JSON-строка либо объект
kind `content` с ограниченными runs и optional source. При наличии source его
UUID уникальны и список непуст. Неизвестные kinds/поля, некорректные UUID,
повтор node IDs, циклы, неверные arity/размеры сетки и лимиты отвергаются.
MathNode и набор операций версионируются в общей схеме Notebook, а не числом
версии CAS. Результат расчёта и MathJSON не входят в авторский wire payload.
Хранимый текст сохраняет прежний предел 100 000 UTF-16 для ручного редактора;
4096 — предел новой конверсии, не доставки ранее написанного содержания.

У sourceInkIDs нового свободного содержания предел 256; у геометрии — 16.
Расширение этих правил, нативных типов и атомарного label отражается во всех
валидаторах, readers, экспортёрах, MCP и обоих приложениях. Вложенный JSON label
не дробится на независимые causal leaves.

На просмотренной базе wire = 17. При реализации резервируется следующая
свободная версия admission/wire от реального HEAD, не повторяется занятый номер.
Обновлённую схему/геометрию понимает согласованная Mac/iPad-пара; старый writer
не допускается к неподдерживаемому содержимому.

Новые source/ink индексы строятся потоково и атомарно с admission marker.
Старый индекс удаляется в той же миграции, без дублирующего read path.
Сбой транзакции оставляет предыдущую завершённую БД. Не переписываются
исторические авторские actions, blobs, receipts, ID, ключи или контейнеры.
Строковые labels и уже сохранённые ellipse/rectangle/plus/connector — обычное
содержание модели, не причина удерживать QuickShape runtime.

Ссылки source входят в существующее замыкание доставки/удержания. Полученный
раньше источников объект имеет pending-зависимость, а не пустой source set;
после адресного получения проекция пересчитывается. Compaction не удаляет
нужные скрытые источники/причинную историю.

Дубликат и вставка на другую поверхность получают новые ID, готовое native
содержание и текст без source claims оригинала. Move внутри owner сохраняет
identity/provenance; cross-owner move использует общие copy/remove-семантики.
Экспорт в изображение не объявляется редактируемым экспортом. Поиск, VoiceOver,
clipboard и MCP читают общий text accessor; строки не исполняются как HTML/JS.

## 13. Последовательное исполнение и жизненные циклы

AppModel владеет одной FIFO всех принятых конверсий. `NotebookInkRecognizer`
владеет одним Engine/Recognizer, временным снимком, source map и декодированием
ответа. Он не выбирает адресата в документе и не вызывает writer.

У SDK один последовательный execution context вне MainActor. Блокирующий native
`waitForIdle` не выполняется на главном потоке или произвольном cooperative Swift
executor: bridge использует выделенную serial queue и возвращает immutable
values. Native callbacks возвращаются в ту же последовательность. Нельзя
одновременно clear/configure/feed/read из разных Task или страниц.

```text
admit(intent):
    дедупликация того же read-set / текущего generation
    резерв ограниченного слота, sources и маркера Undo
    enqueue; запустить один drain

drain:
    взять самый ранний актуальный intent
    подготовить ограниченный снимок и видимые фрагменты
    очистить прежний вход SDK; применить профиль этого запроса
    подать ordered PEN events с source map
    дождаться конца; получить и разобрать один JIIX
    сверить request/generation и исходный guard
    для Math spans передать parse/adapt в NotebookMath с тем же intent
    после полного native candidate вновь сверить guard; передать AppModel
    либо завершить отказом, не выдавая половину text/math содержания
    освободить вход/ответ; взять следующий intent
```

Очистка входа не уничтожает активацию и не создаёт новый Engine на каждый штрих.
Смена профиля сериализована. SDK внутренне может использовать собственные потоки;
«один worker» не означает обещание фиксированного числа внутренних threads.
AppModel не ждёт painter handoff предыдущей записи перед обслуживанием
следующего запроса. Никаких очередей внутри очередей страниц или пула backends.

Разделены три времени жизни:

1. контакт и возможное удерживаемое изменение геометрии;
2. принятая команда от подготовки до receipt;
3. рабочее представление до установки канонического cursor.

Lift не уничтожает второе/третье. Callback адресуется intent ID, не текущей view.
Навигация и новый независимый Pencil не отзывают принятую команду. Внешняя правка
её read-set или Undo отзывают; новые sources/версии не подставляются автоматически.

### 13.1. Математический worker

У `NotebookMath` один serial worker вне MainActor. Принятый parse/adapt для
конверсии и явное действие редактора приоритетнее фонового пересчёта. В очереди
результатов хранится только последняя версия конкретной формулы. Parser job
сохраняет исходный intent/guard и место Undo; его ожидание не требует нового
жеста. Ink FIFO передаёт ограниченный ответ математическому worker, не держит
блокирующий SDK-вызов во время CAS. Общий лимит принятых намерений сохраняется.

Рендер не ждёт CAS. Расчёт старой версии отзывается; приоритетное редактирование
может прервать производный расчёт и позже заново запросить актуальную версию.
Deadline и memory/stack limits обеспечиваются существующим механизмом прерывания
QuickJS, не одним `Task.cancel`. Нет бесконечной очереди всех формул: видимый
контент, выбранный узел и их зависимости запрашиваются адресно; остальные
вычисляются при обращении. Ограниченные кеши вытесняют только производные данные.

VM может оставаться тёплой, но окружение символов каждого запроса изолировано
и заполняется только его снимком. Авторские определения передаются как данные,
не через выполнение JS. Нет доступных документу host callbacks, файлов,
сети, timers, code generation или произвольных MathJSON управляющих операций.
Allowlist операций и пределы действуют до вызова CAS, после разбора и на ответе.
Пакет допускается только с возможностью прекратить фактически исполняющуюся
работу; свободный worker не имитируется запуском второй VM рядом с зависшей.

Результат проходит проверку node/контекстных версий, ограничений и типов перед
публикацией. Ошибка математики не блокирует обычный текст, фигуры, Undo или Save.
Отказ математического parser до commit оставляет исходную формулу ink; отказ
вычисления после commit оставляет уже созданное редактируемое дерево.

Порогами ink владеет один `InkConversionPolicy`, не независимые копии в странице,
доске и адаптере. Математические лимиты задаёт один `MathPolicy`, включая
стоимость раскрытия суммы до выделения памяти. Core всё равно валидирует недоверенный command по тем же
ограничениям. Декодер проверяет длины до выделения больших массивов.

Очередь держит handles/proofs, не восемь полных snapshots. Занятость worker
или writer — нормальное ожидание, не просьба повторить жест. Новый запрос
не вытесняет принятый. Только исчерпание общего ограниченного ресурса отказывает
в приёме следующей команды с сохранением её ink.

До удержания — измерения, drawing, bounds и простая контактная геометрия.
Нет inference, JIIX, SDK callbacks, SQLite или полного обхода доски на каждом
Pencil sample. Нет фонового распознавания всего документа «для уверенности».
Lazy initialization начинается не на MainActor; пригодные ресурсы можно
подготовить при входе в приложение, не задерживая первое появление чернил.

При timeout право позднего результата отзывается. Если native вызов ещё
исполняется, worker не считается свободным; второй Engine не создаётся.
Ожидающие команды получают один согласованный статус недоступности и сохраняют
чернила. Очистка/возобновление возможны после фактического конца вызова.
Отмена Task не объявляется гарантированным прекращением SDK inference.

Save сохраняет ink и уже зарегистрированные команды, а не ждёт бесконечно SDK.
В background работа может закончиться в доступном ОС времени; фоновой службы
не создаётся. Завершение процесса до commit оставляет чернила, после commit —
native объект. Очередь распознавания не объявляется долговечным содержимым.

Копирование/hash имеют O(P), source links O(S), обход конкурентов O(C+E) плюс
сортировку. Стоимость SDK и clipping зависит от содержания и измеряется отдельно.
Нет обещания постоянных времени/памяти SDK или выигрыша над другим recognizer.

## 15. Показ, раскладка и непрерывность объекта

Остаются Metal-чернила, камера, `NotebookGraphicView`, нативные векторные партии
и общий painter order. На фигуру/подпись не создаётся UIView, WebView или слой
SDK. Свободное содержание рисуется тем же путём без контура; UITextInput появляется
только у активного редактора.

Рабочий объект и его маска sources ставятся одной публикацией. До неё видны
чернила, после — native содержание. На lift этот объект **не удаляется**.
Сохранение подтверждает его ID и финальную геометрию, а не создаёт копию.
Движение Pencil после распознавания не становится лишним ink-хвостом.

`NotebookWorkingGraphic` расширяется для runs/AST и подписи; коллекцией владеет
AppModel по action ID. Старый глобальный занятый preview-slot не блокирует
следующую независимую команду. Draft живёт до установки authoritative projection
не старше durable cursor вместе с соответствующей маской sources. Receipt
сам по себе не доказывает установленный кадр.

При уходе потребителя успешная запись освобождает временный draft: невидимый
лист не обязан произвести кадр ради освобождения FIFO. При возвращении читается
каноническое содержание. Более новая правка или tombstone завершают handoff
актуальным состоянием, не оставляют overlay навсегда. Отказ записи возвращает
актуальный ink и локальное объяснение; источник не был удалён.

У label один layout helper для working/canonical/batch/экспорта. Базовый inset
`max(8 surface pt, strokeWidth/2 + 4)`, system regular 24 surface pt, цвет stroke.
Для rectangle — внутренний frame, для ellipse — вписанный прямоугольник с осями
`(width−2·inset)/√2` и `(height−2·inset)/√2`; новые контуры дают внутреннюю область
через тот же geometry module. Ориентация и transforms совпадают с графикой.

Нехватка места в фигуре не отменяет конверсию и не уменьшает шрифт до нечитаемости:
всё содержание хранится, показ имеет маркер продолжения, редактор открывает
его целиком. Свободный content получает frame по bounds и полной раскладке;
он не увеличивает соседние фигуры. Resize перераскладывает runs/AST,
не запускает SDK. Измерение и draw используют одну ширину, параметры и переносы.
Bidi и Unicode обрабатывает системный text renderer, не собственный шейпер.

### 15.1. Одна нативная раскладка математики

Общий content layout создаёт boxes с baseline/ascent/descent, bounds, glyph runs,
линиями и отображением `node ID → визуальные области/позиции курсора`. CoreText
формирует glyph runs; он не объявляется готовым layout дробей/матриц. Для них
добавляется один native math-box слой: числитель/знаменатель, радикал,
script/script-script размеры, растягиваемые скобки, верхние/нижние пределы,
таблица ячеек. Метрики математического шрифта, в том числе OpenType MATH,
используются согласованно для измерения и рисования.

В bundle закрепляется STIX Two Math с его OFL и hash; обычный текст сохраняет
системный шрифт и Bidi. Это ресурс рендера, не ещё один SDK.
[STIX, лицензия шрифтов](https://github.com/stipub/stixfonts/blob/master/OFL.txt).
Один math run не разрывается внутри дроби/матрицы ради переноса текста. В смешанной
строке текст и формула согласуют baseline; высокое выражение увеличивает строку.
Внутри маленькой фигуры полная формула сохраняется, а редактор открывает её без
обрезания смысла; соседние объекты не раздвигаются автоматически.

Тот же layout питает working/canonical painter, векторный batch, hit test,
выделение, accessibility и экспорт. Finger tap выбирает узел, не символ в
сериализованной LaTeX-строке. Курсор перемещается между настоящими слотами;
удаление содержимого ячейки создаёт hole, удаление строки/столбца — явная
структурная правка с Undo. Ввод клавиатурой/распознанная замена используют тот же
AST draft. Незавершённый слот можно сохранить; он приостанавливает только расчёт.

Визуальный результат расчёта имеет отдельную роль в этом же layout и не
участвует в редактировании авторского AST. Позиция результата входит в bounds
показа, но не меняет закреплённую геометрию фигуры/bindings. Длинный ответ
сворачивается с доступом к полному результату, а не занимает всю доску.

Не добавляются MathLive editor, KaTeX/MathJax WebView, SVG-снимок на каждую
правку или TeX → PDF → картинка в интерактивный путь. Существующий
`NotebookSandboxedTeXCompiler` остаётся владельцем своей задачи печатного
экспорта; его не удаляют как «legacy распознавания» и не используют вместо
живой структурной формулы. Выбор CortexJS Compute Engine не подразумевает
подключения UI-библиотеки MathLive.

## 16. Отказы, приватность и доступность

| Событие | Результат |
| --- | --- |
| Активация ещё не завершена | Чернила/редактор доступны; один статус настройки, без cloud fallback |
| SDK или пакет недоступен | Нет автоконверсии и смены backend; существующие объекты доступны |
| Неоднозначный адресат / нет письма | Обычный контакт, без случайно выбранной цели |
| Непустая подпись | Не перезаписывается; обычное редактирование |
| rejected / drawing / непредставимая геометрия или математическая грамматика | Ink остаётся, частичного результата нет |
| Формула допустима, но нет значения / операция не поддержана | Редактируемая формула сохраняется; символический ответ/локальный статус, без fallback |
| Несовместимые размеры / деление на ноль / цикл определений | Диагностика у узла; не выдуманный результат и не отказ сохранения |
| CAS недоступен / исчерпан бюджет | Формула и текст доступны; результат не выдаётся за актуальный |
| Очередь занята | Принятое намерение ждёт, дополнительный жест не требуется |
| Размер запроса/очереди превышен | Локальный отказ без вытеснения и усечения |
| Новый eraser/буква в read-set | Старый ответ не коммитится, guard не освежается |
| Независимая правка за пределами read-set | Не отменяет конверсию |
| Identity цели сменена при том же ID | Старый результат отвергается |
| Диск не сохранил source | Зависимая конверсия не проходит |
| Итог writer неизвестен | Проверка receipt по прежнему action ID, не новый вызов SDK |
| SDK timeout | Поздний ответ не записывает; камера/Save/рисование не ждут |

Trace ID связывает hold/intent, worker queue, SDK, mapping, writer и установку
сцены. 500 мс жеста не смешиваются со временем модели. Локальный буфер до
256 событий содержит outcome, размеры, язык, версии SDK/resources/adapter
и длительности, но не письмо, JIIX, координаты и полный UUID документа.

Text run — plain text, не HTML, команда агента или вычисляемое выражение.
Вычисляются только явно типизированные Math nodes; строка из письма не
исполняется как JS, TeX-программа или инструкция агенту.
SDK не имеет права писать произвольные поля. Активация не включает отправку
рукописи в облачный recognizer; передача принятого содержания Mac — штатная
синхронизация документа, не удалённое распознавание.

Преобразование выбранного поддержанного содержания доступно также обычным
контекстным/accessibility действием через тот же intent, без второго pipeline.
VoiceOver получает текст и структурное чтение дробей, индексов и матричных
ячеек; результат и диагностика имеют отдельные роли. Haptic — дополнительный сигнал.
Reduced Motion не скрывает принятие/отказ. Внутренние проверки не превращаются
в обязательный мастер настройки каждой фигуры.

## 17. Замена runtime без параллельного наследия

### 17.1. Что сохраняется

Нативный документ, ink journal, source provenance, writer, renderer,
адресные индексы, причинные версии, Undo и рабочий объект. Сохраняются исправления
ладони/input gate, resize обеих осей, bindings и стабильного ID между hold,
lift и сохранением. Это полезное поведение, а не зависимость от классификатора.

### 17.2. Что заменяется в той же поставке

| Нынешняя/прежняя поверхность | Целевое изменение, не параллельная реализация |
| --- | --- |
| `Sources/NotebookCore/NotebookQuickShape.swift` | Удалить классификатор, fit/resampling heuristics. Нужные чистые операции binding/transform перенести в существующую graphic geometry ровно один раз |
| `NotebookQuickShapeFit` | Заменить на нейтральный native geometry candidate; не оставлять alias и старый SDK→fit→classifier маршрут |
| `Applications/Shared/NotebookQuickShapeSession.swift` | Перенести контакт/hold/resize в `NotebookPencilIntentSession`, удалить прежний session и его timer |
| `quickShape`, `resolveQuickShape`, `onQuickShape`, `acceptQuickShape` в обоих input owners и AppModel | Перевести на общие intent/candidate/command входы без делегирующих legacy wrappers |
| Предложенный `NotebookInkTextRecognizer` / `PKStrokeRecognizer` | Не реализовывать. Вместо него один `NotebookInkRecognizer` для фигур, текста и математики |
| `PKDrawing`/`PKStroke`/`erasePath` adapter из прежнего TDD | Не создавать для recognition; visible fragments поступают из ink owner напрямую |
| `Tests/NotebookCoreTests/NotebookQuickShapeTests.swift` | Заменить тесты старого алгоритма на source mapping, native geometry и контракт конверсии; не держать старый алгоритм ради этих тестов |
| Native тесты `NotebookGraphicInputTests`, `NotebookGraphicSceneTests`, `AcceptedPageInputTests`, `NotebookGraphicModelTests` | Сохранить пользовательские регрессии; переключить fixtures на новый candidate/service seam |
| Старые recognition feature flags, ресурсы и build references | Удалить вместе с последним потребителем; production fallback не оставлять |

PencilKit/UIKit **не удаляются вслепую из всего проекта**: обычный редактор,
Scribble и независимые существующие нужды могут законно их использовать.
Удаляется именно заменённый путь распознавания наших strokes. Drawgine FP2/G1
не подключается к приложению и не используется как запасной backend.

### 17.3. Поверхности одного изменения

- `Applications/Shared/NotebookPencilIntentSession.swift` — один автомат двух
  жестов, без SDK объектов.
- `Applications/Shared/NotebookInkRecognizer.swift` и его закрытые адаптеры —
  native SDK bridge, JIIX decode, source/coordinate mapping. Не сеть сервисов.
- `PencilCanvasView.swift` и `SpatialInkCanvas.swift` — те же input owners,
  общий intent, финализация измерений и непрерывность принятой геометрии.
- `NotebookAppModel` / `NotebookWorkingGraphic` — одна FIFO, коллекция рабочих
  состояний, writer handoff; прежние preview/command paths расширяются на месте.
- `NotebookGraphic.swift`, `NotebookGraphicConnection`, общий geometry module —
  новые нативные формы/маршруты/content и общий label/AST type, без vendor payload.
- `Collaboration.swift`, `CollaborationStore.swift`, `NotebookGraphicCommand.swift`
  — расширенный `convertInkToElement`, `convertInkToLabel`, один validator и Undo.
- `NotebookActionProjection.swift`, `NotebookGraphicRead.swift`,
  `NotebookGraphicIndex.swift`, `NotebookAddressedRead.swift`, `NotebookSQLite.swift`
  — адресные guards/индексы/admission и доставка ссылок, без полного сканирования.
- `PencilUndoHistory.swift`, scene/painter, Mac/MCP/clipboard/export — единое
  прочтение новых значений и causal отмена без повторного recognition.
- `NotebookMath` — единый parser/types/context/evaluation boundary; CortexJS
  bundle поверх имеющегося CQuickJS, без второго CAS и собственного JS runtime.
- Общий content layout — native text + math boxes, единые метрики и hit map
  для интерактивного показа, batches, Mac и экспорта.
- iPad build dependency/resources — необходимый SDK, math2, языки, закреплённый
  CAS bundle и математический шрифт с лицензией; никаких
  CocoaPods/SPM-дублей одной библиотеки и отдельных demo UI targets в продукте.

Сначала доводится один вертикальный заменяющий срез: native SDK → наш объект →
общая запись/Undo на листе и доске. Переключение контактов и удаление старых
вызовов выполняются вместе. Незавершённая работа может быть в рабочей ветке,
но не поставляется как два выбираемых/каскадных production пути.

Если SDK не допускается на целевой ОС либо отсутствует сертификат/пакет,
интеграция остаётся незавершённой в GUI-205. Не компенсируем это скрытым Apple
fallback и не удаляем работающую реализацию отдельным предварительным релизом.
После замены прежний алгоритм не остаётся ни runtime, ни неиспользуемой библиотекой.
Документацию существующего графического пути обновляют тем же runtime-срезом;
сейчас она честно отделена от этого целевого TDD.

## 18. Наблюдаемые результаты и граница завершения

Это контракт поведения, не отдельная обязанность пользователя проходить
ритуал приёмки или подтверждать каждое внутреннее состояние.

| Сценарий | Обязательный результат |
| --- | --- |
| Одно-/многоштриховая стрелка → hold | Одна native стрелка; только её исходники подавлены |
| Hold → ответ под Pencil → resize → lift | Тот же ID и последняя геометрия до/после записи; нет возврата ink |
| Hold → немедленный lift → поздний ответ | Принятое намерение заканчивается без второго жеста |
| Движение до ответа меняет исходный набросок | Старое generation ничего не заменяет |
| Текст в фигуре → отдельная точка 500 мс | Одна подпись, точка не сохраняется, фигура не пересоздаётся |
| Текст/формула на свободном месте → точка | Один native content без рамки, не WebView и не картинка |
| Точка → lift через 100 мс | Обычная пунктуация, без конверсии |
| Ответ text/math/drawing на геометрическое намерение | Нет принудительной фигуры и fallback-классификатора |
| Пауза/перезапуск → команда над сохранённой надписью | Письмо доступно через индекс, его не требуется переписать |
| Ластик исправил часть буквы | SDK получает оставшийся след; Undo не возвращает стёртое |
| Соседний рисунок в окне классификации | Не скрывается вместе с выбранным блоком |
| Один action разделён между принятым блоком и остатком | Нет частичного присвоения/потери остатка |
| Вторая независимая команда, пока первая занята | Обе обслуживаются одной очередью, принятая не вытесняется |
| Уход view / ладонь / следующий Pencil после принятия | Не отменяют прежнюю команду и не заставляют держать Pencil |
| Undo до ответа / Undo во время writer | Отозванный callback не пишет; начатый commit разрешается причинно |
| Undo → Redo | Native результат восстанавливается без SDK |
| Offline после активации, включая холодный запуск приложения | Фигуры, текст, математика, локальное вычисление, редактирование и сохранение без сети |
| Нет активации или SDK недоступен | Содержание доступно, ink сохраняется, второго recognizer нет |
| Доставка на Mac / перезапуск | Те же объекты и происхождение без лицензии распознавания на Mac |
| Две offline-конверсии претендуют на source | Одинаковая целая проекция на peers, без повторного распознавания |
| SDK/CAS обновился | Авторские AST/текст/геометрия не переинтерпретируются; derived cache инвалидируется по версии |
| «Площадь» и Math span `π r²` → одна конверсия | Текст и формула в одном label, без regex-потери границ |
| Дробь `2/4` → конверсия → расчёт | Авторская дробь `2/4`; отдельный точный результат `1/2` |
| Матрица `A := [[1,2],[3,4]]`, вектор `v := [5,6]` | `A v = [17,39]`, `det(A) = -2`, inverse = `[[-2,1],[3/2,-1/2]]` |
| Для A и v заданы тензорные слоты `A^i_j v^j`, диапазон 1…2 | Компоненты результата `[17,39]`; свободный индекс i сохранён |
| `A^i` без разрешённой роли верхнего i | Запись сохранена; степень/тензорный индекс не выбираются случайно |
| Матрица 2×2 × вектор из 3 компонент | Диагностика размеров, не усечение/дополнение нулями |
| Палец → ячейка → правка → Undo | Меняется и возвращается одна ячейка того же объекта; источники не теряются |
| Рукописная замена узла → Undo | Старое поддерево/claims восстановлены, только новый ink вновь доступен |
| `x := 2` → `x+1` → правка x на 5 | Новый ответ 6; поздний ответ 3 не публикуется |
| Две активные дефиниции x / цикл | Локальный конфликт; нет произвольного winner или вечного расчёта |
| Неподдержанный интеграл / hole / бюджет | Запись доступна для редактирования и доставки; ложного ответа нет |
| Матрица/формула доставлена на Mac | Та же структура и раскладка без повторного OCR и без SDK-лицензии |
| Move/zoom после расчёта | Только native transform/layout, не новый recognition или CAS |

Готовность реализации означает один живой путь и отсутствие заменённых
production вызовов/типов/ресурсов, а не только совпавший mock-ответ SDK.
При реализации используются затронутые source/geometry/command проверки и
реальный Pencil на физическом iPad; Simulator не заменяет целевую среду.
Свидетельства runtime принадлежат `docs/verification.md`, статусы — GUI-205.
Этот TDD не сообщает, что SDK/CAS уже собраны, допущены на целевой ОС,
установлены или быстрее прежнего пути, и не закрывает GUI-199 или оставшийся объём GUI-205.

**Итог:** один MyScript-распознаватель, один нативный документ, один механизм
изменений и одно математическое ядро. Формулы — часть того же содержания,
а вычисления — производное поведение, не второй редактор. Мы заменяем технологию распознавания, а не наслаиваем ещё один
редактор и не заставляем пользователя обслуживать внутренние протоколы.
