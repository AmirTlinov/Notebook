## Вывод

Главный долг — не количество файлов и не отсутствие абстракций. В проекте уже есть адресные команды, причинные версии, ограниченные окна и инкрементальный рендер, но **обычные пользовательские пути местами обходят эти механизмы**. Малое изменение превращается в чтение/сохранение всей истории; временное представление сохраняет собственное решение после изменения модели; завершение пользовательской операции не освобождает нижележащего владельца.

Ниже **19 предметных находок: 2 P1, 16 P2, 1 P3**, отдельно четыре риска для прицельного профилирования/уточнения контракта. P1 — нарушение актуальности состояния или неработающее восстановление; P2 — исправляемый функциональный/производительный долг; P3 — менее частый масштабный путь. Приоритет не означает, что физический симптом уже воспроизведён.

## 1. Корректность и владельцы состояния

### A01 · P1 · Старый исполнитель может записать состояние в новую программу

**Код:** [DocumentEditingSession.swift:75–77](/Users/amir/Documents/projects/Notebook/Sources/NotebookCore/DocumentEditingSession.swift#L75), [DocumentProgramOwner.swift:183–205](/Users/amir/Documents/projects/Notebook/Applications/Shared/DocumentProgramOwner.swift#L183), [NotebookDocumentStateCommand.swift:104–123](/Users/amir/Documents/projects/Notebook/Sources/NotebookCore/NotebookDocumentStateCommand.swift#L104).

`sourceVersion` — версия только `content`, но runtime и writer используют её как идентичность всей программы. `javaScript`, `css`, `initialState`, `height` имеют отдельные причинные поля. После JS-only edit прежняя версия проходит writer fence. Во время focus/contact старый runtime намеренно не уничтожается, поэтому путь достижим и в UI. **Прямое исправление:** Core владеет причинной идентичностью исполняемого блока; обычный commit, checkpoint, runtime и paused preview проверяют её. Убрать использование версии одного текстового поля как полномочия целого объекта; не заменять причинность только хешем байтов из-за ABA. Проверка: JS/CSS-only change при старом активном исполнителе, затем старые commit/checkpoint обязаны быть отвергнуты без потери нового состояния.

### A02 · P1 · «Повторить» после ошибки checkpoint повторяет вечный busy

**Код:** [notebook-program.js:138–172](/Users/amir/Documents/projects/Notebook/Applications/WebResources/notebook-program.js#L138), [DocumentProgramOwner.swift:144–150,321–328](/Users/amir/Documents/projects/Notebook/Applications/Shared/DocumentProgramOwner.swift#L144), [DocumentBlockRuntime.swift:323–325,378–380](/Users/amir/Documents/projects/Notebook/Applications/Shared/DocumentBlockRuntime.swift#L323).

Неуспешный authored checkpoint оставляет `suspended=true`, `frozen=false`. Следующий checkpoint возвращает `program_checkpoint_busy`, хотя первый уже закончился. Native park/return сохраняет этот heap; Retry снова вызывает checkpoint. `runtime.retry()` не пересоздаёт его, поскольку lifecycle error намеренно не становится `failure`. Прямой JS-повтор после ошибки и timeout воспроизвёл тупик; явный `resume` восстановил работу. UI-жест не запускался.

**Прямое исправление:** один lifecycle owner различает выполняющийся и неуспешно завершившийся checkpoint; Retry получает реальный переход восстановления. Нельзя автоматически оживлять программу после любой ошибки writer: успешно frozen, но ещё не записанное состояние уже правильно защищено. Проверка: уход/возврат с transient ошибкой authored hook, Retry, следующий commit; отдельно сохранить корректное повторение после I/O failure writer.

### A03 · P2 · Быстрый Undo не отзывает временную маску ластика

**Код:** [NotebookLiveElementEraserView.swift:23–61](/Users/amir/Documents/projects/Notebook/Applications/Shared/NotebookLiveElementEraserView.swift#L23), [PageSurface.swift:68–74,152–159](/Users/amir/Documents/projects/Notebook/Applications/Shared/PageSurface.swift#L68), [NotebookAppModel.swift:2760–2809](/Users/amir/Documents/projects/Notebook/Applications/Shared/NotebookAppModel.swift#L2760).

После lift маска держит отдельный `pending` action до ready постоянного overlay. Undo допустим раньше ready и удаляет erasure из актуальной модели. `presented` снимает pending только при наличии **того же активного cut**, поэтому новая карта после Undo никогда не удовлетворяет условию. Модель восстановила материал, а второй владелец видимости продолжает его скрывать. Это детерминированный тупик после указанного порядка событий; частота попадания на устройстве не измерена.

**Прямое исправление:** reconcile transient mask с актуальной causal visibility accepted action; matching ready ждать лишь для ещё активного cut. Не считать любую пустую карту достаточным доказательством: старый ready действительно может быть устаревшим. Регрессия — обычные erase → lift → Undo при задержанном overlay → новый ready, не одиночный вызов `presented([:])`.

### A05 · P2 · Подтверждение получения заимствует окно истории и теряет backlog

**Код:** [NotebookActionDelivery.swift:22–33](/Users/amir/Documents/projects/Notebook/Sources/NotebookCore/NotebookActionDelivery.swift#L22), [NotebookActionReadModel.swift:215–225](/Users/amir/Documents/projects/Notebook/Sources/NotebookCore/NotebookActionReadModel.swift#L215), [NotebookDiskRefresh.swift:20–22](/Users/amir/Documents/projects/Notebook/Applications/Shared/NotebookDiskRefresh.swift#L20).

**Прямое исправление:** arrival owner подтверждает точные admitted action IDs либо дренирует pending-arrivals с устойчивым cursor. Можно ограничить размер прохода, не множество навсегда. Проверка: первый offline catch-up >64, повторное чтение, все receipts без повторного изменения старых действий.

## 2. Лишняя работа в обычном UX

### A07 · P2 · Lasso выполняет квадратичную работу до своего background task

**Код:** [NotebookDrawingToolController.swift:247–258,314–340,441–463](/Users/amir/Documents/projects/Notebook/Applications/Shared/NotebookDrawingToolController.swift#L247), [NotebookToolInputContact.swift:56–79](/Users/amir/Documents/projects/Notebook/Applications/iPad/NotebookToolInputContact.swift#L56).

RDP repeatedly сканирует диапазоны, а при превышении числа точек повторяет весь алгоритм с большей tolerance. Это MainActor перед `Task.detached`, также вызываемый на overflow во время move. Разрешённый зубчатый synthetic contour дал 75,4/301,9 млн distance visits для 4096/8192 точек; 138–163/538–697 мс в двух Mac-прогонах. После дорогой работы contour схлопывается в две точки и selection отвергается. Гладкая короткая человеческая линия не обязана вести себя так.

Дополнительно `guard var current = contact → append → contact = current` сохраняет две ссылки на Array и провоцирует prefix COW на каждом move; изолированная модель подтвердила 8192 смены backing. Отдельный feedback держит свой contour и другое правило decimation.

**Прямое исправление:** один изменяемый buffer до lift, freeze для worker; bounded incremental упрощение либо существующая background preparation, без quadratic retry в move. Один contour для семантики и feedback. Проверить длинный/зубчатый и обычный физический lasso, сохранение области, отсутствие паузы при lift и overflow.

## Что сознательно не записано как новый дефект

- Старые `waitUntilCompleted`/readback не находятся на текущем live Pencil пути: оставшиеся вызовы относятся к explicit raster/export. Nonblocking semaphore и `waitUntilScheduled` не приравниваются к синхронному ожиданию завершения GPU.
- Causal `nativeRedo` branch-cut gate уже существует. A03/A04 — иные presentation/routing дефекты, не повторное объявление старого resurrected-ink бага.
- Ранее описанные обратная навигация от `selectedIndex`, source identity invalidation и поэлементная Mac-публикация прошли последующие изменения. Старые красные receipts из [page-publication audit](/Users/amir/Documents/projects/Notebook/docs/page-publication-audit.md) не перенесены в эту сводку как подтверждение актуального дерева. Системный curl/latency остаётся отдельным незакрытым сценарием.
- SVG exact raster cache hit возвращается до конвертера; lazy TeX resource opening уже реализован. «Каждый SVG заново читает весь TeX bundle» сейчас неверно.
- Mac document-shell удерживает iframe map, но текущий Mac — helper/export, не человеческий iPad document browser; без живого долгого caller это не объявлено утечкой iPad.
- File refresh умеет unchanged version; полного повторного скачивания файла каждые три секунды не найдено. Исходный перенос чанков и A12 — другая операция.
- Replica echo без `applied.changed` не требует полного reload. `readWorkingSet` ограничивает metadata/placements; A09 касается именно неограниченных ink bodies.
- Relay bounded/backpressure/revocation и внешняя ArchiveTransfer-граница не дали подтверждённых новых P1/P2. Большой файл `NotebookAppModel` сам по себе не основание разбивать систему.

## Порядок ремонта без переписывания проекта

1. **Корректность и восстановление:** A01/A02; затем accepted visibility/обычный Undo A03/A04, полнота arrival A05 и освобождение наблюдения A06. Это отдельные небольшие изменения владельцев, не новая общая платформа.
2. **Обычная интерактивность:** A07–A13. Сначала соединить существующие быстрые пути с настоящими callers; не лечить таймерами и дополнительными caches.
3. **Вычисления и масштаб:** A14–A17/A19. Убирать конкретные повторные проходы и неправильные wakeups, сохраняя causal и cancellation guarantees.
4. **Рабочая проверка:** A18 исправить до использования этого adapter для acceptance. Каждый ремонт проверять регрессией и затронутым обычным сценарием; UI — на физическом iPad. R01–R04 сначала дать собственный измеримый сигнал.

Ни один пункт не закрывается только новым unit test, зелёной сборкой или установленной парой. При этом полный suite и полная performance acceptance не нужны для каждого локального исправления: достаточны предметная регрессия, прямой runtime-путь и честно ограниченный результат.
