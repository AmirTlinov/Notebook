# Перепроверка Notebook

Дата: 4 сентября 2026 года. Основа проверки: `a7c3018` и исправления
сохранения досок в текущем срезе. Проверка охватывает общий Swift-домен,
MCP, сборки Mac/iPad, нативные тесты, 29 сценариев iPad Simulator и чтение
установленного Mac-приложения. Дополнительные пробы проверяют границы новых
вложенных досок. Статус каждого вывода указан ниже.

## Итог

Штатный `./verify.sh` прошёл на исходном срезе. Два дополнительных
регрессионных теста затем воспроизвели потерю независимых изменений досок.
После исправления полный набор Mac прошёл: 21 тест, 0 ошибок, 0 пропусков.
Повторный `./verify.sh` текущего среза также завершился кодом 0; последняя
фаза iPad Simulator заняла 382,55 секунды. Оба полных запуска завершены.

Открыты пять существенных границ: авария при выходе из уменьшенной доски,
удаление доски с отдельной надписью, неполная идентичность версии составного
дерева, упрощённое содержимое портала и рассогласование установленного
приложения с MCP. Поэтому зелёный штатный маршрут подтверждает перечисленные
им сценарии; готовность всех граничных случаев требует следующих проверок.

## Исправлено и проверено

### Получение нового каталога сохраняет независимые локальные изменения

Владелец публикации — `NotebookAppModel.publishStagedWorkspaceIfReady`.
Раньше он выбирал готовое входящее дерево целиком. Если на Mac уже была
передвинута тетрадь в дочерней доске, а входящий снимок добавлял документ на
другой доске, публикация возвращала тетрадь в старое положение. Аналогично
терялась новая камера портала.

Теперь модель перед публикацией передаёт входящий состав существующему
`BoardHierarchy.merge`. Каталог определяет состав, а независимые версии узлов
сохраняют актуальные положения и камеры. Регрессия
`testIncomingCatalogPreservesIndependentLocalBoardAndPortalEdits` проверяет
реальную последовательность сетевых сообщений, память модели и итоговый файл.
До исправления она получила центр `(0, 0)` вместо `(370, -240)`; после
исправления положение и камера сохранены.

### Действия сцены объединяют результат с изменениями, уже записанными MCP

Владелец сохранения — `NotebookAppModel.persistBoard`, который вызывает
`NotebookStore.saveMergedBoard` под общим файловым замком. Через него теперь
проходят перемещение, создание/разбор стопки и сохранение камеры при выходе
из портала. Заменены прямые записи всего дерева из этих четырёх путей.

Регрессия `testPortalExitMergesAnIndependentBoardEditAlreadyOnDisk` кладёт
новое положение тетради в файл до реакции наблюдателя, затем выходит из
дочерней доски. До исправления выход заменял `(1400, 320)` на `(0, 0)`.
После исправления память модели и файл содержат и новое положение, и
сохранённую камеру портала. Контракт сохраняет независимые доски; одновременные
изменения одного `BoardDocument` по-прежнему разрешает версия этого документа.

## Открытые дефекты

### P1 — Выход из уменьшенной доски может аварийно завершить приложение

Владелец преобразования —
[`BoardPortalProjection.portalCamera`](../Sources/NotebookCore/BoardPortalProjection.swift).
Он делит масштаб камеры на масштаб заполнения окна. При окне `1366 × 1024`
и допустимом масштабе доски `0.0125` получается примерно `0.00763`.
Конструктор `SpatialCamera` требует минимум `0.0125` и завершает процесс.

Воспроизведено отдельным Swift-процессом из текущих исходников: вызов
`portalCamera(from: SpatialCamera(scale: SpatialCamera.minimumScale),
viewport: SpatialPoint(x: 1366, y: 1024))` завершился кодом **133** на
`SpatialWorkspace.swift:185`. `NotebookAppModel.leaveBoard` использует ровно
этот путь. Проверка физического жеста на устройстве остаётся отдельным шагом.

Критерий исправления: допустимая активная камера должна иметь представимую
каноническую камеру портала, а выход и повторный вход должны сохранять её
проекцию во всём диапазоне масштаба и размеров окна.

### P1 — Защита удаления пропускает доску с отдельной надписью

Владелец проверки —
[`BoardHierarchy.deleteItem`](../Sources/NotebookCore/BoardHierarchy.swift).
Сейчас он проверяет только `child.board.itemIDs.isEmpty`. Надписи и
агентские слои принадлежат `child.board.elements`, поэтому доска с одним
текстовым элементом проходит проверку и исчезает вместе с этим элементом.

Swift-проба создала пустую по предметам дочернюю доску, добавила в неё
`SpatialElement` с текстом и вызвала удаление. Результат:
`accepted=true`, `childExists=false`. Рисунок принадлежит отдельному
`SpatialInkJournal`; его сохранность при удалении также требует явного
контракта. В этой проверке воспроизведён именно случай текстового элемента.

Критерий исправления: понятие очищенной доски учитывает всех владельцев её
содержимого, либо пользователь явно подтверждает удаление содержимого целиком.

### P1 — Изменившееся дерево может сохранить прежнюю версию снимка

[`BoardHierarchy.merge`](../Sources/NotebookCore/BoardHierarchy.swift) объединяет
узлы независимо, а общей версии присваивает максимум двух прежних версий.
Два участника могут одновременно изменить разные доски. После объединения
получится новый состав узлов с тем же максимальным `stamp`, который один
участник уже опубликовал.

Swift-проба с разными UUID участников подтвердила одновременно:
`MERGE_CHANGED=true`, `HIERARCHY_STAMP_UNCHANGED=true`, `NODES_CHANGED=true`.
[`MacPreviewPublisher`](../Applications/Mac/MacPreviewPublisher.swift) использует
в ключе публикации только `board.stamp`, а MCP сравнивает этот же `boardStamp`
в квитанции. Из кода следует, что при остальных неизменных владельцах
прежний PNG может оставаться принятым за актуальный. Изменение дерева с
сохранением версии воспроизведено; отдельная сквозная проверка устаревшего PNG
остаётся открытой.

Критерий исправления: идентичность опубликованного дерева отражает версии
всех входящих узлов и камер. Проверка должна соединять независимое слияние,
обновление PNG и отказ MCP принять прежнюю квитанцию.

### P2 — Портал показывает исходник Markdown/HTML вместо готового слоя

В [`PortalElementPreview`](../Applications/Shared/SpatialWorkspaceView.swift)
ветка любого элемента, кроме `nativeText`, создаёт
`Text(element.source.isEmpty ? element.html : element.source)`.
Активная доска показывает тот же элемент через WebKit. Поэтому SVG,
оформленный Markdown и интерактивная модель меняют вид при переходе через
портал. Совпадение камер само по себе обеспечивает только геометрию.

Подтверждение: прослежен исполняемый путь двух представлений. Пиксельная
регрессия со сложным слоем в дочерней доске пока отсутствует. Дополнительно
портал каждый раз собирает пространственные чернила через PencilKit;
стоимость этого пути на плотном рисунке требует замера на физическом iPad.

Критерий исправления: портал использует готовое визуальное представление
того же содержимого; тест сравнивает последний кадр портала с первым кадром
активной дочерней доски, включая текст, SVG и стёртые чернила.

### P2 — Установленный Mac и текущий MCP используют разные форматы

На момент проверки канонический исполняемый файл
`~/Applications/Notebook.app/Contents/MacOS/Notebook` собран 3 сентября.
Его текущая квитанция имеет формат **3**, тогда как исходники MCP и
`CurrentViewReceipt` требуют **4**. Живой `notebook_observe` вернул
`operation_failed: Квитанция текущего вида повреждена`.
Повторное чтение свежим процессом MCP подтвердило ту же ошибку.

Каталог, доска и контекст читаются через предусмотренную миграцию:
получены 6 предметов, одна корневая доска и режим `board`. Приложение
открывает существующее окно; ошибка относится к согласованности публикации.
Установленные приложения в ходе этой проверки сохранены на прежних версиях.

Критерий завершения: установить один проверенный срез на Mac и iPad,
получить свежую квитанцию формата 4 и успешный живой `notebook_observe`.

## Граница доказательства

Проверка Simulator исполняет пользовательские сценарии синтетическими
касаниями. Качество настоящего Pencil, 120-Гц плавность плотных вложенных досок,
радиосеть между физическими устройствами и восстановление после обрыва
питания требуют самостоятельного измерения. TCP остаётся каналом личной
доверенной сети, как описано в README; спаривание и шифрование находятся за
границей текущего прототипа. Текущий документ фиксирует найденные условия и
критерии их закрытия, а штатный тестовый успех сохраняет свой проверенный объём.
