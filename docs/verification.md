## Проверка зависимостей и карта адресов — 246

Повторный поиск использует один проверяемый промежуток в неизменяемых путях.
Кеш промахов отвергнут: ускорял прогретый пакет ценой первых запросов.
Три попеременные пары Release-замеров на 4096 файлах: 25 проверок одной квитанции
по 4000 зависимостей **9,736 → 5,625 мс**; один повтор **0,398 → 0,237 мс**;
первая проверка свежего Source **5,608 → 5,228 мс**, построение индекса отдельно.
Память не накапливает отрицательные пути; 100 000 запросов, произвольный порядок,
32 компонента пути и прежние отпечатки проверены.

Конструктор карты адресов вычисляет поля один раз и использует общий hex-кодировщик.
Полная проверка загруженных карт сохранена. На 4096 файлах **194,107 → 14,827 мс**,
на одном **0,203 → 0,014 мс**; медианы 45 построений, JSON побайтно равен.
Стоимость причинной перепривязки попадания в память теперь видна в фазе `bind`.

**10 Core + 7 native iPad + 1 physical UI + 7 Mac PASS**, без пропусков и native
runtime warnings. Сценарий первого ввода сохраняет `x=7`, `x²=49` после смены
страницы, закрытия и нового процесса; оба снимка проверены визуально.
В одиночном native sound opening бумага/программа **1102/1284 мс**, повтор
**119/168 мс**. TeX остаётся **982 мс**: ускорение этих алгоритмов не установило

## Печатные зависимости и приоритет — 244

Повторные поиски по массиву заменены одним индексом неизменяемого исходника и
повторным использованием отпечатков. Каталоги читаются по диапазону путей;
промежуточный вариант с полным графом каталогов удалён из-за расхода памяти.
На 4096 допустимых файлах 25 повторных проверок одной квитанции по 4000
зависимостей заняли **3886 → 9,27 мс**, полный ключ: **103,47 → 6,33 мс**.
До — медиана трёх запусков, после — один; все отпечатки совпали. Это прогретый
пакет алгоритма на Mac. Промежуточный граф давал **4,87 мс**: его замена
диапазонами ухудшила повторный поиск. Сравнение с линейным сканером скрывало
этот компромисс; исправление и отдельные fresh/warm замеры приведены выше.

Одна ограниченная очередь теперь владеет подготовкой байтов и движком.
Текущий запрос отзывает спекулятивную попытку, ждёт фактического завершения и
сохраняет её читателей для повтора. Повышение уже ожидающего запроса действует
сразу; принятый экспорт защищён. На занятой бесконечным TeX-циклом VM текущая
печать завершилась за **202 мс на iPad / 159 мс на Mac**. Это один native сценарий
на платформу. Десять отмен с завершением движка — **1,77–2,70 мс** на iPad.

**6 Core + 13 native iPad + 1 physical UI + 11 Mac PASS**, без пропусков и native
runtime warnings. Первый ввод → смена страницы → закрытие → новый процесс
сохраняет `x=7`, `x²=49`; оба полных снимка проверены визуально.
Независимое ревью завершено; проверенная Release-пара установлена на Mac и iPad.
В одиночном native sound opening бумага готова за **1039 мс**, программа за
**1247 мс**; повторное открытие — **116/159 мс**. Native print всё ещё **980 мс**.
`sample` останавливал standalone probe, а `xctrace` не завершил запись;
пригодного CPU-профиля нет. Cold-process p95/p99 и системная приёмка открыты.

## Печать и кеш — 243

Один SQLite-владелец хранит производные данные, бюджет и LRU; повреждение и отмена
не мешают повторному открытию. Проверяются CRC и длина ресурсов ZIP.

На Mac медиана десяти попеременных компиляций **715 → 641 мс (−10,4%)**;
PDF, SyncTeX и прочитанные входы побайтово равны. При 100 000 посторонних
metadata-only кандидатах поиск **19 500 → 1,6 мс**, сохранение — **1,5 мс**;
промежуточный вариант с прежним глобальным вытеснением занимал 15,3 с и удалён.
Это измерения компилятора и кеша, без переноса коэффициентов на весь UI.

На физическом iPad первое открытие sound: бумага **1124 мс**, программа **1320 мс**
против прежних 1451/1646 мс; повторное — **116/166 мс**. По одному native observation
на состояние, без cold-process и p95/p99. Десять отмен вычисления с завершением
движка занимают **1,7–2,1 мс**. **19 native iPad + 1 physical UI + 18 Mac PASS**,
без пропусков и runtime warnings. Первый ввод, смена страницы, закрытие и новый
процесс сохраняют `x=7`, `x²=49`; оба снимка проверены визуально.
Независимое ревью принято. Подписанная пара 243 установлена на Mac и iPad.

## Архитектурная переработка — 241

Чтение, запросы страниц и публикация сцены получили отдельных владельцев.
Состояние каждого программного runtime собрано в одной записи; позднее завершение
прежнего источника не меняет его замену. Immutable layout владеет индексом размеров
программ. Заменённые поля, partial-layout/isComplete, массовый loadAvailableDocuments
и неиспользуемая диагностика reservations удалены. Исправлена потеря interaction
failure после независимой подготовки native PDF; повтор сохраняет видимую бумагу.

**73 уникальные native проверки физического iPad + 24 Mac PASS** в отдельных
адресных прогонах; runtime warnings 0. Код продукта неизменен после run-2;
позднейшие исправления затрагивают setup тестов. На iPad прошли запуск программ
на доске и в документе, фон/холодное открытие, pinch-close/double-tap-open,
ссылки/возврат, LaTeX и перелистывание. Composition journey с перемещением,
удалением, undo/redo и cold reopen прошёл отдельным неизменённым повтором;
причина signal kill в первом UI-прогоне не установлена.
Board24 прошёл обе реальные фазы масштаба и первые нажатия всех 24 программ.
Траектория теста исправлена по физической записи; product input routing сохранён.
Итого 7 UI сценариев PASS. Подписанная пара 241 собрана и установлена.
[Результаты и исходные неудачные попытки](audit-evidence/2026-10-05/architecture-documents/results.json).

В нагрузке из 100 000 fragments / 1000 программ / 1024 тёплых запросов размеры
находятся за **0,046 мс вместо 3951 мс** (медиана трёх пакетов).
Это lookup в layout, без стоимости первого построения индекса и показа UI.
В изолированном native IPC на доске из 16 текстовых тел правка одного тела
передаёт **1 PNG вместо 16**, base64 **11 616 вместо 122 224 байт (−90,5%)**;
перемещение использует прежние материалы без новых PNG. Одиночные IPC timings
не устанавливают общий прирост FPS/отклика.

## Открытые измерения

- **GUI-388:** на 240 / SDK frontend 0.1.6 чёткий материал после 50→95%
  появился за 228 мс (239: 374 мс); резкий 100→350% — за 1672 мс.
  Эти DOM/rAF и native manifest clocks не измеряют OS display time.
  Native crash при нулевой ширине региона исправлен в 240.
  Активная панель Codex тогда загружала старый frontend 0.1.5; принятие 0.1.6,
  перенос между экранами/DPR и лишние idle manifests остаются открытыми.
  [Замеры и active consumer](audit-evidence/2026-10-01/codex-zoom-latency/results.json).
- **Cold document/SVG/programs, Native24, first curl:** строгие бюджеты,
  причина первого cold discard и ready-time WebKit IPC не приняты.
  В 240 accepted→preparation cold1/cold24 — 0,305/0,283 мс;
  первый native installation — 330,515/436,173 мс, все 24 — 1057,570 мс.
  Порядок холодных сцен и instrumentation влияют на сравнимость.
  [Source clocks](audit-evidence/2026-10-01/cold-owner-240/cold-metrics.json).
- **Pencil/eraser:** каждый sample ≤20 мс и аппаратный contact-to-display
  требуют цепочки contact revision → callback → submission/GPU → presentedTime.
  Подача через native recognizer и CADisplayLink не измеряют аппаратный отклик/FPS.
- **Промежуточный mixed cut:** итоговый снимок не доказывает все OS-кадры.
  В inverse-journey2009 GPU cut содержал штрих и OS receipt 23,023 мс,
  но drawHierarchy(false) его не показал. Independent display oracle открыт.
- **Системные frame/CPU/GPU/memory:** текущая пара ещё не принята;
  прежние Time Profiler2042 и logging-only60s не дали пригодных измерений.
