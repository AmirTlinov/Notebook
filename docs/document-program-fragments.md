# Живые программы в LaTeX-документе

## Источник и идентичность

`\NotebookInteractive[id=osc,width=\linewidth,height=60mm]{programs/osc}`
объявляет экземпляр программы. Встроенный `notebook.sty` вычисляет размеры TeX и
записывает прямоугольники при shipout, включая float. `breakable` разбивает область
между страницами обычного одноколоночного потока; в `twocolumn`/`multicols` даёт
адресную ошибку. Внутри `figure`/`minipage` область цельная, как и программа без
`breakable` в колонке.
Разные единицы TeX допустимы; PDF-карта нормализована в PostScript points.

Единственный редактируемый источник — файлы документа. `program.json` задаёт
входные HTML/CSS/JavaScript, модульный режим, начальное состояние и явные
зависимости. Без него используются `index.html`, `style.css`, `main.js`.
`DocumentProgramSource` превращает неизменяемое поддерево и зависимости в обычный
`NotebookProgramPackage`; второй редактируемой копии нет.

`sourceBasis` связывает пути, SHA и выигравшие причинные точки исполняемых файлов.
Полученная проигравшая конкурентная версия меняет файловый CAS, но не heap.
ABA того же файла меняет basis. Абзац в другом файле, размеры или положение
области — нет. Состояние хранится отдельно по ID экземпляра. Совпадающие ID
экземпляров, отсутствующий ресурс и неверный размер диагностируются адресно;
ошибка программы не закрывает корректный печатный текст.

## Владельцы экрана

`DocumentPagePreparation` принимает только карту завершённой сборки; диапазоны
сгенерированных строк больше не определяют интерактив. Для продолжений карта
несёт страницу, прямоугольник и смещение в общем viewport.

На iPad `DocumentPagePresentationOwner` владеет листом и композицией,
`DocumentProgramOwner` — исполнителями и checkpoint. Один `DocumentBlockRuntime`
на ID/basis использует один WebKit; `DocumentProgramOverlayHost` показывает его
через нативный clip. На Mac тот же контракт исполняет iframe-адаптер.
Соседние страницы читают разные части одного viewport, без скрытых копий.
Изменение геометрии обновляет тот же WebKit, сохраняя heap; оно не меняет basis.

Каждый heap имеет одну запись `DocumentProgramOwner.Slot`: lifecycle job,
применение состояния, ошибка паузы и удержание при возврате заканчиваются вместе
с ним. Поздний результат старого heap не меняет его преемника. Пассивный снимок
живёт отдельно. Неизменяемый `DocumentLayoutRecord` один раз индексирует размеры
продолжений; показ программы обращается к её ID без обхода чужих фрагментов.

Исполнители допускаются общим `SceneRenderResources` по реальной видимости.
Фокус и принятый контакт удерживают владельца ввода. Ожидающая область показывает
ожидание, сломанная — адресный повтор; это не фиктивная готовая картинка.
Готовность бумаги допускает перелистывание с видимым ожиданием или ошибкой
программы. Она не выдаёт receipt успешного запуска программы. Для физического
перелистывания владелец страницы соединяет готовый бумажный растр с атомарными
снимками существующих WebKit только в видимых областях; ожидание и ошибка
снимаются с того же нативного состояния. Заимствованный кадр удерживает ресурсы
до завершения жеста. Авторский pause/checkpoint в этот путь не входит.

Пакеты материализуются по спросу: сначала текущая страница и уже живые
исполнители, затем требуемые соседние страницы. Отсутствие ещё не загруженного
дескриптора не означает удаление старого heap. Сообщение страницы содержит
только её записи состояния; на iPad бумажный WebKit не получает начальные
состояния внешних нативных исполнителей. Переход по ссылке завершает только
сфокусированную программу; освобождение владельца сохраняет общий checkpoint
его удерживаемых исполнителей.

## Состояние и жизненный цикл

`NotebookProgram/1` общий для документов, пространственных программ и экспорта.
API устанавливается до авторского HTML. JavaScript объявляет `notebook.ready`;
отказ, отсутствие декларации или зависшее обещание не становятся успехом.
На Mac неготовый iframe завершается адресной ошибкой, а корректный PDF и
остальные программы остаются доступны. Receipt готового листа сохраняет эту
ошибку; он не утверждает успешную проверку программы. Проверка выбранной
страницы возвращает для всех ID карты `ready`, `failed` или `not_checked` со
сферой `startup`: успешный запуск не подтверждает взаимодействия, экземпляры
других страниц не считаются проверенными. Автор отвечает за остановку своих таймеров и ресурсов.

Порядок освобождения: pause → checkpoint полного JSON → подтверждённая запись
общим writer → снимок/освобождение. Ошибка записи удерживает остановленный heap
и предлагает повтор. Явное закрытие/фон держит execution gate закрытым до
явного resume: resize, Retry или освобождение внимания его не открывают.
Параллельные pause/resume следуют последнему явному намерению. Ошибка автора
требует Retry, а не изменения размеров; новый автор не наследует старую ошибку.
Приостановленный кадр принадлежит также снятому viewport. Смена «Лист → Код → Лист» использует тот же порядок:
без вытеснения возвращается тот же контекст, после вытеснения — принятое состояние.

Callback проверяет установленный runtime token и текущую карту; Core проверяет
ID документа, путь программы, точный basis файлов и причинную версию состояния.
Поздний ответ заменённой программы не перезаписывает новую. `onStateChange`
асинхронно возвращает фактически принятую SQL-версию, как и `onStateCheckpoint`;
синхронный публичный `notebook.commit` сообщает только допуск. Старый
оптимистичный echo не откатывает локальный ввод.

`notebook-program.js` — единственный владелец состояния: каждый успешный commit
держит неизменяемый JSON в FIFO до записи и ACK. Перегрузка отклоняется до true;
checkpoint сначала дренирует принятую очередь. Потеря фокуса запрещает новые
записи, но не отзывает принятые. Неготовый/сломанный автор при закрытии также
дренирует очередь, без ожидания ready или повторного вызова сломанного checkpoint.

Нового постоянного потолка JSON нет. `SceneRenderResources` допускает стоимость
UTF-8, узлов и обоих значений причинного merge; bridge переносит дескрипторы и
ограниченные Unicode-safe окна. Снимок внешнего состояния устанавливается
атомарно. Native deadline 4,5 s и JS deadline 4 s проверяют load token независимо
от приостановленных таймеров WebKit. Retry продолжает незаконченный этап, сохраняя
окна, heap, допуск и подтверждённый writer receipt; ACK не списывает кредит дважды,
таймаут не отменяет уже начатую SQL-запись. Checkpoint failure не снимает heap заново.
Авторский JSON `toJSON`/getter может синхронно повторно войти в lifecycle.
Поэтому существующий JS owner повторно проверяет disposed, cancellation и generation
после сериализации, непосредственно перед freeze commit. Отменённая попытка не
заменяет accepted state и не возвращает frozen descriptor; новая попытка и исходная
ошибка сериализации сохраняют свои исходы. Это не решает NB13 admission-before-copy:
полный двухфазный протокол должен использовать существующий native owner.

Frozen descriptor хранит отдельный commit ID вместо повторно используемого имени.
Retry и неуспешный resume возвращают тот же ID; успешный resume и export
отзывают старый адрес. Dispose завершает авторскую работу, но сохраняет уже
замороженные окна для незавершённого durable drain. Позднее окно не может читать уже другой freeze. Native
Snapshot.revision и существующий iframe adapter передают этот непрозрачный адрес
без изменений. Числовой FIFO/ACK и публичный авторский lifecycle API сохранены.
Это самостоятельное исправление ABA; lifetime после native/iframe timeout и
producer admission-before-copy остаются отдельными незакрытыми проверками.

`CheckpointPreparation` владеет ожиданием памяти и прочитанными окнами снимка.
Отзыв источника отменяет очередь допуска до нового чтения; уже начатый ответ
WebKit удерживает свои байты до завершения. Принятая запись независимо дренируется writer.

Внутренний `readDocumentProgramState` использует предварительно допущенные байты
в одном SQLite-снимке. Публичное `documentProgram` сохраняет отдельный 4 MiB лимит.
Проверка basis читает только поддерево программы и объявленные зависимости,
не соседнюю главу или исторический журнал. Пассивный рендер учитывает одновременно
промежуточную бумагу и финальный растр; плотность backing равна допущенной.

Новая TeX-сборка не является новым исполнителем. Пока исправляется TeX-ошибка,
последний корректный PDF и неизменённые установленные программы остаются
предыдущей сборкой, а не объявляются текущим render.

## Ресурсы, экспорт и перенос

`NotebookProgramAssets` выдаёт случайный capability-origin только для файлов
пакета. GET/HEAD, диапазонное чтение, MIME, CSP, bounded reads и отзыв namespace
принадлежат существующему адаптеру. Произвольные устройства/файлы/сеть не доступны.

Регистрация проверяет весь пакет и сохраняет неизменяемые `NotebookProgramResource`.
Каждый диапазон читает один SQLite cut, до 1 МиБ и только затронутые parts;
его стоимость не растёт с общим числом частей. Сырой публичный `readProgramFile`
полностью проверяет переданный descriptor при каждом вызове.

PDF-экспорт использует неизменяемый source/state cut: текст остаётся векторным,
кадры программ занимают только их реальные области. Он не перематывает живой
документ. Один ZIP-контейнер `.notex` переносит manifest, исходники, ресурсы и
состояние; импорт проверяет пути, размеры и хеши и создаёт новую закрытую копию
штатной транзакцией. Подходящие производные PDF/SyncTeX/карта используются сразу,
неподходящие отбрасываются без потери исходников. Импорт не запускает программы.

## Изображение и внимание

`capturePresented` фиксирует установленную нативную композицию в момент Send;
последующее PNG-кодирование не меняет её. `captureCurrent` делает новый кадр и
не доказывает прошлый момент. Источник, состояние, страница, crop и диагностика
связаны с той же сборкой.

`notebook.semantic` — ограниченные данные выбранного авторского объекта после
pause/checkpoint, не инструкции. Семантика и пиксели делят один `RasterLease`;
координаты преобразуются через текущий фрагмент. Очистка, ошибка и завершение
внимания освобождают pause. Старые UUID/basis/state ответы отклоняются.

`DocumentProgramOwnerTests` и `DocumentBlockRuntimeTests` проверяют один heap,
независимость абзаца/состояния/геометрии, разные продолжения и запись до удаления.
Физические жесты, доставка и полная совместная сессия проверяются отдельно по
[приёмке](verification.md).
