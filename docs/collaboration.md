# Общий ход

Один `CollaborationAction` — законченный вклад агента: описание, ссылки на
рассмотренные фрагменты, версии владельцев и упорядоченный пакет операций.
Содержание принадлежит прежним PageDocument, BoardDocument и DocumentDocument.
Квитанция хранит различия полей и причинные версии для точной отмены.

## Исполнение

`MCP/src/actions.ts` описывает публичные операции и готовит Markdown.
`Sources/NotebookBridge/main.swift` передаёт JSON одному владельцу исполнения:
`Sources/NotebookCore/CollaborationStore.swift`. Все поля проверяются до записи.
Создание предмета сохраняет выбор человека. Текущая камера служит контекстом
чтения, а запись всегда называет физического владельца.

Файловый замок объединяет обычные записи приложения и публикацию хода.
`collaboration/pending.json` фиксирует подготовленный пакет; следующий владелец
замка завершает его перед своим действием. Квитанция публикуется после предметов
и каталога. Повтор action ID возвращает прежний результат; другой запрос с тем
же ID получает `action_id_conflict`.

## Согласование и отмена

`CollaborativeContent` хранит причинные версии смысловых полей. Изменение
исходника и производного HTML является одним полем содержания; оформление,
рамка и интерактивное состояние имеют собственные версии. Независимые правки
сходятся по ID. При конкурентном пересечении человеческое поле сохраняет
значение. Составной результат получает новую агрегатную версию, поэтому
рендерер и зеркало видят изменение даже при совпавших исходных счётчиках.

Отмена сравнивает значение и владельца поля с результатом хода. Сохранившиеся
поля возвращаются назад; поздние доработки перечисляются как сохранённые.
Предмет, который человек уже наполнил, сохраняется вместе с зависимостями.
Повтор отмены возвращает ту же квитанцию.

## Проверяемый маршрут

- `swift test`: адресация доски, атомарная проверка, повтор запроса, частичная
  правка, отмена после доработки, восстановление подготовленной публикации,
  согласование полей страницы, блоков документа и элементов общей доски.
- `cd MCP && npm run check && npm test && npm run smoke`: настоящий stdio MCP,
  явные конфликты, пакет, отмена, A4/Letter и физические границы обложек.
- `./verify.sh`: нативные приложения, сетевые сообщения и пользовательские жесты.

## Вид и продолжение

`notebook_observe` возвращает доступное содержание сразу. `visual.status` отдельно
называет готовность проверенного PNG; `wait_ms` задаёт явное ожидание до 4000 мс.
`cursor` и `since` связывают два наблюдения и перечисляют изменившихся владельцев.
Чтение листа, доски и документа по умолчанию компактно; ID элемента/блока раскрывает
исходник. `notebook_search` возвращает путь по дереву и точную ссылку на результат.

`notebook_point` сохраняет интерпретацию агента с физическим владельцем и хешем
рассмотренного содержания. `notebook_render` заказывает конечную поверхность либо
область без движения камеры. `TargetRenderRequest` связывает запрос с исходниками,
а `MacPreviewPublisher` готовит WebKit, бумагу и окончательные чернила. Квитанция
возвращает хеш PNG, область, версии и диагностику JavaScript, загрузки и переполнения.
`notebook_place` использует эту же карту видимых чернил и геометрию владельцев;
занятое место получает явное предложение продолжить на другом листе или доске.

`SpatialInkComposer`, `SpatialInkGeometry` и общие Metal shaders воспроизводят одни
сырые операции на iPad и Mac. `SpatialInkRasterCache` связывает результат с владельцем,
ревизией и проекцией. Ластик является операцией смешивания того же рендера.

`CollaborationContent` переносит завершённый срез существующих владельцев одним
сетевым сообщением. Приёмник объединяет его с памятью и диском под файловым замком,
проверяет принадлежность и публикует восстанавливаемую транзакцию. Сохранение,
подтверждение приёма устройством и подтверждение видимой области имеют отдельные
квитанции; отсутствие квитанции остаётся ожиданием соответствующего события.

## Общее внимание и показ

`NotebookAttentionProjection` переводит устойчивую ссылку в текущую геометрию
владельца. `NotebookPointerView` принимает один контакт; пара пальцев остаётся
у сценовой камеры. `SharedContext` хранит неизменяемые указания и ответы с
устойчивыми ID. Ответ называет предыдущее указание того же контекста; независимые
ответы объединяются, а повторный ID с другим содержанием отвергается.
`SharedContextSelection` принадлежит выбору человека, а не адресу агентской записи.
Ход с `contextID` требует существующий контекст. Самостоятельный ход создаёт
контекст из собственных ссылок; текущий выбор человека не используется.
Контексты, выбор, содержание и ходы публикуются одной восстанавливаемой транзакцией.
`notebook_observe(context_id)` читает прежний контекст после перехода человека;
без аргумента он читает текущий человеческий выбор. `notebook_point` создаёт
контекст либо добавляет ответ через `context_id` и `reply_to`.
Поиск принадлежит `NotebookStore.search`: названия и текст всех владельцев
рассматриваются в одном завершённом снимке, результат содержит путь и ссылку. `DocumentRenderRegistry` получает реальные области блоков от того же
WebKit, который размечает физические страницы.

`NotebookCollaborationView` показывает интерпретацию, описание хода, «Показать»,
«Отменить» и историю результатов. Запрошенный показ проходит через существующие
владельцы камеры и выбора страницы после завершения касания. `NotebookAppModel`
подтверждает видимые результаты по готовности слоя, точной ревизии и полной
рамке внутри viewport. `NotebookDisplayConfirmation` запускает эту проверку
после кадров активного окна физического устройства. Приём пакета и показ —
разные квитанции. Для нескольких результатов подтверждение накапливает
действительно посещённые области.

Состояние интерактивного блока имеет операцию `setBlockState` и обязательную
`stateRevision`. `DocumentStateRecord.fieldVersion` сохраняет человеческое
значение при конкурентной агентской записи. `notebook_place.expected` включает
`sourceRevision`: вставка проверяет под файловым замком также рассмотренные
чернила и геометрию. Их изменение возвращает `revision_conflict` и ведёт к новому
расчёту места.

## Региональное рассмотрение и возвращение

`ReferenceVision` отличает `checking`, `current`, `changed`, `review_required`
и `target_missing`. Регион получает отпечаток окончательных пикселей того же
Metal-рендерера, а пересекающиеся агентские элементы — идентичность содержания.
Положение физического владельца не становится содержанием ссылки. Исходный
отпечаток сохраняется отдельно от ограниченного кеша PNG; ответ на ту же область
использует тот же рассмотренный источник. Если источник успел измениться до
первого точного снимка, система просит повторное рассмотрение, а не выдаёт новый
рисунок за прежний. Неподготовленная область не объявляется ни свежей, ни изменённой.

`NotebookAttentionProjection.references` переводит одно прямоугольное указание
в ссылки на пересечённых физических владельцев. `NotebookCollaborationView`
собирает указание, интерпретацию и ходы вокруг `contextID`; шестисекундная отметка
уступает место компактному доступу к истории. Снятие человеческого выбора
сохраняет контекст. `NotebookNavigationView` использует общий Core-поиск,
показывает страницы и не более шести настоящих миниатюр одновременно.
«Показать» сохраняет `SessionPresence` и выбранный лист в ограниченном стеке
возврата. Возвращение ждёт касания и использует существующий сценовый переход;
поворот экрана переводит сохранённую камеру через `SessionPresence.adapted`.

Ручка, ластик и указание имеют одинаковое состояние выбора. Любое нажатие ручки
только выбирает её; настройки открывает отдельная кнопка. Неинтерактивное
содержимое выбирается касанием, интерактивное сохраняет контролы и предлагает
редактирование в контекстном меню. `ElementEditingSession` владеет переносом и
изменением размера; рамочные ручки передают ему жест, завершение меняет только
геометрию существующего элемента. Источник и интерактивное состояние сохраняются.

## Миграция и выпуск

Первый запуск `migrateCollaborationStorage`
под файловым замком сохраняет точные прежние файлы в
`migrations/before-collaboration-v1/`, добавляет причинные версии существующему
содержанию и публикует `collaboration/format.json`. Подготовленная транзакция
восстанавливает завершённый пакет при следующем открытии. Маркер делает
последующие запуски обычным чтением. Установочный маршрут дополнительно
сохраняет копию всего рабочего пространства перед заменой Mac-приложения.

Формат сотрудничества 2 заменяет перезаписываемые указания контекстами.
Миграция сохраняет точные байты в `migrations/before-collaboration-v2/`;
старый ход получает самостоятельный контекст, старое указание — отдельный.
Связи между ними не выдумываются. Перенесённые указания отмечены
`requiresReview`: отсутствие регионального отпечатка не считается свежестью.
Прежние файлы указаний удаляются только восстанавливаемой публикацией маркера 2.

Прежний установщик (до перехода на SQLite) проверял один хеш исходников и собирал
согласованные Mac/iPad и подтверждает свежее наблюдение установленной пары.
Навык Notebook раскрывает ритм observe → point → place → apply → render → action.
Разговор и запуск агента принадлежат Codex.

## Приёмочный сценарий

Автоматические проверки проходят адресацию A/B, независимые и пересекающиеся
правки, восстановление публикации, повтор запроса и отмены, миграцию с копией,
защиту рассмотренных чернил, указание после перемещения и изменение источника.
Нативный тест разделяет доставку и показ. Mac-тест сверяет окончательное стирание,
составной растр и увеличение области, реальную ошибку JavaScript и переполнение.
UI-сценарий указывает рисунок, открывает агентский результат, перемещает его рукой
и отменяет ход: рамка человека и исходная рукопись остаются.

Физическая приёмка выполняется с Амиром: указать рисунок → получить привязанное
понимание и пояснение → открыть результат → доработать → отменить ход → сверить
итог через MCP. Факт этой приёмки фиксируется отдельно от автоматических тестов.

Проверенный текущий срез: 125 Core-тестов, 28 MCP-тестов, свежий stdio MCP,
нативные Mac-тесты и полный набор сценариев iPad Simulator прошли через
`./verify.sh`. Нативная проверка региона сравнивает настоящие окончательные
чернила после правки снаружи, внутри, перемещения владельца и стирания;
UI-проверка проходит миниатюры, поиск, возврат и бережную отмену.
Локальная квитанция: `.build/notebook-0.4-slice2-verify-final.log`.
Промежуточная версия 0.3.4 (7) установлена на Mac и USB-подключённый iPad.
Квитанция `.build/install.YUAFXV/installed-proof.json` подтверждает готовый
составной снимок через новую stdio MCP-сессию. Повторное наблюдение
`.build/install.YUAFXV/installed-proof-recheck.json` подтверждает соединение
с запущенным iPad. Сохранённые данные скопированы
в `.build/install.YUAFXV/workspace-before-install`. Физическая приёмка 0.4
ещё не выполнена.


Реплика на уже рассмотренный источник передаёт его хеш в
`notebook_point.references[].source_revision`. Ссылка сохраняет именно этот хеш; наблюдение
явно сообщает `changed`, если человек успел продолжить фрагмент.
`notebook_action.action.continuations` перечисляет изменённые после хода поля с
устойчивыми ID и текущим владельцем. Интерфейс отмечает «Продолжено вами» и
раскрывает фрагменты в истории. Исходное предложение остаётся в квитанции хода.

Системный `flock` постоянного `.mutation.lock` владеет исключением между
процессами. Ядро освобождает его при завершении процесса; следующее открытие
завершает подготовленную транзакцию. Чтение сохраняет каталог файлов неизменным,
поэтому `DirectoryWatcher` реагирует на публикацию содержания. Нативная проверка
`testCoherentReadsLeaveTheWatchedDirectoryQuiet` требует ноль уведомлений от
повторных согласованных чтений. Проверка установленного Mac на сохранённых
данных подтвердила готовый MCP-снимок, соединение с iPad и 0% CPU в покое.


## Граница выпуска 0.4

Текущий срез реализует сохраняемые контексты, общий поиск, региональную проверку
исходника на Mac, указание нескольких владельцев, явные инструменты и рамки,
историю связанных ходов, управление страницами и возвращение из «Показать».
Это ещё не завершённая 0.4; установлен промежуточный выпуск 0.3.4 (7).

До выпуска остаются защита предмета под текущим контактом, ограничение всей фоновой
работы и измерения касания до показанного кадра. MCP-ответ на несколько источников
ещё адресует запись указания, а не отдельную ссылку внутри неё. Поиск и карточки
ходов пока не имеют миниатюр; конкретные сохранённые доработки требуют общего
человекочитаемого представления для приложения и MCP. Точная региональная
квитанция готовится на Mac; iPad без неё честно показывает ожидание проверки.
Навык обновлён под сохраняемые контексты; новая MCP-сессия и согласованная
установка проверены для промежуточного выпуска. Финальная установка 0.4 и
30-минутная физическая приёмка следуют после завершения оставшихся контрактов.

В исходном физическом цикле Амир подтвердил фризы при перемещении камеры и зуме.
Успех проверок Simulator не является доказательством устранения этих фризов.

Первичная запись Instruments не содержит процесса Notebook; адресное
подключение к PID, полученному от устройства, также было отвергнуто профайлером.
`.build/notebook-0.4-baseline/baseline-result.json` фиксирует эту непригодность,
а не нулевое число фризов. До принятия производительности нужна новая запись
с подтверждёнными кадрами самого приложения.


## Пакетная композиция

`notebook_place` принимает одну поверхность, её `expected_revision`, до 32
новых `items` и до 32 явно `movable` предметов либо элементов. Каждый новый
элемент имеет ID, размер и направление. `relative_to` называет исходник,
а `relative_to_id` — предшествующий результат этого же пакета. Вся композиция
получает один согласованный снимок каталога, контекста, геометрии и чернил.
Сначала расчёт сохраняет существующие положения. Только если весь пакет так
не помещается, он пробует переставить перечисленные объекты. Область поиска
доски ограничена 2048 × 2048 points относительно возвращаемого `worldOrigin`;
лист и обложка используют свой физический размер. Стопка остаётся целой: её
участник не становится независимо перемещаемым через расчёт.

Готовый ответ содержит `placements`, необходимые операции `moves`, `expected`,
`contextID` и `additionalOwners`. Ни один из этих результатов сам не изменяет
содержание. Если весь пакет не помещается, ответ `placement_unavailable` имеет
пустые результаты и предложение другого места. `snapshot_pending` означает
ожидание окончательных чернил, а не свободный лист.

`notebook_apply` передаёт `context_id` и при необходимости `additional_owners`.
Core под тем же файловым замком проверяет разрешённый состав перемещения,
версии владельцев и `sourceRevision`. Прямой вызов записи не обходит область
разрешения расчёта. Регион разрешает элементы, пересекающие его; ссылка на лист
или блок документа разрешает перенос их физического носителя. Новые элементы
одного хода принадлежат этому ходу и могут быть упорядочены в том же пакете.

Проверки этого среза: 132 Core-теста, 28 MCP-тестов и настоящий stdio-сценарий
пакета, версии, контекста и отмены. Нативные тесты Mac и iPad прошли.
Квитанции: `.build/composition-core-tests.log`, `.build/composition-mcp-smoke.log`,
`.build/composition-mac-tests.log` и `.build/composition-ipad-tests.log`.
Это изменение ещё не входит в установленную 0.3.4.

## Приоритет активного ввода

`NotebookInputGate` расширяет прежнего владельца Pencil: один пассивный наблюдатель
оконной сцены учитывает контакт пальцев, не забирая жест у камеры, страницы или
интерактивного элемента. Окончание ввода ждёт всех контактов и сериализации
текущего листа. Старое завершение не может отпустить уже начавшийся новый ввод.

`NotebookInputActivity` передаёт занятых физических владельцев существующей
связью. Core проверяет их под файловым замком перед применением и отменой.
Bridge и нативная отмена ждут вне замка не более четырёх секунд, перечитывая
маленькое состояние ввода, а не весь рисунок. Новый проход вновь проверяет все
версии. Ответ `input_active`, `status: pending`, `acceptance: not_saved` означает,
что запрос **не сохранён и не поставлен в скрытую очередь**: агент повторяет тот
же пакет после касания. Уже сохранённая квитанция доступна без ожидания.

Занятая доска консервативно защищает свои предметы и вложенные поверхности;
другая независимая доска остаётся доступной. Потеря связи снимает удалённый
временный барьер. Пакет, пересёкшийся с началом контакта или переподключением,
iPad удерживает до локального завершения. Ожидающие пакеты объединяются в один
причинный срез, а не в растущую очередь сообщений. Приём и подтверждение доставки
происходят после слияния с человеческой доработкой. После перезапуска неполученный
пакет приходит заново вместе с сохранённой историей отправителя.

Mac-публикатор отменяет текущую подготовку при получении активного ввода;
страницы, текущий вид и целевые снимки снова готовятся после его завершения.
Квитанция готового снимка дополнительно проверяет отсутствие активного ввода.
Контакт хранится в `runtime/input.json`, вне наблюдаемого журнала содержания.

`InputFrameMonitor` на iPad связывает контакт с ограниченным окном из 4096
интервалов CADisplayLink. До 64 итогов сохраняются вне главного потока в
`runtime/input-frames.json`; очередь записи удерживает только последний
необработанный итог. Запись содержит режим, номер сборки и времена, без текста,
изображений или координат рисунка. Это частота обслуживания главного потока,
**не доказательство GPU-показа и не измерение всей подготовки кадра**.
`ContactToCommit` отмечает этот же период в системной трассе.

Проверки среза проходят ожидание без частичной записи, новый конфликт после
отпускания, адресацию владельца, повтор квитанции, отмену, слияние удерживаемых
пакетов и ограничение памяти диагностического окна. Нативный тест проверяет
неперехватывающий наблюдатель и сохранение человеческого продолжения после
касания. Фактическая плавность физического iPad остаётся отдельной приёмкой:
USB-запись Instruments 5 сентября зависла при завершении и не экспортируется.
Её нельзя использовать как исходное измерение или как доказательство улучшения.

Изолированный срез ввода проверен отдельно от параллельного изменения ручки:
136 Core-тестов, 28 MCP-тестов, новый stdio-путь ожидания и нативный набор Mac.
Четыре нативные проверки ввода и три UI-сценария проходят панорамирование с
обложки, щипок и различающееся содержание страниц документа.
Квитанции: `.build/input-isolated-core-tests.log`,
`.build/input-isolated-mcp-smoke.log`, `.build/input-isolated-mac-tests.log`,
`.build/input-gesture-tests.log`. Установленное приложение пока остаётся 0.3.4.


## Общая ручка агента

`appendInkStroke` добавляет один нативный штрих в `PageInkDrawing` листа либо
`SpatialInkJournal` доски/обложки. Ручка человека и агента получает один
`SpatialInkSample` и один Metal-рендерер. Документ поддерживает такую ручку на
обложке; его печатный поток остаётся потоком блоков, не холстом чернил.

Пример операции внутри `notebook_apply` (UUID и версии берутся из чтения владельца):

```json
{
  "kind": "appendInkStroke",
  "target": { "kind": "page", "id": "UUID листа" },
  "values": {
    "width": 4,
    "opacity": 1,
    "color": { "red": 0.1, "green": 0.25, "blue": 0.7 },
    "points": [
      { "x": 80, "y": 100 },
      { "x": 180, "y": 180, "width": 2, "opacity": 0.5 },
      { "x": 300, "y": 100 }
    ]
  }
}
```

- Операция получает UUID штриха; если `id` пропущен, MCP устойчиво выводит его
  из `action_id` и индекса операции. Повтор запроса не добавляет вторую линию.
- `expected.revision` остаётся `agentRevision` листа или `boardRevision` доски.
  Для ручки дополнительно обязателен `expected.inkRevision`: `drawingRevision`
  листа либо `spatialInkRevision` доски/обложки. Созданный в том же пакете
  владелец ещё не требует отдельной исходной версии.
- Координаты и ширина заданы в физических points владельца. На доске
  `values.worldOrigin` обязателен: каждая точка является смещением от этого
  плиточного адреса. На листе и обложке он отсутствует; весь след, включая
  половину толщины по краям, должен помещаться в бумагу.
- По умолчанию ширина 2, непрозрачность 1, цвет обычной чёрной ручки.
  Ширина положительна и не больше 128; компоненты цвета и непрозрачность —
  от 0 до 1. Один штрих содержит 1–8192 точки, весь ход — не более 100000.
  Соседние точки соединяет обычная геометрия ручки; кривую агент задаёт
  последовательностью её точек. Ластик агенту этой операцией не предоставляется.
- Один пакет проходит проверку до записи. Активное касание, неверная версия,
  занятый UUID, невозможная область или неверная точка не оставляют часть рисунка.

Нативный архив листа сохраняет последовательность и признак активности каждого
штриха. Независимые добавления сходятся по порядку и UUID; отмена оставляет
неактивную запись, которую не оживляет старый пакет. Старый нативный архив
получает порядок из прежнего массива, сохраняя точки. Импорт или явная замена
архивной основы PencilKit остаётся сменой всей основы по `drawingStamp`.
Человеческая отмена хранит UUID контакта, поэтому поздний агентский штрих
не исчезает вместе с ним. Агентская отмена также не откатывает рисунок целиком.

Квитанция хода связывает результат с версией чернил. «Показать» получает область
реального следа, а iPad проверяет эту версию перед подтверждением показа.
`notebook_render` и карта рукописи используют те же окончательные пиксели;
текущая камера человека не меняется. Проверки: `AgentInkTests`,
`AgentInkRenderingTests` и `MCP/test/agent-ink.test.ts` проводят штрих через
сохранение, слияние, stdio MCP, составной PNG и отмену.

## Отзывчивое чтение общей истории

Открытие «Общего фрагмента» показывает сохранённые описания сразу. Строка
больше не вызывает сериализацию содержимого или чтение файлов. Один
`CollaborationReadSnapshot` получает неизменный срез модели, готовит нужных
владельцев по одному разу и возвращает ссылки на результаты, проверку исходников
и доработки через те же правила Core. Ненужные листы с чернилами не кодируются.
Источники результатов заново разрешаются после изменения содержания или положения;
прежний бесконечный кеш результата по ID хода удалён.

`NotebookAppModel` инвалидирует эту временную проекцию при изменении её входных
владельцев. Чтение строки сравнивает одно поколение, не сканируя дерево и не
вычисляя хеши. Подготовка работает вне главного актора; новая задача сначала
завершает отменённую, а результат принимается только для всё ещё текущего
поколения и вне активного ввода. Пока данные готовятся, интерфейс сообщает
о проверке, а не о свежести источника. Проверка регионального отпечатка читает
маленькие готовые квитанции по уже вычисленной ревизии: двухсекундный опрос
больше не блокирует запись камеры файловым замком всего рабочего пространства.

Исходное физическое свидетельство 0.3.5: USB-квитанция
`.build/ipad-0.3.5-input-frames.json` содержит разрыв обслуживания 539 мс и
контакт длительностью 6326 мс с семью межкадровыми интервалами. Последняя запись
показывает ограничение прежнего измерителя: он не учитывал ожидание первого
кадра и время после последнего. `InputFrameMonitor` теперь сохраняет обе границы
и даже контакт без кадров. `runtime/collaboration-ui.json` отдельно хранит до
32 измерений от нажатия истории до её монтажа. Это не время GPU-показа и не FPS;
записи содержат лишь время, тип и сборку, без содержания источников.

На копии 31 листа, 8 ходов и 15 ссылок прежняя подготовка только доработок
