# Владение взаимодействиями

Владельцы текущего ремонта; результаты по сборкам — в [verification](verification.md).

## Решения и границы

| Действие | Приём и состояние | Установка и завершение |
|---|---|---|
| Панорамирование → щипок | `NotebookInputGate` хранит маршрут контакта и единственный navigation claim; recognizer сообщает намерение | Передача синхронно отменяет прежнего владельца. Позднее освобождение старого claim не затрагивает новый. Программа сохраняет собственную пару; пара через границы программы передаётся камере вместе с отменой начатого WebKit-нажатия. |
| Камера / открытие / возврат | `WorkspaceCameraOwner` владеет подготовкой, жестом, переходом, подпиской готовности и ожиданиями; `SceneCameraSettlement` хранит текущую позу и цель | Clock публикует фактические позы. Completed/cancelled/superseded/failed освобождают callback; новый контакт начинает с установленной позы. Замена движения не публикует промежуточный idle; проснувшийся подписчик проверяет текущего владельца. Ошибка подготовки завершает операцию; retry создаёт новую. |
| Перелистывание | `IPadPageTurnController.Operation` удерживает исходный и целевой host/UUID, материал и completion | Кадры двух страниц запрашиваются параллельно в одной отменяемой операции. Curl сообщает физический endpoint. Только controller выбирает landing. Удалённая цель не превращается в страницу, занявшую её индекс; отмена сохраняет существующий источник. |
| Первый штрих | `InkCanvasView` сохраняет идентичность незавершённого первого reveal независимо от content revision | GPU completion и OS presentation — разные события. Lift/следующий материал не отбирает transactional reveal; retirement или отказ завершают его явно. |
| Смешанное выделение | `NotebookSelectionPresentation` хранит единый desired/presented cut: материал, изменения объектов, рамка | Геометрия authored hosts проверяется непосредственно перед общей native transaction. Отмена восстанавливает исходный cut; ink owner удерживает транзакционный режим до OS receipt всех видимых плиток. Снятие выделения по его установленным границам не ждёт готовности всей страницы. Ошибка отзывает подготовку целиком, включая ожидающего writer. |
| Холодный документ | `DocumentRenderSession.Opening` владеет запросом, чтением, admission, источником, подготовкой и отменой | Existing session передаёт source в native owner после регистрации page demand. `DocumentPagePreparation` имеет одного производителя на source/page и отдельных отменяемых читателей. |
| Установленная бумага | `DocumentPagePresentationOwner` владеет установленными страницами; `DocumentProgramOwner` — отдельным исполнением/фокусом/checkpoint | Capturable material не требует окна. Live/input требует канонической геометрии установленного host. Бумага не ждёт интерактивности соседней программы. |
| Изменения и доставка | `NotebookPersistenceQueue` сохраняет FIFO принятых изменений; Core проверяет затронутый scope | `NotebookPeerPublication` владеет remote contact, ancestry lookup, подписками и отменой. Доставка остаётся после принятой записи. |

## Что удалено

- Отдельные mutable navigation/content-gesture флаги и выполнение анимации из `SpatialWorkspaceView`.
- Опрос готовности камеры через display confirmation и 40 ms опрос её покоя.
- 60 ms / 8 s цикл поиска страницы по ссылке: теперь события layout/live и завершения камеры.
- 5 ms опрос установки документа: `DocumentPagePresentationOwner` фиксирует событие готовности канонической бумаги и её ввода; ошибки подготовки завершают запись измерения.
- Независимое завершение curl, controller и старые тестовые delegate-вызовы в обход операции.
- Обнуление первого reveal при любой смене содержимого; переключение ordered cut в обычный показ до его OS receipt. Пустой следующий материал также ждёт эту границу.
- Отдельные desired/shown edits/frame поля выделения; расчёт authored pose до ожидания drawable.
- Opening request/read/task/preparation поля и retry-процесс из AppModel.
- Четыре коллекции peer-состояния, lookup/cancel/wait процесс из AppModel.
- Глобальное ожидание любого local/peer контакта перед адресной командой Core.
- Рекурсивные `lazy.compactMap(...).first` в проверках: поиск повторял найденную ветку и сам блокировал главный поток. Прямой обход посещает каждый узел один раз.

FIFO перед lookup ancestry сохранён: уже принятый перенос carrier должен быть записан до проверки его предков. Scope остаётся физической страницей/carrier/веткой доски, а не отдельным элементом. Неизвестные предки не считаются доказательством независимости.

Двухсекундный отказ ожидания обязательного хоста выделения сохранён для случая, когда host вообще не смонтировался и не может прислать unregister. Он вызывает тот же terminal failure, что отмена и исчезновение host; подготовка после отказа установиться не может.

## Страница и её материал

`NotebookPagePreparationWindow` владеет конечным адресным окном, чтением и
подготовкой страницы по UUID. Принятый workspace/header допускает подготовку
текущей бумаги до композиции сцены; запись стартового присутствия её не блокирует.
Native host заимствует того же владельца через `PageTurnReadiness`. Reorder
меняет адрес сохранившегося UUID; удаление и terminal withdrawal завершают работу.
У каждой тетради своя очередь пассивных растров. Mac и доска используют локальное
время жизни подготовки; ранний запуск окна относится к iPad.

Фактический reader и pending destination камеры имеют разные сроки жизни.
Cover progress 0 сохраняет уже принятый reader при удержании/развороте pinch;
неподвижная закрытая обложка сама его не запускает. Pending reader принадлежит
существующему UUID жеста/settlement. Его завершение не отзывает новую операцию.
Composition callback только использует принятый demand. Native window callback
проверяет существующий controllerID: старый host не восстанавливает закрытое
окно и не отзывает заменившее его. Terminal board/другой reader освобождает
исполнение, даже если UIKit ещё удерживает исходный host.

`PreparedAgentElementPreparationOwner` хранит задачу, WK, растр, readiness и ошибку.
View устанавливает результат и меняет demand. Публикация исходника достигает
владельца без mounted consumer; state сохраняет runtime, новый source отзывает
token. Владелец создаёт `AgentWebNativeSession` после grant, до SwiftUI mount;
representable получает тот же WK/coordinator. Consumer и owner проверяют взаимную
идентичность: поздний detach не отзывает новую установку. Retirement отменяет
admission и native installation; coordinator завершает принятый checkpoint,
удерживая ресурсы отправленных captures до физического completion.

Готовность бумаги/input, материала для capture, native installation и OS presentation
различны. Пустая текущая бумага устанавливает прозрачный кадр и сохраняет pool до
смены роли/reclamation. Ранний контакт заменяет только незавершённый пустой кадр.
Соседняя пустая бумага готова логически без drawable. Перелистывание требует
полного материала; открытие бумаги не ждёт соседнюю программу.

`PageTurnActivity` хранит адресные native providers по source/owner. Runtime и
временный растр сосуществуют при передаче; установленный runtime приоритетен.
Его уход выбирает установленный растр. Поздний loss прежнего token не отзывает
новый. Неизменный layout не инвалидирует страницу; получение материала повторно
проверяет фактическую установку. Состояние curl исключено из `ItemPlaneRevision`.

`PageTurnMaterialOwner.FramePreparation` — один производитель пассивного соседнего
кадра с ключом page/material/source/provider/ink. Письмо на текущей странице его
не запускает. Принятый turn присоединяется и повышает приоритет; отмена читателя
завершает только его ожидание, отмена owner — всех читателей и производителя.
Замена основы отзывает результат; временная потеря установки сохраняет неизменные
входы. Reclamation подавляет повторную подготовку той же версии. Только отказ
памяти допускает одну input-композицию после проверки основы. Живой DOM/CSS
захватывается заново; кеш не удерживает ink lease.

Готовый `RasterLease` без преобразований заимствуется синхронно. Живые captures
начинаются на MainActor владельца до первого ожидания. Пара страниц принадлежит
одной операции; acquisition зарегистрирован до `Task.immediate`, поэтому раннее
завершение не очищает следующую задачу. Core Image/CPU encoding работают у
исполнителя; GPU callback напрямую завершает ожидание. Отмена после отправки
запрещает публикацию, удерживая пиксели и reservation до fence. Преобразования
ограничены четырьмя одновременными работами.

`PageRasterPreparation` допускает невидимых соседей после первой установки
текущего содержимого. Локальное изменение программы не закрывает барьер заново.
Принятая цель приоритетна; новые посторонние задания ждут, отправленные captures
завершаются. До двух браузерных оболочек живут только при наличии потребителей;
пустая очередь освобождает их, отмена завершает продолжения.

## Камера, curl и выделение

Камерная команда ограничивает цель существующей бумагой до принятия движения.
Неизменная допустимая цель не создаёт pending/clock/запрет ввода. Навигация
по-прежнему готовит адресную страницу; равные позы завершаются после подготовки.
При замене движения нет промежуточного idle. Новый жест получает установленную
позу; deferred callback проверяет текущую операцию.

Curl связывает GPU/OS callbacks с UUID операции, поколением и sequence.
`SheetCurlMetalView` использует один `UIUpdateLink`: released motion кодируется
после планирования update, контакт — после dispatch. Перед CA commit публикуется
scheduled drawable; scheduling fence ограничен 1 мс и текущим deadline,
GPU completion на main не ожидается. Первый transactional reveal сохраняется
до OS outcome; затем непрозрачные кадры публикуются асинхронно тем же clock.
Новый контакт берёт OS-показанную позу и отзывает ещё не опубликованную будущую.
Endpoint требует receipt своей операции. Неподвижный контакт останавливает clock.

Страничный output — отдельный `CAMetalLayer` внутри существующего view.
Его размер, pool и публикация принадлежат рендереру; MTK backing обслуживает
обложку. Terminal outcome сразу скрывает точный старый output, а его удаление
и освобождение памяти ждут GPU fence и acquisition drain. Поздний callback
не меняет слой следующей операции.

Page shader заполняет каждый пиксель. Три drawable разделяют показываемый,
ожидающий и подготавливаемый кадр; все учитываются в reservation. GPU in-flight
ограничен двумя. Один фоновый `nextDrawable` удерживает допуск до возврата:
отмена не позволяет менять pool или начать следующий запрос раньше drain.
Terminal outcome освобождает reservation после GPU fence и acquisition drain,
независимо от времени жизни Metal callbacks. Cover сохраняет отдельный прежний путь.

При отмене смешанного выделения `SourceRestoration` устанавливает исходные
чернила, объекты и рамку одним cut. Общая проекция до установки сохраняет последний
показанный cut. Параллельные `retiringBodies` и раннее снятие raw suppression
удалены. Адресный witness проверяется перед приёмом; отказ allocation/encoding
возвращает прежнее состояние и завершает ожидание ошибкой. Следующее изменение
канонического источника восстанавливает demand. Первый ink reveal и ordered cut
удерживают transactional режим до OS receipt всех затронутых видимых плиток.

## Программы, документы и локальные изменения

Программа сообщает готовность после fonts/images, author readiness, input regions
и принятого состояния. Native owner проверяет token/error и раскрывает слой до
сообщения установки. Ready до mount не означает показ. Дублирующие запуск из
`didFinish`, передача первого готового state через пустую MainActor-задачу и
внешняя SwiftUI opacity удалены. Последующие state-публикации объединяются с
проверкой актуальности. Turn и checkpoint получают независимые свежие captures.

Allocator ограничивает две ожидающие native-конструкции WebKit. Конструкция или
retirement освобождает grant; navigation/author readiness не блокируют соседей.
У каждой программы собственное хранилище, общий лимит и время жизни.
`NotebookProgramStateEncoding` кодирует inline до 64 узлов/4096 байт оценки;
крупное состояние, нехватка памяти и bundle сохраняют отменяемый async путь.
Encoder, FIFO/reservation и source/token проверки общие. Static SVG сохраняет
браузерную оболочку и заменяет DOM без program bridge; новый рисунок получает
новый token, смерть процесса отзывает оболочку.

`SceneCompositionSource` хранит до 96 проекций одного проверенного source cut.
Геометрия/стирания читаются адресными пакетами с проверкой каждого пакета и
публикации. Установка уже допущенного runtime сохраняет композицию; новый pin
требует admission. Поздний `WorkspaceSceneIndex` использует тот же полный reuse
predicate: catalog, board sources, размеры бумаги. Идентичный источник сохраняет
поколение и page lookup; UUID фоновой задачи не запускает повторную композицию.

Durable cursor сам не пересоздаёт сцену. Ограниченный интервал изменений только
в телах открытых страниц прежнего размера обновляет страницы и validation cursor
текущего cohort; plan, paint identity, native ink и растры сохраняются. Изменение
состава/размеров/доски, неизвестная запись и неполная история требуют подготовки.
Cursor пикселей отделён от проверки тел. Attention принимает страницу только от
текущего owner с точным свидетельством установки.

`PageDocument.replaceProgramState` меняет один state и причинные версии;
`PageElementProjection` сохраняет геометрию графа. Полная сериализация объектов
через `replaceElements` удалена из этого пути. Source basis, адресная команда и
FIFO writer сохранены. Peer admission ждёт затронутое взаимодействие; FIFO перед
ancestry lookup сохраняет порядок уже принятого переноса carrier.

TeX execution хранит counters/stack floor/call depth в контексте импорта;
горячие TLS lookup удалены при сохранённых проверках памяти, глубины и отмены.
Runtime владеет неизменными format/font bytes в прежнем лимите 64 МиБ. Компиляция
заимствует их; её `ResourceCache` ограничен 8 МиБ/256 entries одного bundle,
освобождает неоткрытые файлы при нехватке памяти и весь кеш по завершении.
Копия 24 МиБ format и повторная распаковка entry удалены; междокументного кеша нет.

## Проверка и незавершённые условия

Результаты, установленная пара и команды — в [verification](verification.md).
Описание текущего кода не подтверждает его задержку или доставку. История
заменённых реализаций остаётся в git и адресных audit-evidence.

Время фиксируется у input, preparation, native installation, submission/GPU и
OS presentation. Скриншот/readback/DOM probes выполняются отдельно и не входят
в скорость приложения. Native installation не объявляется показом; CADisplayLink
не измеряет FPS. Native Pencil fixture проверяет установленный recognizer, но
не аппаратную доставку/coalescing/prediction Pencil.

Mixed selection проверяет общий submission/revision и его OS receipt, затем
отдельный снимок чернил, объектов и рамки. `drawHierarchy(false)` не имеет
идентичности compositor-кадра; mixed readback не доказывает mixed screen. Промежуточную
экранную согласованность проверяет системная запись. Native24 фиксирует landing
в callback владельца, curl — по OS receipt, без обхода 24 runtime в callback.
Документ измеряет установку бумаги/input независимо от программ.

Строгие задержки первого curl и холодной установки программ остаются отдельными
условиями до проходящего физического измерения. Полная длительная приёмка не
становится PASS от реорганизации владельцев или прохождения локальной регрессии.
