# Владение взаимодействиями

Владельцы текущего ремонта; результаты по сборкам — в [verification](verification.md).

## Решения и границы

| Действие | Приём и состояние | Установка и завершение |
|---|---|---|
| Панорамирование → щипок | `NotebookInputGate` хранит маршрут контакта и единственный navigation claim; recognizer сообщает намерение | Передача синхронно отменяет прежнего владельца. Позднее освобождение старого claim не затрагивает новый. Программа сохраняет собственную пару; пара через границы программы передаётся камере вместе с отменой начатого WebKit-нажатия. |
| Камера / открытие / возврат | `WorkspaceCameraOwner` владеет подготовкой, жестом, переходом, подпиской готовности и ожиданиями; `SceneCameraSettlement` хранит текущую позу и цель | Clock публикует фактические позы. Completed/cancelled/superseded/failed освобождают callback; новый контакт начинает с установленной позы. Замена движения не публикует промежуточный idle; проснувшийся подписчик проверяет текущего владельца. Ошибка подготовки завершает операцию; retry создаёт новую. |

Curl сообщает физический endpoint. Только controller выбирает landing. Удалённая цель не превращается в страницу, занявшую её индекс; отмена сохраняет существующий источник. |

Live/input требует канонической геометрии установленного host. Бумага не ждёт интерактивности соседней программы. |

## Что удалено

- Отдельные mutable navigation/content-gesture флаги и выполнение анимации из `SpatialWorkspaceView`.
- Опрос готовности камеры через display confirmation и 40 ms опрос её покоя.
- 60 ms / 8 s цикл поиска страницы по ссылке: теперь события layout/live и завершения камеры.
- 5 ms опрос установки документа: `DocumentPagePresentationOwner` фиксирует событие готовности канонической бумаги и её ввода; ошибки подготовки завершают запись измерения.
- Независимое завершение curl, controller и старые тестовые delegate-вызовы в обход операции.
- Обнуление первого reveal при любой смене содержимого; переключение ordered cut в обычный показ до его OS receipt. Пустой следующий материал также ждёт эту границу.
- Отдельные desired/shown edits/frame поля выделения; расчёт authored pose до ожидания drawable.
- Opening request/read/task/preparation поля и retry-процесс из AppModel.
- Четыре коллекции peer-состояния, lookup/cancel/wait процесс из AppModel.
- Глобальное ожидание любого local/peer контакта перед адресной командой Core.
- Рекурсивные `lazy.compactMap(...).first` в проверках: поиск повторял найденную ветку и сам блокировал главный поток. Прямой обход посещает каждый узел один раз.

FIFO перед lookup ancestry сохранён: уже принятый перенос carrier должен быть записан до проверки его предков. Scope остаётся физической страницей/carrier/веткой доски, а не отдельным элементом. Неизвестные предки не считаются доказательством независимости.

Двухсекундный отказ ожидания обязательного хоста выделения сохранён для случая, когда host вообще не смонтировался и не может прислать unregister. Он вызывает тот же terminal failure, что отмена и исчезновение host; подготовка после отказа установиться не может.

## Пассивный кадр страницы — 218

`PageTurnActivity` версионирует установленный provider отдельно от типа исходника:
готовый растр или исполняемый runtime. `PageTurnMaterialOwner` по событиям
готовит только соседний пассивный кадр, с ключом page/material/source/provider/ink.
Письмо на текущем листе не запускает эту композицию. Замена основы и retirement
отменяют производителя; reclamation освобождает кадр и подавляет повторную
подготовку той же версии. Само завершение кеша не изменяет source revision.

Принятый переход присоединяется к тому же passive producer. Только отказ памяти
разрешает одну временную input-композицию в отменяемой задаче перехода, после
повторной проверки основы. Живой DOM/CSS захватывается заново. Кеш не удерживает
ink lease; weak texture identity исключает повторное использование адреса.
Готовность бумаги и её ввода не зависит от наличия кеша.

Повторный layout того же provider больше не публикует изменение всей страницы.
`PageTurnActivity` сообщает замену материала и переход доступности; повторную
проверку всех соседних объектов на каждый неизменный `updateUIView` удалили.
Фактическая установка проверяется при заимствовании, сохранённая доступность
служит только для обнаружения события. Готовые слои читаются непосредственно
у владельца, без повторного ожидания уже завершённой задачи.
Потеря окна и возврат публикуются native owner; отрицательное событие прежнего
растра не может отозвать следующий runtime. Временная неготовность сохраняет
уже заимствованные неизменные входы и готовый кадр; получение кадра требует
актуальной установки и повторной проверки полной основы.

Состояние curl удалено из `ItemPlaneRevision`: начало и конец перелистывания
больше не заменяют корень всей сцены и не вызывают её синхронный layout.
Ограничения ввода остаются у native page controller и владельца камеры.

Свежий runtime cut завершается прямо в MainActor callback WebKit, без второй
постановки каждого снимка в очередь. `PageTurnFrame` передаёт неизменные входные
пиксели отдельному исполнителю Core Image; владелец резервирует память и принимает
результат. Отмена до кодирования останавливает работу, после его начала — дожидается
GPU fence без публикации. Пиксели и их бюджеты удерживаются до этой границы.

Curl связывает GPU/OS callbacks с UUID операции и sequence. Повторное использование
того же кадра не делает callback отменённого перехода актуальным. В диагностическом
режиме время фиксируется у request, display callback, encoding и GPU; OS receipt
остаётся отдельным событием. Анимация и прежние пределы не сокращены.

## Подготовка содержимого и отмена — 219

Страница и curl сохраняют один системный clock на время жизни native owner.
Операция определяет актуальность GPU/OS callbacks; завершение по-прежнему
требует настоящего OS receipt. Отброшенный drawable завершает свою попытку,
но не считается показанным содержимым. Дополнительные pump, bootstrap и
очередь публикаций удалены после выявленной физической регрессии.

Текущая видимая пустая бумага устанавливает прозрачный кадр через тот же clock
при открытии и сохраняет допущенный pool до смены роли или reclamation. Ранний
контакт заменяет только пустую незавершённую попытку. Соседняя пустая бумага
сохраняет логическую готовность без drawable. Прогрев текущей бумаги не отзывает
уже принятую готовность прозрачного содержимого; поздний callback завершает только
свою попытку и не затрагивает новый контакт.

При отмене смешанного выделения `SourceRestoration` один устанавливает исходные
чернила, объекты и рамку. Общая проекция страницы до этой установки сохраняет
последний показанный cut. Параллельная подстановка `retiringBodies` и раннее
снятие raw suppression удалены: они отменяли частную подготовку восстановления
и отпускали объекты раньше соответствующего GPU-материала. Адресный witness
проверяется внутри отложенной задачи перед приёмом cut. Отказ allocation или
encoding возвращает предыдущее состояние и завершает частное ожидание ошибкой.
Следующее изменение канонического источника владеет восстановлением спроса.

Живая программа сообщает готовность из своего документа после fonts/images,
author readiness, input regions и принятого состояния. Native owner проверяет
token и terminal failure. Дополнительный вызов запуска из `didFinish` удалён.
Пассивный снимок создаётся только по спросу представления; принятые turn и
checkpoint по-прежнему получают собственный свежий cut. Их отмена независима.

При перекрытии WebKit и временного изображения `PageTurnActivity` сохраняет
два адресных native-кандидата одного source/owner. Установленный runtime имеет
приоритет; его уход выбирает уже установленный растр без повторного layout.
Callback несёт фактический тип материала. Поздний loss прежнего token не отзывает
новый; terminal withdrawal освобождает borrow до очистки callbacks. В board cohort
те же два слабых native receipt защищают установленное содержимое. Последний
случайный callback больше не выбирает владельца страницы.

Для доказанно статического SVG браузерный исполнитель сохраняет оболочку и
заменяет DOM вместо повторной навигации и запуска программного bridge. Каждый
рисунок имеет новый token; снимок принадлежит точному источнику. Шрифты и
геометрия остаются у WebKit. Смерть процесса отзывает оболочку целиком.

Измерение контакта связывает source/revision, render/deadline, submission/GPU и
OS receipt; без подписчика дополнительные измерения не создаются. Cold source
фиксируется событием native installation, а диагностические снимки и DOM-запросы
идут после замера. Native installation не объявляется показом на экране.
Undo/redo связывает exact OS receipt с отдельным чтением принятого GPU-материала.
Native runner не вызывает системный screenshot; композицию экрана проверяет UI
runner. UIKit `drawHierarchy` мог пропускать Metal уже показанного кадра.


Бумага публикует `paperReady` отдельно от полного содержимого и curl cut.
Открытие не ждёт запуска программы; перелистывание требует полного материала.
Native WebKit раскрывает свой слой до сообщения установки, без внешнего
SwiftUI opacity и зависимости от случайного следующего layout.

Allocator допускает две ожидающие native-конструкции WebKit. Завершение
конструкции или retirement освобождают grant; remote navigation и author
readiness принадлежат программе и не задерживают создание соседей. Работающие
программы сохраняют независимые хранилища, общий лимит и собственное время жизни.

`SceneCompositionSource` хранит до 96 проекций в пределах одного проверенного
source cut. Планирование и рендер читают геометрию и стирания адресными пакетами;
каждый пакет и окончательная публикация проверяют исходник. Установка уже
допущенного runtime сохраняет текущую композицию. Новый пользовательский pin
по-прежнему требует допуска.

`PageRasterPreparation` начинает невидимые соседние программы после первой
установки содержимого текущего host. Локальное изменение программы не закрывает
этот барьер заново. Принятая цель допускается сразу и приостанавливает выдачу
новых заданий посторонних страниц; отправленные captures завершаются.
До двух оболочек живут только пока существуют ожидающие потребители; отмена
завершает их продолжения, пустая очередь освобождает оболочки.
`ElementFrameAcquisition` различает готовый `RasterLease` и асинхронный свежий
cut runtime. Растр без crop и преобразования заимствуется синхронно при любом
приоритете до создания задач; полностью растровая страница не создаёт task group.
Ключ, время жизни и отзыв native borrow остаются у `PageTurnActivity`.
Копирование и преобразования ограничены четырьмя одновременными работами.

`PageTurnMaterialOwner.FramePreparation` хранит производителя, результат и
адресные ожидания. Отмена потребителя завершает только его ожидание; отмена
владельца завершает все ожидания и отменяет производителя. Отправленная GPU-команда
удерживает входы до fence независимо от потребителей. Задача очищается при
терминальном исходе; принятый переход повышает приоритет существующего производителя.
Временная потеря установки не перезапускает его. Замена source/provider и retirement
сохраняют отмену, а получение кадра проверяет полную установленную основу.

TeX execution хранит poll counter, native stack floor и call depth у своего
импортного контекста. Горячие TLS lookup удалены из generated prologue/epilogue;
границы памяти, глубины, отмены и все проходы TeX сохранены.

## Проверка

Сначала реализован связанный срез, затем выбранный физический прогон: первый reveal, передача контакта и прерывание камеры, UUID reorder/deletion, готовность соседней страницы, cold source/geometry, mixed cut/undo/reopen, scoped peer admission и отмена. Последующие проверки относятся к выявленным разрывам и пропущенным сценариям.

Отмена выделения проверяет единственную native-установку общего cut и OS receipt
того же submission/revision; до receipt снимок не выполняется. После него первый
снимок отдельно проверяет чернила, объект и рамку. Исторический pre-OS
`drawHierarchy(false)` не имеет идентичности compositor-кадра: смешанный readback
не доказывает смешанный экран. Проверка общего экранного перехода остаётся у
системной записи, а capture/decode не включается в скорость приложения.

Native24 фиксирует landing в terminal callback владельца, curl — отдельно по OS receipt. Обход 24 runtime убран из измеряемых callbacks. Документ фиксирует native paper/input в принимающем событии, независимо от программ; это не OS presentation. Подробные WebKit probes остаются диагностическим режимом, который добавляет обращения к браузеру. Избыточный синхронный снимок после проверки геометрии reopen удалён; системный UI-сценарий сохраняет отдельную проверку изображения.

Точные команды, результаты и установленная пара фиксируются в [verification](verification.md). Предыдущие незакрытые строгие задержки и полная длительная приёмка не становятся PASS от реорганизации владельцев.

При передаче контактов распознаватель читает сохранённый маршрут в `NotebookInputGate`,
не регистрируя заново уже поднятый палец. Native-владелец программы отменяет
только recognizers своего WebKit-поддерева; физические observer и запись сохраняют
свою границу отпускания. Контакты над кнопками наблюдаются до решения gate,
а пара с программой не передаётся curl, который её принять не может.
