# Notebook SDK API v2: JavaScript

Два MCP-инструмента передают сообщения единственному Mac-владельцу.
`notebook_context` читает общую среду и справку; `notebook_execute` запускает
JavaScript или присоединяется к его журналу. MCP-процесс не исполняет код и
не открывает хранилище. `NotebookScriptCoordinator` использует существующую
последовательную очередь записи `NotebookStore`.

## Справка и программа

Справку раскрывайте только при неизвестном контракте: в `notebook_context` передайте `{"method":"help"}`. Тема `operations` даёт
компактный список всех 20 операций. Например,
`{"method":"help","args":{"topic":"operation/createDocument"}}` возвращает
точную схему одной операции. `transaction` содержит полную схему атомарной записи
с общими `$defs`, `examples` — примеры, `interactive` — встроенную программу с
готовностью, `execution` — цикл чтения результата. `nativeText` описан в
`operation/insertElement`. Внутри программы та же справка: `await nb.help(topic)`.

```json
{
  "op":"start",
  "run_id":"новый UUID",
  "api_version":2,
  "code":"const p=await nb.page({id:args.pageID}); await emit({id:p.data.id,basis:p.basis});",
  "args":{"pageID":"прочитанный UUID листа"},
  "wait_ms":1000
}
```

Код является асинхронным телом JavaScript с `args`, `nb`, `emit` и `emitImage`.
Вызовы SDK возвращают Promise; их нужно ожидать. `Promise.all` разрешён:
SDK держит до четырёх настоящих запросов одновременно. Для одного согласованного
среза используйте `nb.readMany({queries,expectedCursor?})`.

## Адресное чтение

`nb.page({id, elementID})` и `nb.read({kind:'pageElement', id, elementID})`
читают один элемент с заголовком владельца и вычисленной геометрией в одном
SQL-снимке. `pageHeader` и `documentHeader` возвращают только метаданные и
версии; `documentBlock` — один блок с его собственным состоянием и версиями.
Пустой элемент — `null`, отсутствующий владелец — ошибка, не пустая страница.
`appearance:{state:"intact"|"partial"|"erased",sourceIsCompleteAppearance}`
отражает общую с UI геометрию стирания. В адресном чтении авторский элемент
сохраняется даже при полном стирании; `partial` не разрешает считать source
полной видимой картинкой. Для пикселей нужен явный `render`. Неявный `observe`
пропускает стёртое; дельта возвращает `outOfScope`, не удаление авторского объекта.
Отмена стирания вновь возвращает `upsert`. Чернила читаются по индексу цели.
`graphic.connection.routing` поддерживает `straight`, `elbow`, `curved`;
положение, привязки и итоговый путь по-прежнему вычисляет общий граф Core.

`nb.observe({target:{kind:'page',id},elementID})` выбирает точный объект,
независимо от камеры и первых 32 превью. Для документа — `target` и `blockID`.
Без адреса используется опубликованная среда; превью действительно читает
не более `limit` (1–32, по умолчанию 32) элементов и только адресные маски их стирания;
остальные чернила и состояния блоков не декодируются.
`coverage.complete:false` явно обозначает неполноту. Полные `nb.page`/`nb.document`
остаются явными полными чтениями. Все чтения содержания возвращают
`Snapshot<T> {data,basis,coverage,cursor}`. `readMany` возвращает типизированный
кортеж `data` и отдельные `coverages` для каждого запроса в том же SQL-снимке.
В публичном SDK нет `values[0]`. Нативные внутренние IPC-проекции не являются
второй публичной версией SDK.

`ReadBasis {workspaceID,owners}` содержит существующие content/state/source/ink
предусловия владельца. Это данные, не разрешения или новая сессия. Передавайте
`base:snapshot.basis`, либо явный массив оснований. Core детерминированно объединяет
их; разные версии одного владельца дают `basis_conflict`, отсутствующий компонент —
`basis_incomplete` с нужным чтением, другое пространство — `basis_workspace_mismatch`.
Версии перед записью не освежаются. Scope ссылок/контекста/additionalOwners проверяется
независимо: чтение соседа не разрешает его перемещение.

```js
const s = await nb.page({id: args.pageID, elementID: args.elementID});
const result = await nb.transaction("label", {
  base: s.basis, summary: "Изменить подпись",
  operations: [{kind:"updateElement", target:{kind:"page", id:args.pageID},
    id:args.elementID, values:{graphic:{label:"Обратная связь"}}}]
});
await emit(result);
```

`ActionResult {actionID,actionVersion,publication,changed,basis,next?}` сохраняется
в той же нативной транзакции, что содержание и журнал эффекта. Ограниченная страница
`changed` содержит канонические адреса, хеши результата и небольшие новые значения;
крупное значение обозначено `valueOmitted`, а не усечено. `next` читается через
`nb.action({actionID,actionVersion,next})`. Подробные разделы требуют эту же
`actionVersion`. Undo сохраняет новую версию, не переписывая первоначальный результат.
Старую квитанцию без такого свидетельства нельзя выдать за новый точный результат.
`saved`, получение и показ на iPad остаются раздельными; повтор результата не
перепроверяет и не выдумывает текущее состояние устройства.

Декларации `notebook-sdk.d.ts`, входные/выходные JSON-схемы и справка генерируются
существующим `MCP/build-script-services.mjs` из общего машинного контракта.
Типы помогают составлять код; нативная валидация остаётся обязательной. Наличие
деклараций ещё не включает исполнение TypeScript — это отдельный срез compiler-границы.

### Наблюдение и дельты области

`observe` и `read/readMany` с `kind: "observation"` используют один Core-читатель.
Область задают `target`, необязательные `ids` (1–32), `fields`
(`preview`, `content`, `state`, `geometry`) и одношаговый `expand` от явных ids
(`incoming`, `outgoing`, `neighbors`, `container`). Обход рекурсивно не продолжается.
На доске/обложке можно задать `bounds`; геометрическое окно ограничено 256 адресами.
Переполнение даёт `observation_scope_full`, а не незаметно усечённый снимок:
нужно сузить окно либо читать всю поверхность постранично без bounds.

Объекты возвращаются в стабильном порядке адресов, с `change: upsert | deleted |
outOfScope`; исчезновение из связей или геометрического окна не означает удаления.
Геометрия соединения инвалидируется движением/удалением endpoint и изменением
победителя общего ink claim без авторской перезаписи соединения. Неизменное
наблюдение не декодирует тела; `presenceGeneration` имеет отдельный монотонный
сессионный счётчик и не двигает журнал содержания.

`coverage.next` — продолжение неполного чтения. `checkpoint` появляется только
после последней страницы. Они не взаимозаменяемы. Страницы закрепляют workspace,
полную нормализованную область/проекцию/expand и `through` журнала содержания;
межстраничная запись вызывает `observation_cursor_stale`, истёкшая история —
`observation_cursor_expired`. Полного обхода в качестве восстановления нет.
Новая область с `since` получает новый ограниченный snapshot (`reset: scope_changed`).
`next` с другой областью отвергается. Размер страницы можно менять.

```js
const scope = {target: args.target, fields: ["content", "geometry"]};
let page = await nb.read({kind: "observation", scope, limit: 32});
while (page.coverage.next) {
  page = await nb.read({kind: "observation", scope, next: page.coverage.next});
}
const delta = await nb.read({kind: "observation", scope, since: page.data.checkpoint});
```

`observe` возвращает ту же оболочку `Snapshot`: `coverage.next` продолжает страницу,
а `data.checkpoint` — основание нового инкрементального чтения. `cursor` оболочки
остаётся read-cursor, `data.through` — change-cursor; они намеренно разные.
Изображения — только по `includeImage:true`. Раскрытие соседей не расширяет scope.

## Идентичность, вывод и отмена

Fingerprint запуска содержит workspace, API version, точный код и канонические
JSON-аргументы. Повторный `start` с теми же данными присоединяется к существующему
run; другие данные с прежним ID дают `run_id_conflict`.

`resume` принимает `run_id`, `after_seq` и `wait_ms`. Он не проигрывает код и не
восстанавливает JS heap. Состояния: `queued`, `running`, `completed`, `failed`,
`cancelled`, `interrupted`. Ответ содержит `events`, `next_seq`, `has_more`,
`result`, `error` и ограниченные `effects`. Effects возвращают ID, key, method,
fingerprint, state и ссылки на квитанции. HTML, исходные аргументы и код не
повторяются в каждой странице.

Состояние эффекта определяется квитанцией у единственного владельца записи.
`saved` означает сохранённое действие либо принятое задание экспорта;
последующая ошибка компилятора не отменяет сам факт принятия задания.
`notSaved` означает подтверждённое отсутствие записи или остановку до её
отправки. Это окончательный результат данного `key`: повтор возвращает
сохранённую ошибку и не выполняет запрос заново. Для исправленного запроса
нужны новый `key` и свежие версии владельцев. `outcomeUnknown` означает,
что квитанцию нельзя прочитать либо действие было временным показом без
долговечного свидетельства. Ошибка чтения не считается отсутствием записи.
Отдельный индекс незавершённых эффектов читается страницами по 64 адреса;
при запуске Mac они сверяются даже у завершённых JS runs. Код не повторяется.
Явный `resume` старого завершённого run может восстановить отсутствующий индекс
только по его собственным 128 адресам и сверить квитанции. История других runs
не сканируется. Для `running`/`queued` отсутствие квитанции не используется
как доказательство отказа: принятый native command ещё может выполняться.

Перемещение существующей геометрии требует исходных ссылок, покрывающих предмет,
либо его точного владельца в `action.additionalOwners`. Для `moveItem` операция
адресует доску, а дополнительный владелец — `{kind:'cover',id:itemID,boardID}`.
Одна доска в `additionalOwners` не разрешает перемещение её носителей.
Если указан `contextID`, область действия задают сохранённые ссылки этого
контекста; новые `action.references` её не расширяют. Без `contextID` используются
ссылки самого действия. Выбор камерой и `expected` не заменяют эту область.
`nb.help('operation/moveItem')` содержит короткий исполняемый пример; справка
`updateElement`, `reorderElements` и `stackItems` описывает соответствующих владельцев.

`renameItem` адресует **доску, в которой находится предмет**. UUID предмета
передаётся в `operation.id`; его доска читается через
`nb.read({kind:'ownerBoard',id:itemID})`. Его `basis` содержит версии этой доски
и каталога `{kind:'workspace',id:rootBoardID}`. Каталог участвует в проверке
версий, но не является допустимым `operation.target` для переименования.
`nb.help('operation/renameItem')` даёт исполняемый пример с обоими владельцами.

При отказе конкретной операции родная ошибка сохраняет `code` и добавляет
`operation:{index,kind,target,id?}`. `index` начинается с нуля в массиве
`action.operations`, `id` ограничен 120 символами. Адрес доступен на пойманной
JS-ошибке и в `effects[].error`; исходник и `values` не возвращаются.
Отказ отменяет весь ход, в том числе предыдущие операции. Общие проверки хода,
например устаревшая ожидаемая версия, не получают выдуманный индекс операции.

`nb.place` и `notebook_context` с методом `place` используют один нативный
декодер: пропущенные `movable` и `additionalOwners` означают пустые списки.
Для предложения свободного места достаточно target, expectedRevision и items.
Ответ `snapshot_pending` означает подготовку карты чернил, а не размещение
части элементов или разрешение перемещать существующий материал.

Один MCP-ответ ограничен четырьмя секундами целиком: проверка IPC, ожидание
очереди записи, чтение квитанции и получение изображений используют общий срок.
`wait_ms` отсчитывается с входа в Mac handler. MCP оставляет 100 мс для упаковки
ответа и сокращает максимальное нативное ожидание, оставляя время для возврата
по IPC. Поэтому здоровый пустой poll с `wait_ms:4000` может вернуть `running`,
а не неизбежный транспортный тайм-аут. По истечении срока `response_pending` возвращает прежние `run_id` и
`after_seq`; `admission:"unknown"` означает, что допуск пока не подтверждён,
`admission:"confirmed"` — квитанция получена, но ответ, например с изображением,
ещё не собран. Это не состояние программы и не квитанция сохранения.
Продолжите `resume` с теми же ID и cursor. Если получен `run_missing` при
`after_seq:0`, допустим повтор исходного `start` с теми же code и args.
Разрыв сокета не отменяет принятый Mac handler; завершение приложения ждёт
его через существующий IPC drain и очередь записи.

Продолжайте `resume` с `after_seq:next_seq`, пока состояние `queued`/`running`
**или** `has_more:true`. Остановиться можно только при `completed`, `failed`,
`cancelled` или `interrupted` **и одновременно** `has_more:false`.
`running` с `has_more:false` — обычный ответ: текущие события прочитаны, но
программа ещё может сохранять изменения и создавать вывод. Повторный cursor читает
те же события. `cancel` закрывает допуск новых эффектов, останавливает user
worker и сохраняет результат уже принятой нативной записи. Намерение отмены
фиксируется тем же владельцем записи, который завершает run: принятая раньше
завершения отмена даёт `status:cancelled` и `error.code:run_cancelled`, даже если
после неё пришёл успешный ответ либо разрыв XPC. Run, завершённый раньше отмены,
сохраняет свой результат. Терминальное состояние ждёт все принятые effect-вызовы,
включая те, для которых долговечный допуск уже записан, а ответ ещё задержан.
Разрыв MCP не
отменяет run. После перезапуска Mac незаконченные программы становятся
`interrupted` (либо `cancelled`, если намерение отмены уже было сохранено);
эффекты сверяются с нативными квитанциями без проигрывания кода.
Восстановление выполняется до открытия IPC. `context` остаётся чистым чтением.

Срок исполнения пользователя — 30 секунд с начала активного run, включая
запуск XPC sandbox и все ожидания JavaScript. Его отсчитывает Mac, поэтому
зависший до `main` запуск сервиса не может бесконечно удерживать очередь.
Результат такого истечения — `failed` / `script_timeout`; допуск новых SDK
эффектов закрывается, принятые эффекты завершают запись до публикации
терминального результата. Ожидающий в очереди run ещё не расходует этот срок.
Доверенная нормализация имеет собственный срок 8 секунд, компилятор отдельного
PDF job — 120 секунд; оба срока также включают запуск сервиса.
Закрытие Mac ждёт уже допущенные запросы и завершает очередь отменой; поздний
ответ о прежнем состоянии `queued` не может запустить отменённый код.

## Атомарная запись

```js
const p = await nb.page({id:args.pageID});
const saved = await nb.transaction("explanation", {
  summary:"Пояснение на листе",
  base:p.basis,
  operations:[{
    kind:"insertElement",target:{kind:"page",id:p.data.id},id:"explanation",
    values:{kind:"markdown",source:"# Пример",
      frame:{x:20,y:30,width:300,height:180}}
  }]
});
await emit({actionID:saved.actionID});
```

Каждый изменяющий вызов получает устойчивый `key`. ID эффекта выводится из run
ID и key; другие параметры с тем же key конфликтуют. Неизвестный исход не
разрешает повторное исполнение. `nb.id(key)` выдаёт устойчивый UUID заранее.

Одна транзакция атомарна и имеет одну undo-квитанцию. Несколько транзакций
программы могут сохраниться частично; журнал показывает каждую.
`nb.undo(key,{actionID})` сохраняет более поздние изменения человека. Версии
содержания, интерактивного состояния и чернил остаются отдельными предусловиями.

Fingerprint raw action фиксируется до чтения вида элемента и до Markdown.
Доверенный parser работает в отдельном XPC-процессе и очереди, поэтому не ждёт
user run, который ожидает `transaction`. SQL перепроверяет идентичность, версии
и допустимые производные поля. Markdown внутри SQL не разбирается. Исторические
квитанции сохранены; raw retry без известного исходного fingerprint возвращает
`request_identity_unavailable`.

## Готовность интерактивного документа

Код блока выполняется во встроенном браузере с `notebook.state`,
`notebook.commit(next)` и `notebook.ready(promise)`. Объявите готовность во время
установки программы; Promise должен завершиться после первого рисования и
асинхронной подготовки. Последующие нажатия продолжают работать. Готовность
не подтверждает сохранение будущих изменений.

Для HTML `<button id="increment">Прибавить один</button> <output id="count"></output>`
и `initialState:{count:0}`:

```js
const button = document.getElementById('increment');
const output = document.getElementById('count');
const draw = () => { output.textContent = String(notebook.state?.count ?? 0); };
button.addEventListener('click', () => {
  notebook.commit({count: (notebook.state?.count ?? 0) + 1});
  draw();
});
addEventListener('notebookstate', draw);
notebook.ready(Promise.resolve().then(draw));
```

`notebookstate` приходит при применении внешнего или восстановленного состояния.
`nb.help('interactive')` содержит полный вызов вставки такого блока. Без объявления
`ready` рендер честно сообщает `program_completion_unknown`.

## Пиксели, показ и PDF

Изображения имеют непрозрачный descriptor с SHA-256.
`await emitImage(descriptor)` проверяет пиксели у нативного владельца и сохраняет
их неизменяемую копию для журнала. Движение камеры не меняет последующий resume.
JavaScript не получает файловой функции или дескриптора.

`nb.attention` читает замороженный источник вопроса со статусом `source_pixels`,
`source_pixels_unavailable` или `pending`. `nb.render` относится к названной
текущей версии. `nb.referenceStatus` только читает; `checking` не запускает
рендер.

`nb.present(key,{view,steps})` требует свежую возможность текущего iPad из
`nb.presentation({})`. `nb.presentation({id})` читает фактический показ,
`nb.cancelPresentation(key,{id})` прерывает его. Сохранение, доставка и
отображение различаются; `nb.action({actionID})` возвращает нативные
receipt, continuations, delivery и snapshots.

Результат transaction/undo подтверждает сохранённую квитанцию непосредственно
из нативной записи. Чтение текущих продолжений, доставки или показа не может
превратить успешную запись в ошибку. Исходные тела и before/after остаются
в Core для idempotency/undo и не повторяются в ответе.
Сводка показывает до 32 адресов операций, версий и изменений. Для остальных
используйте `nb.action({actionID,section:'operations',offset:32,pageSize:32})`;
разделы `operations`, `revisions`, `changes`, `continuations`, `undo`, `snapshots` дают
`total/nextOffset`. Список квитанций продолжается через `after:nextActionID`.
Snapshot coverage явно ограничено совпадающими квитанциями последних
80 нативных render requests.

`nb.export(key,{documentID})` возвращает jobID отдельного PDF-задания.
`nb.exportStatus({jobID})` работает после окончания JS. Документ и версия
фиксируются при допуске; публикация перепроверяет версию. Job и квитанция
публикации записываются атомарно. Незаконченная компиляция после перезапуска
становится `interrupted`.

Компиляция выполняется отдельным дочерним процессом существующего markup XPC,
с собственной связью и временным каталогом. Она не занимает очередь parser.
Дочерний процесс наследует App Sandbox без сети и доступа к содержанию Notebook;
он получает только текст TeX и закреплённые ресурсы своего bundle. Один лишь
`--untrusted` не запрещает TeX читать произвольные файлы и не является этой
границей доступа. Только основной Mac-владелец публикует полученные байты PDF.

В Mac bundle входят официальный Tectonic 0.16.9 arm64 и полный набор TeX
`tlextras-2022.0r0`: 134980 файлов, 1481187938 байт сжатых ресурсов. Это сохраняет
пакеты пользовательской преамбулы, включая TikZ и siunitx. Ресурсы на iPad не
копируются. Системный шрифт Georgia остаётся частью прежней печатной преамбулы.
Скрипт `Applications/prepare_notebook_tex.py --prepare` собирает ресурсы в `.build`
только из URL и хешей `Sources/NotebookMarkupService/TeXResources.lock.json`.
`--check` сравнивает точный состав и байты, ничего не скачивая и не записывая.
Пользовательский Tectonic cache, документы, `.aux`, `.log` и приватные `.fmt` не
используются; каждый job строит свой format из закреплённого дистрибутива.

## Изоляция и пределы

QuickJS 2026-06-04 собран из закреплённого исходника. User worker и markup
worker — два sandboxed XPC service без network, файловых расширений доступа
или контейнера содержания. quickjs-libc не включён: нет std/os, require,
Node, Python, DOM, fetch, загрузчика модулей и SQLite. Принимается текст,
не сторонний bytecode. Markup service исполняет только свой встроенный parser
и принимает отдельный data-only запрос компиляции TeX; переданный request.code
отклоняется. User service запрос компиляции не принимает.

Нативные контрактные тесты используют постоянный суффикс исполнителей
`.native-test` и Apple Development подпись с первого запуска. Их sandbox
не содержит содержания и отделён от сопряжённого стенда и установленной пары.
`NOTEBOOK_SCRIPT_BUNDLE_SUFFIX` по умолчанию наследует `NOTEBOOK_BUNDLE_SUFFIX`;
только маршрут нативных тестов задаёт отдельное значение. Он не переносит
контейнеры, не изменяет их ACL и не получает доступ к старому тестовому sandbox.
Проверка этих исполнителей не подтверждает запуск прежнего стенда, если macOS
ожидает решения о доступе для его другой подписанной идентичности.

Serial queue может продолжить выполнение на другом системном потоке.
Перед каждым входом обновляется stack top QuickJS, чтобы предел стека
относился к текущему потоку. Interrupt считает только время внутри JS;
независимый XPC watchdog ограничивает wall time и завершает зависший worker.

| Ресурс | Предел |
|---|---:|
| Активные user run / очередь | 1 / 8 |
| Код / начальные аргументы | 256 КиБ / 1 МиБ |
| JS heap / stack | 128 МиБ / 1 МиБ |
| CPU / wall time | 5 / 30 секунд |
| Одновременные SDK-вызовы / всего | 4 / 1024 |
| Эффекты / события вывода | 128 / 128 |
| Аргументы одного нативного вызова | 32 МиБ |
| Вывод, включая замороженные пиксели | 4 МиБ на run |
| Одно JSON-событие / return value | 256 КиБ / 256 КиБ |
| Изображения на страницу resume | 4 |
| PDF jobs / срок компиляции | 2 / 120 секунд |
| Исходник TeX / готовый PDF | 4 / 16 МиБ |
| Временные файлы / память процесса TeX | 128 МиБ / 1 ГиБ |

Лимит вызывает явную ошибку, не молчаливое обрезание. Большой материал
сохраняйте как документ, возвращая ID и краткую квитанцию. Предел исходного
кода не уменьшает ёмкость создаваемого содержания: JS может собирать строки
и передавать их нативному action.

## Проверка через публичный интерфейс

`MCP/public-transport.mjs` — тонкий stdio-клиент для независимой приёмки.
Он подключает MCP из выбранной private Mac-сборки к уже запущенному владельцу
и допускает только `notebook_context` и `notebook_execute`. Он не запускает
помощника, не регистрирует сервер глобально и не читает SQLite.

```sh
node transport.mjs /absolute/endpoint.json list-tools
node transport.mjs /absolute/endpoint.json call notebook_context < arguments.json
node transport.mjs /absolute/endpoint.json call notebook_execute < arguments.json
```

Схемы берутся настоящим `tools/list`; аргументы вызова читаются из JSON на stdin.
Первый запрос справки: `{"method":"help"}`. Ответ сохраняется целиком, включая
изображения MCP. Для просмотра CLI дополнительно выдаёт пути к тем же PNG-байтам
и их SHA-256. Снимки экрана и ответы владельца не подставляются. Таймаут
транспорта не повторяет вызов и не отменяет уже принятое действие.

Новый acceptance run создаётся стандартным `notebook_acceptance.py prepare`.
Его Mac manifest и пустое пространство находятся в собственной папке
`~/Library/Application Support/NotebookAcceptance/<run>`, а квитанция с путями
и SHA драйвера — рядом с неизменяемой сборкой в `.build`. Это расположение
не запрашивает доступ к Documents ради временного стенда. Сопряжение устройств
и дальнейшие запись, доставка и показ проходят обычных владельцев приложения.

## Продолжение поиска

`nb.search({query,limit,filters?,next?})` возвращает `Snapshot` с `data.results`, точным индексным
`data.total` и `coverage:{complete,next?}`. Чтобы получить остальные совпадения,
передавайте `coverage.next` с теми же запросом и фильтрами; размер страницы
можно менять. Порядок закреплён типом источника и уникальным адресом записи.
Фильтр `kinds` выбирает `item` (заголовок), `page` (элемент листа), `document`
(блок), `spatial` (элемент доски/обложки). `target` ограничивает точную поверхность,
не неявно всё её вложенное дерево.

Курсор переносим между клиентами и не хранит сессию на сервере. Он связан с
пространством и курсором журнала содержания. `search_cursor_stale` требует
явного нового ограниченного поиска; скрытого restart нет. Смена камеры,
присутствия или страниц вывода программы не портит срез. Ошибки чужой области
и повреждённого токена — `search_cursor_mismatch` и `invalid_search_cursor`.
`total` читает индекс при каждом запросе; это работа, пропорциональная
совпадениям, а не бесплатное поле. Сортируются только ключи, после LIMIT
раскрываются выбранные тексты и адресные версии. OCR не добавлялся.

## Согласованное переключение и короткий результат

Новый `start` принимает только `api_version:2`. MCP и helper явно отвергают
несовпадающий протокол. `resume` передаёт `api_version:2` в ответе и настоящую
`run_api_version` сохранённой программы, включая v1. Старые результаты не переписываются
и старый исполнитель не сохраняется. Возобновление не исполняет исходник заново.

По умолчанию start/resume ждёт до 1000 мс от входа в coordinator, возвращая готовый
результат немедленно. Ранний emit не завершает ожидание; terminal или deadline —
единственная граница. Общий бюджет MCP остаётся четыре секунды. Длительный run
возвращает тот же run_id и курсор продолжения, без скрытого увеличения ожидания.
