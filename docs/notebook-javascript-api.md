# Notebook SDK v2: TypeScript and JavaScript

Three public MCP tools route to the single Mac owner:

- `notebook_context`: reads, derived rendering/placement and typed help.
- `notebook_execute`: starts a script or attaches to its durable output.
- `notebook_import_program`: admits immutable package bytes from a trusted local
  descriptor; ready does not publish or display content.

MCP neither evaluates user code nor opens SQLite. `NotebookScriptCoordinator`
uses the existing NotebookStore writer. Exact method/operation schemas and
`notebook-sdk.d.ts` are generated by `MCP/build-script-services.mjs` from the
shared machine contract; native validation remains authoritative.

## Help and execution

Request help only for an unknown contract:
`{"method":"help","args":{"topic":"operations"}}` lists 22 operations.
`operation/createDocument` describes one; `transaction` supplies the complete
atomic schema, `interactive` readiness, `execution` output pagination.
Inside a script use `await nb.help(topic)`.

```json
{
  "op": "start",
  "run_id": "11111111-2222-4333-8444-555555555555",
  "api_version": 2,
  "language": "javascript",
  "code": "const p = await nb.page({id:args.pageID}); await emit({id:p.data.id,basis:p.basis});",
  "args": {"pageID": "REPLACE_WITH_READ_PAGE_UUID"},
  "wait_ms": 1000
}
```

Use a new actual UUID per intended run; preserve it for retry/resume.
Code is an async body with `args`, `nb`, `emit` and `emitImage`.
Await every SDK call. Promise.all admits up to four concurrent calls;
`nb.readMany` is the way to obtain one consistent SQL cut.

## Addressed reads and bases

Content reads return `Snapshot<T> {data,basis,coverage,cursor}`.
`readMany({queries,expectedCursor?})` returns a typed data tuple and individual
coverages from one snapshot, not `values[0]`.

| Need | Read |
|---|---|
| One page element | `page({id,elementID})` or read kind pageElement |
| Metadata only | read pageHeader / documentHeader / itemHeader |
| One document block with state | `document({id,blockID})` or read documentBlock |
| One board element | read boardElement |
| Whole page/document | explicit page / document without a child selector |
| Code and its notes | `code({id})` or bounded file query |
| Actual selection | read selection |
| Whole-item lifecycle basis | read itemLifecycle |

A missing element is null; a missing owner is an error, not an empty page.
Appearance is intact/partial/erased with `sourceIsCompleteAppearance`.
Exact-ID reads preserve fully erased source for history; partial source is not a
complete picture. Render actual masks for visual analysis. Compact observation
excludes fully erased material; delta is outOfScope, and undo yields upsert.

Spatial elements include required typed textStyle; page elements do not require
that field. Connections support straight/elbow/curved routing, with derived
geometry/bindings resolved by the shared Core graph.

`ReadBasis {workspaceID,owners}` contains version preconditions, not permissions.
Pass `base:snapshot.basis` or an explicit array. Conflicting owner versions return
basis_conflict; missing components basis_incomplete; another workspace
basis_workspace_mismatch. There is no automatic refresh before writing.
Reference/context/additionalOwners scope is checked independently.

### Item lifecycle

`read({kind:"itemLifecycle",id:itemID})` returns
`{item,target,revision,bodyRecordCount}` or null. Target is the actual cover with
parent board; basis includes workspace, parent and cover lifecycleRevision.
The digest covers all stored page/document/state records and relevant cover/board
history without decoding their bodies. bodyRecordCount is not total deletion size.
Ordinary itemHeader does not provide this expanded basis.

`appendPage` and `deleteItem` target that exact cover and require authorized scope.
Both take empty values; appendPage optionally takes a new page UUID and inherits
the first sheet's size. Missing ID is assigned stably. deleteItem takes no operation
ID and cannot remove the last working item or a nonempty child board.
There is no recursive deletion, deletePage, reorderPages or generic native undo API.

Create uses createNotebook/createDocument/createBoard; renameItem targets the
containing board and names the item in operation.id. Read ownerBoard for the
board/workspace basis. moveItem can unstack one member without rewriting neighbors'
placement registers; stackItems composes stacks.

### Source ink

`pageInkActions` returns at most 64 headers (default 32), no samples/raster bytes.
Continue via coverage.next; authored sequence is distinct from UUID order.
`baseline.present/actionCount` reports raster provenance without invented stroke IDs.
`pageInkAction` uses page UUID in id and stroke UUID in elementID:

```js
const directory = await nb.read({kind:"pageInkActions",id:args.pageID,limit:16});
for (const stroke of directory.data.actions) {
  if (stroke.tool !== "pen" || !stroke.isActive) continue;
  const source = await nb.read({
    kind:"pageInkAction",id:args.pageID,elementID:stroke.id
  });
  await emit(source.data);
}
```

Activity is not final pixel visibility: later erasure/conversion changes appearance.
pageMap returns real contentPoints/cropPoints and pixel/cell bounds, not a generic
invented region field. Existing stroke-point editing and a universal agent eraser
are unsupported. See [ink contract](page-ink-conflict-contract.md).

## Selection, observation and immutable attention

Selection reads the actual session publication, not a camera guess.
Known data identifies device/session/generation and selection; empty means an
explicitly cleared active scene. Startup/disconnect/inactivity is unknown.
Element selection has target/elementID, item selection itemID; saved context and
temporary reference are distinct. Its empty basis does not authorize mutation.

Unaddressed observe includes actual selection and reads the selected element even
outside the first preview page. Explicit target ignores selection. contextID without
target reads saved context, not a current-camera write basis.
Preview limit is 1–32 (default 32); coverage.complete:false states incompleteness.

Observation scope supports target, ids (1–32), fields
(preview/content/state/geometry) and one-step expand from explicit IDs
(incoming/outgoing/neighbors/container). Expansion is not recursive and does not
expand mutation authority. Board/cover bounds admit at most 256 addresses;
overflow returns observation_scope_full, requiring a narrower window or unbounded-
surface pagination rather than silent truncation.

Results are stable-address upsert/deleted/outOfScope entries. Leaving a relation/
window is not deletion. Endpoint/ink-claim changes invalidate derived connection
geometry without authored rewrites. Unchanged observation avoids body decoding;
presenceGeneration is separate from the content journal.

coverage.next continues a page; data.checkpoint appears only after the final page
and starts incremental observation. Scope/projection/expand/workspace/through are
bound to continuation. An intervening write returns observation_cursor_stale;
expired history returns observation_cursor_expired. No hidden full scan/restart occurs.
Changed scope with since resets explicitly; next with a different scope fails.

```js
const scope = {target:args.target,fields:["content","geometry"]};
let page = await nb.read({kind:"observation",scope,limit:32});
while (page.coverage.next) {
  page = await nb.read({kind:"observation",scope,next:page.coverage.next});
}
const delta = await nb.read({
  kind:"observation",scope,since:page.data.checkpoint
});
```

Envelope cursor is a read cursor; data.through is a change cursor.
Images require explicit includeImage:true. For current context this requires a known
active scene matching display evidence; otherwise current_scene_unknown/pending.
Explicit target returns target_render_required (use render); contextID returns
source_reference_required.

`attention({contextID,referenceID})` returns immutable reference, payload and
SHA-bound artifact, or source_pixels_unavailable/pending. Later selection, camera,
navigation or edits never replace those historical pixels.
`referenceStatus` is read-only; checking does not start rendering.

## Run identity, output and cancellation

Fingerprint binds workspace, API, original language/code and canonical JSON args.
Identical start attaches without recompilation; changed data under the same run ID
returns run_id_conflict. Resume reads the journal; it never replays code or restores
the heap.

States: queued, running, completed, failed, cancelled, interrupted.
Responses include events, next_seq, has_more, result, error and bounded effects.
Continue with after_seq=next_seq while queued/running **or** has_more.
Stop only at a terminal state **and** has_more:false. Running with no more current
events is normal. Repeating a cursor returns the same events.

Each mutation takes a stable key; effect identity derives from run/key.
`nb.id(key)` supplies a stable UUID. Same key with changed arguments conflicts.
Effects retain identity/fingerprint/state/receipt links, not repeated source bodies:

- saved: a durable action or accepted export job; later render failure does not
  undo job admission.
- notSaved: confirmed no write or stop before dispatch; terminal for that key.
  A corrected request needs a new key and fresh basis.
- outcomeUnknown: receipt is unreadable or a transient presentation lacks durable
  evidence; read failure is not proof of absence.

A 64-address unresolved-effect index is reconciled on startup, including completed
runs, without code replay. A resumed old terminal run may rebuild only its own
128 effect addresses. Missing receipts of running/queued native work do not prove
failure.

Whole MCP response budget is four seconds, including admission, queue, receipts
and images. It reserves serialization/IPC return time. response_pending preserves
run_id/after_seq and distinguishes unknown admission from confirmed admission.
Resume those values. Only run_missing at after_seq:0 permits retrying the identical
original start. Socket loss does not cancel an accepted Mac handler.

Cancel closes new-effect admission, stops the user worker and preserves already
accepted native writes. A cancel intent accepted before terminal publication wins
over late success/XPC failure; an already-terminal run retains its result.
Terminal status waits for all accepted effects. Mac restart makes unfinished runs
interrupted, or cancelled if intent was durable, and reconciles before opening IPC.

## TypeScript and isolation

Language is explicitly javascript (default) or typescript; no syntax guessing or
TS-error fallback. Admission saves original source/args/compiler/SDK pins.
The separate markup connection invokes pinned TypeScript 7.0.2 with strict,
noEmitOnError, fixed noResolve/noLib and ES2022+SDK declarations. No runtime npm,
imports, arbitrary references or user tsconfig. Output runs in the existing QuickJS.

Compiler limits: ten wall seconds inside the 30-second active-run budget, five CPU
seconds, sampled 512 MiB RSS, 4 MiB temporary files, 64 KiB diagnostics,
256 KiB output JS and 1 MiB source map. Type/syntax errors admit no effects.
Runtime errors map back to notebook-user.ts. Cancellation blocks late transition
to JS. Retry preserves original compiler/SDK identity even after an upgrade.

QuickJS 2026-06-04 user and markup workers are separate sandboxed XPC services without
network, content storage or file extensions. User code has no std/os, require, Node,
Python, DOM, fetch, module loader or SQLite. Markup accepts only its bundled parser,
not arbitrary request.code. Native typesetting has its own bounded owner.

Serial executors may change OS thread, so QuickJS stack top is refreshed on every
entry. Interrupt counts JS CPU; native watchdog counts wall time including sandbox
startup and awaits. Queue waiting does not consume active-run time.

| Resource | Limit |
|---|---:|
| Active user runs / queued | 1 / 8 |
| Source / initial args | 256 KiB / 1 MiB |
| JS heap / stack | 128 MiB / 1 MiB |
| CPU / active wall time | 5 s / 30 s |
| Concurrent SDK calls / total calls | 4 / 1,024 |
| Effects / output events | 128 / 128 |
| One native-call argument payload | 32 MiB |
| Total output including frozen images | 4 MiB |
| One JSON event / return | 256 KiB / 256 KiB |
| Images per resume page | 4 |
| Concurrent export jobs | 2 |

Limits fail explicitly rather than truncate content. Put large material in a document
and return its ID/compact receipt. Canonical print limits—not the retired native
Tectonic process budget—are in [paper](document-page-fragments.md).

## Atomic writes and results

```js
const p = await nb.page({id:args.pageID});
const saved = await nb.transaction("explanation", {
  summary:"Add an explanation", base:p.basis,
  operations:[{
    kind:"insertElement",target:{kind:"page",id:p.data.id},id:"explanation",
    values:{kind:"markdown",source:"# Example",
      frame:{x:20,y:30,width:300,height:180}}
  }]
});
await emit({actionID:saved.actionID});
```

One transaction is atomic with one undo receipt. Several transactions in one script
can partially succeed; its effect journal reports each.
`undo(key,{actionID})` preserves later human work. Content/state/ink preconditions
remain distinct. Existing geometry changes require references covering the target
or exact additionalOwners; contextID uses stored context scope, not added references.
For moveItem the operation targets the board while scope names the exact cover.

Errors retain native code and, for an operation-specific failure, zero-based
`operation:{index,kind,target,id?}`; source/values are not echoed. Any operation
failure rolls back the batch. General stale-basis failures do not invent an index.

`ActionResult {actionID,actionVersion,publication,changed,basis,next?}` is saved with
content/effect. Large values use valueOmitted, never clipped strings.
Continue via `action({actionID,actionVersion,next})`. Sections operations/revisions/
changes/continuations/undo/snapshots have total/nextOffset, typically 32 per page.
Receipt lists continue with after:nextActionID.

Undo creates a new version; replay of the original result remains frozen.
Historical metadata can be read with its exact actionVersion and checked receipt
hash; unavailable old versions return action_version_unavailable instead of fresh
bodies. Deleted owners are absent from writable post-action basis.
Lifecycle changes include appendPage/deletedItem/restoreItem/removePage without
large removed bodies. Preserved undo groups identify lifecycle_owner_continued.

Saved, receivedByIPad and shownOnIPad are separate. Reading current delivery cannot
turn a successful write into failure or invent display. Snapshot-list coverage is
explicitly limited to matching receipts among the last 80 native render requests.

## Programs, images and exports

Browser programs use NotebookProgram/1, not the server-side nb SDK:

```js
const button = document.getElementById("increment");
const output = document.getElementById("count");
const draw = () => { output.textContent = String(notebook.state?.count ?? 0); };
button.addEventListener("click", () => {
  notebook.commit({count:(notebook.state?.count ?? 0) + 1});
  draw();
});
addEventListener("notebookstate", draw);
notebook.ready(Promise.resolve().then(draw));
```

Use matching HTML IDs and initialState:{count:0}. Declare ready during installation
and finish it after first draw/asynchronous preparation. Missing declaration reports
program_completion_unknown. State-change events apply accepted external/restored
state; readiness is not durability. Full lifecycle/package contract:
[program fragments](document-program-fragments.md).

`emitImage(descriptor)` validates SHA-bound native pixels and freezes them into
the run journal without exposing file APIs. `render` requests current named source;
`attention` reads past evidence. `present` needs a fresh capability from
`presentation({})`; read/cancel use that presentation ID.

`export(key,{documentID,format?})` creates an independent job; exportStatus reads it
after script completion and cancelExport cancels it explicitly. Formats are PDF,
PNG, SVG, HTML, portable package and MP4. Export captures **both source and state**
and composes authored program frames on the shared canonical PDF; programs are not
generic placeholders. Saved and presented moments have distinct guarded semantics.
See [export contract](document-export-contract.md) for exact options, cancellation,
offline packaging and frozen-frame requirements.

## Search continuation

`search({query,limit,filters?,next?})` returns results, exact indexed total and
coverage. Continue with the same query/filters and coverage.next; page size may vary.
Kinds are item, page, document and spatial. Target restricts one physical surface,
not its whole nested tree.

Portable cursors bind workspace/content journal, not a server session.
search_cursor_stale requires a fresh bounded search; mismatched scope or malformed
tokens return search_cursor_mismatch / invalid_search_cursor. Camera/presence/output
events do not invalidate content search. Counting total costs work proportional to
matches; only selected keys after LIMIT decode bodies. No OCR is implied.

## Public verification client

`MCP/public-transport.mjs` is a deliberately narrow **two-tool test client** for
context/execute, not the complete three-tool server inventory. It connects an
already-running isolated Mac owner; it does not launch/register a helper or read SQL.

```sh
node MCP/public-transport.mjs /absolute/endpoint.json list-tools
node MCP/public-transport.mjs /absolute/endpoint.json call notebook_context < arguments.json
node MCP/public-transport.mjs /absolute/endpoint.json call notebook_execute < arguments.json
```

It obtains schemas from tools/list and preserves complete replies/images with hashes.
Timeout neither repeats nor cancels accepted work. Package import uses the installed
skill submit tooling. Isolated setup follows
[release acceptance](release-build-contract.md#isolated-acceptance).

New starts require API 2; mismatched MCP/helper reject explicitly. Resume reports
API 2 plus the stored run_api_version, including historical v1, without retaining
the old executor or rewriting output. Default wait is 1,000 ms until terminal/deadline,
not until first emit. Exact results and installation: [verification](verification.md).
