# Адресное чтение файлов документа

`NotebookStore.readDocumentFile` возвращает `NotebookDocumentFileRead`:
`documentID`, `contentStamp`, один `DocumentFile` и его `sourceVersion` из одного
снимка SQLite. Это не полный документ и не журнал состояния программы.

`documentFileProjection` сначала проверяет живую принадлежность и размеры строк,
затем читает заголовок, выбранный файл и четыре причинных поля. Бюджет проекции —
4096 фрагментов и 16 MiB; текст одного файла ограничен 4 MiB. Проверка размера
готового ответа не заменяет допуск перед декодированием.

SQL-адреса экранируют `/` и `~`, нормализуют UUID-подобные ID, но сохраняют обычные
имена и Unicode. Проверяется структура записи и её владелец. Отсутствующий файл
возвращает null; отсутствующий blob существующей записи — повреждение данных.

`nb.document({id,fileID})` и read kind `documentFile` используют этот путь.
`nb.document({id})` / `documentDirectory` возвращают только каталог: entrypoint,
пути, MIME, размеры и файловые версии. Поиск текущего документа использует
опубликованное присутствие; чтение не меняет камеру или человеческое выделение.
Полный источник читается только явно: `nb.read({kind:'document',id})`.

## Двоичные ресурсы

`notebook_import_document_resource({filePath,path,sha256})` принимает один обычный
локальный файл до 16 MiB. `NotebookDocumentResourceTransfer` проверяет путь, размер
и хеш вне очереди записи; существующий `NotebookProgramImporter` сохраняет части
до 4 MiB через `NotebookPersistenceQueue` и SHA-хранилище. Результат — `resource`,
не публикация. Прикрепление или замена — только `putDocumentFile` с файловым CAS.
Ни фиктивной программы, ни второй упаковки, ни редактируемого зеркала нет.

`nb.document({id,fileID,bytes:{sourceVersion,offset,maxBytes}})` / read kind
`documentFileBytes` проверяет версию и читает ровно выбранный диапазон в одном
снимке. Возвращаются base64, offset, byteCount, totalBytes, eof и та же версия.
Лимит — 1 MiB; для `emit` выбирайте 64 KiB, поскольку событие ограничено 256 KiB.
Текстовые файлы также можно читать как UTF-8 байты. По умолчанию ни каталог, ни
обычное адресное чтение не возвращают двоичные байты. Устаревший CAS даёт
`file_conflict`, а не данные другого снимка.

## Программы — отдельное чтение

`documentProgram` с `id`, `instanceID` и `programPath` возвращает исполняемый
`sourceBasis`, начальное/сохранённое состояние и непрозрачный `stateVersion`.
Он не запускает программу и не подготавливает пакет. Сохранённый JSON null
отличается от отсутствующей записи; только отсутствие использует initialState.
Состояние не выдаётся за содержимое файла или его CAS. Публичный ответ ограничен
4 MiB; внутренний `readDocumentProgramState` читает большие значения только после
допуска стоимости памяти, оконно и в одном снимке. Basis проверяется по выбранным
файлам и зависимостям, без декодирования соседних глав или журнала целиком.

Сценарии настоящего изолированного IPC находятся в
`MCP/test/document-files-ipc.test.ts` и `MCP/test/store.test.ts`.
Адресное чтение не означает инкрементальную компиляцию LaTeX или проверку
физического устройства: [verification](verification.md).
