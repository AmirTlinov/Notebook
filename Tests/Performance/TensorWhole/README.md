# GUI-281: одно преобразование целого вместо записи каждого узла

**Работает:** изменение состояния целого имеет постоянный объём независимо от
числа узлов. На миллионе узлов контроль с одинаковым Float32-форматом показал
ускорение GPU-обновления в **57,7–59,4 раза**, но полного цикла с отрисовкой —
только в **1,14 раза**. Весь изменившийся контур всё ещё нужно рисовать.
Это отдельный Metal-эксперимент; приложения не менялись.

## Механизм и сохранённый смысл

У целого один владелец преобразования: две строки аффинной матрицы, **32 байта**,
включая перенос и выравнивание. Локальные координаты, связность, цвет и форма
узлов не переписываются. В видимом пространстве:

```text
p_visible = A p_local + t
Q_visible = A Q_local Aᵀ
```

Преобразование вокруг опорной точки c задаётся переносом `t = c − A c`.
Новая операция `(B, u)` действует слева: `A' = B A`, `t' = B t + u`.
Поэтому растянуть, затем повернуть — не то же самое, что повернуть, затем
растянуть. Никакой сортировки или перестановки операций нет.

GPU меняет ровно одну запись состояния группы. При отрисовке общий вычислитель
`TensorGPU/TensorInk.metal:evaluate` читает её как uniform, получает видимые
центры и Q и строит контур. Старые прямой и плиточный пути используют тот же
вычислитель с тождественным преобразованием; второй геометрической реализации
нет. Материализованных CPU-треугольников в этих путях нет.

Это конкретная обычная аффинная реализация отношения целого, не доказательство
универсального выигрыша от тензоров или битов. Размерность пространства остаётся
2D. Память читается; просто не нужно записывать N новых состояний на каждое
действие с целым. Реализован один уровень групп, без обхода иерархии.

**Геометрическая семантика:** правило соединений и дискретных концов пера
вычисляется в видимом пространстве, одинаково для обоих контролей. Это не
постпреобразование уже готовой треугольной сетки: при анизотропии дискретизация
концов и ограничение miter могут отличаться от аффинно растянутой старой сетки.
Формула Q и центры соблюдаются, «идеальная аффинная копия каждого старого
пикселя/треугольника» не заявляется.

## Честный контроль

Сравниваются:

- **Поузловая материализация:** compute shader меняет настоящий центр и
  Float32-тензор каждого узла; затем обычный прямой shader рисует результат.
  Это GPU-контроль, не заведомо медленный CPU-цикл.
- **Преобразование целого:** compute shader меняет один affine state;
  локальное представление остаётся неизменным, преобразование применяется
  при отрисовке.

Основные случаи сохраняют компактное 32-битное слово локальной формы GUI-279.
Поузловой контроль начинает с **того же декодированного Q**, но хранит изменения
в Float32, чтобы не смешивать скорость с накоплением повторной квантизации.
Дополнительно на миллионе узлов обе стороны используют одинаковые
Float32-координаты и Float32-Q. Этот контроль отделяет отношение целого от
влияния компактного формата на чтение памяти.

## Измерения: Apple M5 Max, три процесса

Каждый процесс — 4 разогрева + 32 измерения на сценарий, порядок двух вариантов
чередуется. Узлы синтетические, находятся внутри viewport 1536×1024, 4×MSAA.
Операции: растяжение X ×2, поворот +45°, поворот −45°, растяжение X ×1/2,
вокруг общей опорной точки. В cached-draw заранее применены растяжение и поворот.
Обновление, готовая отрисовка и их совместный проход измерены **раздельно**.

Таблица — медианы трёх медиан, мс, основной компактный вариант:

| Узлы | Только обновление, GPU: поузлово → целое | Правка + отрисовка, GPU | Правка + отрисовка, весь цикл |
|---|---:|---:|---:|
| 1 000 | 0,00875 → 0,00752 | 0,03013 → 0,03063 | 0,1614 → 0,1571 |
| 10 000 | 0,00288 → 0,00213 | 0,04175 → 0,04163 | 0,1864 → 0,1851 |
| 100 000 | 0,00813 → 0,00210 | 0,08446 → 0,07985 | 0,2541 → 0,2320 |
| 1 000 000 | 0,16885 → 0,00660 | 0,76083 → 0,64581 | 0,9532 → 0,8261 |

Абсолютные времена зависят от текущего состояния GPU/системы: меньшая сцена
может иметь большее время запуска, чем следующая. Поэтому нельзя вычитать
времена разных сценариев или выбирать минимум из разных процессов.
На миллионе компактных узлов отношения поузлово/целое внутри процессов:

- GPU только обновления: **25,568 / 35,180 / 29,454**;
- весь цикл только обновления: **2,515 / 1,995 / 2,641**;
- GPU правки с отрисовкой: **1,178 / 1,159 / 1,172**;
- весь цикл правки с отрисовкой: **1,131 / 1,154 / 1,140**.

### Одинаковый Float32-формат на миллионе узлов

| Сценарий | GPU: поузлово → целое, мс | Весь цикл: поузлово → целое, мс |
|---|---:|---:|
| Только обновление | 0,12396 → 0,00213 | 0,27875 → 0,13444 |
| Готовая отрисовка | 0,69010 → 0,69756 | 0,88315 → 0,88148 |
| Правка + отрисовка | 0,76090 → 0,64927 | 0,93463 → 0,81808 |

Отношения GPU только обновления: **57,677 / 57,766 / 59,393**; полного цикла
обновления: **2,108 / 2,042 / 2,073**. Для правки с отрисовкой GPU:
**1,181 / 1,165 / 1,182**, весь цикл: **1,145 / 1,136 / 1,142**.
Готовая отрисовка не ускорилась: добавилась работа применения преобразования.
Следовательно, сокращение записей реально, но не отменяет цену всего кадра.

GPU — завершённый интервал `gpuEndTime − gpuStartTime`; весь цикл включает
создание/отправку command buffer, обновление и ожидание GPU. Чтение пикселей,
проверки и PNG не входят в измерения. Это задержка offscreen-прохода, **не FPS**,
не нагрузка GPU в процентах и не энергопотребление.

## Память и объём изменения

Поузлово логически записываются 8 байт центра + 16 байт Q на узел: **24 МБ**
на миллион. Целое меняет одну запись **32 байта**; не 24 МБ и не миллион
индивидуальных команд. Это объём членов структур, **не измеренный физический
трафик памяти**. Чтение/кэширование и выравнивание могут давать другой трафик.

Геометрические GPU-буферы на миллионе узлов:

- поузловой Float32-контроль: 73 120 000 байт;
- целое с Float32-локальной формой: 73 120 032 байта;
- целое с битовой локальной формой: 61 120 032 байта.

12 МБ разницы последнего варианта — **формат Q**, а не бесплатное следствие
группирования. Общие render targets и независимые состояния контрольного стенда
в этих числах не суммируются; это запрошенные буферы, не RSS.
Подготовка/загрузка исходной геометрии вынесена за замеры и остаётся O(N).

## Проверка результата

Все три процесса: **5174 проверки PASS**. Прежние стенды после изменения общего
вычислителя: прямой GPU — **3892 PASS**, плитки — **624 PASS**.

В отдельном примере три полупрозрачных штриха/точки образуют изменяемое целое,
четвёртый штрих — независимую группу. После каждого действия:

- локальные буферы побитно неизменны; другая группа и её контур неизменны;
- центры и Q сверены с независимой композицией в Double;
- максимум ошибки центра — 0,000096 pt, Q — 0,0000341;
- максимум расхождения контура с поузловой материализацией — **0,0004402 pt**;
- все четыре проверенных RGBA-кадра этого примера совпали побитно;
- обратный цикл вернул те же пиксели, но вершины имеют ошибку 0,0001365 pt;
- после 256 действий дрейф вершин — **0,0001857 pt**, не точная обратимость;
- перестановка растяжения и поворота меняет контур до **110,37 pt**.

На больших сценах пиксельное равенство не заявляется: максимум RGBA RMSE
0,000275 по шкале 0…1, доля пикселей с разницей >2/255 среди занятых — 0,140%.
Принятые границы: RMSE ≤0,003, доля ≤1%, расхождение контуров ≤0,03 pt;
256 действий ≤0,1 pt. Настоящие Metal-снимки обеих последовательностей осмотрены.

## Границы

Поддержан один штрих или группа целых штрихов в неизменном порядке. Границы
групп проходят **между штрихами**, не через зависимые соседние узлы одного
штриха. Произвольный внутренний участок потребует явного правила его стыка
с неизменяемым окружением; оно здесь не выдумано. Произвольное членство,
вложенные группы, независимые правки в мировых координатах, вырожденные
матрицы, отражения и долговременная стабилизация не проверены.

Все вершины видимого целого всё ещё обрабатываются и рисуются. Плиточный опыт
GUI-280 сюда не смешан: **его ускорение нельзя умножать на эти числа**. Для
интеграции изменения целого надо также обновлять границы повреждённой области;
поузловые границы из прежнего стенда для этого не подходят без изменения.
Нет production-интеграции, Pencil/ластика, сохранения/доставки, физического iPad
или долговременной UX-приёмки. Установленные приложения не менялись.

## Повторение

Из корня checkout на Mac с Metal toolchain:

```sh
Tests/Performance/TensorWhole/run.sh
mkdir -p .build/tensor-whole/run2
.build/tensor-whole/probe .build/tensor-whole/ink.metallib unused .build/tensor-whole/run2
```

`Results/run{1,2,3}.json` содержит все времена, p95, точность и объёмы.
`environment.txt` фиксирует исходники SHA-256, машину и компиляторы; первая
строка — HEAD перед фиксацией, а хеши относятся к проверенному изменению.
`binary-hashes.txt` — один бинарник для трёх процессов; PNG — первый процесс.
`direct-regression*` и `tiles-regression*` фиксируют повторные проверки общих
путей; исторические результаты GUI-279/280 не переписываются.
